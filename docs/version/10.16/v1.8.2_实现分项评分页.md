### 1.1 本版可用的接口（照抄 `frontend/src/api/index.ts` 的真实签名）

```ts
getReview(reviewId: string): Promise<ReviewArchive>          // 本版会用到（兜底读档）
listContests(includeArchived = false, includeDrafts = false): Promise<ContestListResponse>
// 其余本版用不到；页面不得绕过 api/index.ts 自己发请求
```

类型（`frontend/src/api/types.ts` 已定义，**不要另造**）：

```ts
DimensionResult { dimension_code: string; band: string | null; chunk_ids: string[];
                  quote: string | null; status: string | null }
ScoreEntry     { dimension_code; band; status; weight; contribution; reason }
ReviewScore    { total: number; weighted: number; excluded: ScoreEntry[]; weight_sum: number }
ReviewReport   { review_id; status; contest_id; rubric_id; rubric_version; model_name;
                 source; dimensions: DimensionResult[]; score: ReviewScore;
                 change_list: ChangeListItem[]; note: string }
```

三条页面纪律（写在 `api/index.ts` 的模块注释里）：**URL 一律相对路径**；非 2xx 抛 `ApiError`，消息里带 `detail`；**页面不自己算档位、不自己算加权**。

### 1.3 需求缺口：量规条文没有任何接口

需求原文：

> （第 259 行）**agent2-分项评分.html** — 按维度列出档位、**量规原文**和论文原句，点击分数滚动到对应段落。证据不足的维度用单独颜色标出，不显示假的高分。
> （第 12.3 节）状态为充分、基本、不足的维度，页面能打开**量规条款**和论文原句，且原句能在切片中原样找到。

**实测**：`GET /api/contests` 一条赛题的字段是 `contest_id / year / problem_code / title / statement / status / rubric{rubric_id,version,status} / constraints[] / pitfall_count / exemplar_count`——**没有 `dimensions`**。维度名、权重、四档说明只存在于库表与 `data/contests/` 的 JSON 里，而 P8 不许改后端、也不许前端读 `data/`。

**本版的处置**：

- 维度以 `dimension_code` 呈现（原样显示，**不翻译、不臆造中文名**）。
- 「量规条文」在每张维度卡里**预留一块**，本版显示一行说明：维度名、权重与四档说明由后端量规提供，当前接口未给出（`GET /api/contests` 只有 `rubric_id` 与 `version`）。**不要在这块里放占位假条文。**
- 记 Ruling 挂账（原文见第三节）。

> **如果你希望本版就把条文显示出来**，那需要先有「取量规维度」的接口——那属于**改后端 + 改执行手册 §3.6 的冻结清单**，超出 P8 范围。默认按上面的处置执行。

### 1.5 三个诚实性约束（写进用例，能扫出来）

1. **`score` 四个数全是 0 时不能显示成"0 分"**。确定性回退（`source === 'deterministic'`）下后端不产生加权。页面显示「加权未产生（本次来源 `deterministic`，未接模型）」，并把 `total / weighted / weight_sum` 作为**原始值**列出来；**页面不自己按维度权重求和**（任务文档 §14 明确禁止）。
2. **`quote` 为 `null` 时不给假原句**。证据不足的维度本来就没有原句，显示「未给原句：证据不足不产生引用」，定位按钮置灰并说明原因。
3. **需求 §12.2 有两条本版达不到**，如实记挂账、不写进断言：
   - 「未讨论『两段圆弧半径 2 倍且相切』的维度为**证据不足**」——确定性回退下该维是「基本」，这条要等接模型才成立；
   - 「种植策略样例的两个金额（1286 万元 / 974 万元）」属一致性审查页（v1.8.3）。

- 有 report 时显示：赛题（contest_id 原样）、量规版本（rubric_version，为 null 显示「未绑定量规」）、
  状态（status）、来源（source）、模型（model_name）。全部来自 report，**一个字都不自己编**。
- 没有 report 时显示空态：标题「还没有分项结果」+ 一句说明（需要先在论文解析页确认章节树）
  + 指向 /parse 的链接。**空态文案里不要出现「充分 / 基本 / 不足 / 证据不足」这四个词**——
  阶段验收第一条就是「未确认章节时，评分页没有档位结果」，文案里有这四个字会污染断言。

一.2  维度卡列表（data-testid="dimension-card"，每条带 data-dimension 与 data-band）
逐条渲染 report.dimensions，顺序**与后端一致，不要排序、不要过滤**：
- 维度标识：dimension_code 原样。
- 档位徽标：band；为 null 时显示「未选档」。四档之外的值原样显示（不猜）。
- 状态：status 原样。
- 论文原句：quote 用 --pr-font-quote + white-space: pre-wrap 原样呈现；
  为 null 时显示「未给原句：证据不足不产生引用」，**不放占位假句子**。
- 切片编号：chunk_ids 用 --pr-font-data 呈现；空数组显示「无切片」。
- 量规条文：预留块 + 自检第 4 条那行说明。
- 「定位原句」按钮：行为见自检第 6 条；quote 为 null 时置灰并给出原因。

一.3  证据不足单独配色
- band === '证据不足' 的卡片：用 --pr-insufficient / --pr-insufficient-soft，
  并带 data-insufficient="true"，使其可被扫描。其余档位不得带这个属性。
- 证据不足的卡片**不显示任何分数**，也不显示「0」当作分数。

一.4  加权合计（score）
- **不自算**：页面上出现的 total / weighted / weight_sum 必须与后端返回值逐字一致。
- source === 'deterministic' 或 weight_sum === 0：显示「加权未产生」说明 + 三个原始值，
  **不出现「总分 0」「0 分」「得分 0」这类字样**。
- excluded[] 非空：单独一小节「未进入加权的维度」，用一张**原生 table** 列出
  维度 / 档位 / 权重 / 计入 / 原因（reason），每行带 data-testid="excluded-row"。
  **不要引 el-table**（本页 jsdom 单测不装 Element Plus 插件，原生标签才断言得到行内容；
  Element Plus 留给后续页面的表单与消息）。
- excluded 为空：显示「本次没有被排除在加权之外的维度」，**不放占位假行**。

一.5  共享状态与刷新
- 页面不写共享状态（那是解析页的职责），只读。刷新后若 sessionStorage 里有 report，
  评分页应当照旧显示——E2E 会验证这一点。

## 3. 为什么提示词要这么写（给你复核用）

| 约定 | 来源 | 为什么写进提示词 |
|---|---|---|
| **把两份实测响应整段贴进 §1.2** | 本次新采（建评审 → resume → 取档） | 上一份文档的教训：类型与实测一旦分叉，AI 会照着类型写页面，然后静默拿到 `undefined`。**存档缺 `score` 这件事，只有跑一遍才看得出来** |
| **要求改 `types.ts` 并记 Ruling** | 同上 | P8 禁止改后端，但**类型错误在前端**，必须在前端修。不改的话，加权区会"显示空白且不报错"，比报错更难查 |
| **量规条文只预留、不臆造** | 实测 `GET /api/contests` 无 `dimensions` + 需求第 259 行 / §12.3 | 需求明写要"量规原文"，后端却给不出。**臆造中文维度名是这里最容易发生的"好心办坏事"**——看起来页面更完整，实际与量规不符，且后端补接口时要重写 |
| **0 不能当分数显示** | 实测 `score` 四个数全 0 + 需求第 41 行 + 任务文档 §14 任务 4 | 任务文档只写了"不显示假的高分"。**0 是同一类问题的另一面**：确定性回退下显示"总分 0"，用户读到的是"这篇论文零分"。写进断言才能防住 |
| **定位用 `indexOf(quote)`，不造偏移** | 后端 `quote_is_substring` 已校验原句是父块连续子串 | 页面能拿到的最硬的事实就是这个子串关系，用它定位是**可复现**的；编一个偏移或复用审查条目的偏移，点击就会跳错段落 |
| **高亮用三段文本拼接，禁 `v-html`** | 本次判断 | 论文正文是用户可控输入，`v-html` 会把正文里的标记当 HTML 执行。三段拼接没有这个风险，也更好断言 |
| **不用 `el-table`** | 本次判断 + v1.8.1 的实践 | 解析页全程手写、没用 Element Plus 组件（jsdom 单测不装插件）。表格是 Element Plus 的"允许用途"，但**本页只有一张静态表**，引组件会让单测断言不到行内容，还给已经 1 MB 的包再添一层 |
| **`views.spec.ts` 名单减为三页 + 单独写真实断言** | 读源码 | 与 v1.8.1 同类的坑：占位页断言在页面变真后必然红。不写清，AI 会把断言整条删掉——那就是放宽意图 |
| **`h1` 无条件渲染** | `smoke.spec.ts` 断言 | E2E 对五个页面都断言 `h1` 文案 = 导航名。评分页的空态如果没有 `h1`，报错只会说"标题不对" |
| **空态文案禁止出现四个档位词** | 阶段验收第一条「未确认章节时，评分页没有档位结果」 | 现在的占位页里正好写着"证据不足单独配色"。实现时如果留着这类说明文字，验收断言（页面不含档位字样）会**因为文案而不是因为功能**失败 |
| **需求 §12.2 两条达不到就写挂账** | 实测确定性回退的档位全是「基本」 | 需求点名"该维为证据不足"，但那是接模型之后的结果。**把它写成断言只会有两种下场：用例红，或者 AI 去改数据让它绿**——都比如实挂账糟 |
| **E2E 复用解析页链路后再进评分页** | 任务文档 §14 任务 3 + 共享状态的意义 | 跨页交接（`useReviewFlow`）是本版真正的新东西。只做组件测试等于没验过"解析 → 评分"这条链 |
| **E2E 写库污染写成 Ruling 而非加清理接口** | 冻结清单里没有删除路径 | 与 v1.8.1 同一条纪律：接受污染 + 记行数 + 挂账 |
| **`package.json` 与 `backend/` 零改动写进完成定义** | 前两版的教训 | 把"零新依赖、零后端改动"变成可核对的硬条件 |
| **progress.md 用「阶段 3/6」小节** | 与 v1.8.0 / v1.8.1 一致 | 不发明新的里程碑号：六份文档都以 v0.9.0 = P8 |
