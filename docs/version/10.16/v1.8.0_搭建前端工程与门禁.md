### 1.1 前端到底缺什么（这是本版存在的理由）

`frontend/package.json` 里**没有 Vue、没有 Vite、没有 TypeScript**，也没有 `index.html`、`vite.config`、`src/main.ts`、`src/App.vue`、`src/router/`。

也就是说：**这不是"补几个页面"，是从零搭一个前端工程。** 工具链的未知风险（依赖相容、TS 配置、Element Plus 主题、vitest 环境、Playwright 双服务）与"写一个页面"的风险类型完全不同——捆在一版里，构建一挂就分不清是配置错还是页面写崩。所以本版**独占一版**，只关工具链这一件事。

> **⚠️ 勘误（2026-10-16 11:38 执行后回填，原地更正，不另起版本号）**
>
> 本表原写 `typescript@7.0.2`，**实测不可用**。按 7.0.2 装完后空跑 `npm run build` 直接失败：
>
> ```text
> Error [ERR_PACKAGE_PATH_NOT_EXPORTED]: Package subpath './lib/tsc' is not defined by "exports"
> in ...\node_modules\typescript\package.json
>     at resolveTscPath (...\node_modules\vue-tsc\index.js:73:43)
> ```
>
> `vue-tsc@3.3.13` 需要 `require('typescript/lib/tsc')`，而 **TS 7 是原生实现的包，`exports` 里不再暴露这条子路径**；`vue-tsc` 的 peer 区间 `>=5.0.0` **拦不住这种包内布局变化**。改用 **`typescript@6.0.3`** 后 `vue-tsc --noEmit` 正常，四道门禁全绿。
>
> **教训：`peerDependencies` 的版本区间不能当作相容性证明。** 前端依赖必须"装上跑一次"才算验过。原 `7.0.2` 是我用 `npm view` 解析到的 latest 直接填的，**没有真装**——这一格填错了，代价是一次失败的构建。本版"装完先空跑 build 与 vitest"这一步，正是为了抓这类问题而写。

> **`vue-router@5` 同样要留神**：它是大版本跳跃。任务文档 §14 让读的 `vue-router-best-practices` 讲的是 **Router 4** 的套路，遇到写法不一致**以官方文档为准**，不要硬套 skill 里的示例。装完先空跑一次 `build` 与 `vitest`，**确认工具链成立再写任何业务代码**——这次的 TS 问题就是这一步抓出来的。

### 1.3 为什么必须走 Vite 代理

后端 `backend/app/api/app.py` **没有 CORS 中间件**（`create_app()` 只装了 router），而 P8 的允许范围**不含后端**。所以前端页面在浏览器里直连 `http://127.0.0.1:8077` 一定会被 CORS 挡掉，而且报错信息不会告诉你是代理没配。

唯一出路：**Vite 把 `/api` 代理到 `http://127.0.0.1:8077`**，前端一律用相对路径 `/api/...` 调接口。Playwright 的 E2E 也必须走 5173 这个端口，才能吃到代理。

```json
 "model_name": "deterministic", "source": "deterministic",
 "dimensions": [{"dimension_code": "assumption", "band": "基本", "chunk_ids": [], "quote": "…", "status": "基本"}],
 "score": {"total": 0, "weighted": 0, "excluded": [], "weight_sum": 0},
 "change_list": [
   {"section": "题目约束与数字冲突", "kind": "数字冲突", "finding_kind": "数字冲突",
    "upstream_id": "finding:数字冲突:盘入终止时刻", "target": "盘入终止时刻",
    "evidence": [{"char_start": 175, "char_end": 180, "text": "412 s"},
                 {"char_start": 699, "char_end": 704, "text": "386 s"}],
    "action": "…"},
   {"section": "表述", "kind": "表述", "upstream_id": "dimension:presentation",
    "dimension_code": "presentation", "target": "表述与结构",
    "evidence": [{"text": "| 指标 | 数值 |", "band": "基本", "status": "基本", "chunk_ids": []}],
    "action": "…"}
 ],
 "note": "source=deterministic：…"}
```

> **`change_list` 有两种条目形状，这是 `types.ts` 最容易写错的地方**：
> - **审查类**（`kind` 为 数字冲突 / 越界 / 未提到条件 / 缺少情形 / 引用缺失）：带 `finding_kind`，`evidence[]` 是 `{char_start, char_end, text}`，**这是"点击滚动到偏移"唯一的数据来源**。
> - **维度类**（`kind` 为 证据不足 或 表述）：带 `dimension_code`，`evidence[]` 是 `{text, band, status, chunk_ids}`，**没有字符偏移**。
>
> 两种都可选地出现，所以类型要写成联合或把两组字段都标成可选；页面渲染时必须先判形状再取字段，否则会在运行时拿到 `undefined` 而**不报错**。

## 3. 为什么提示词要这么写（给你复核用）

| 约定 | 来源 | 为什么写进提示词 |
|---|---|---|
| **脚手架独占一版** | **实测** `package.json` 里连 Vue 都没有 | 前端是从零搭工具链，与"写页面"的风险类型完全不同。捆在一版里，构建一挂就分不清是配置错还是页面崩——本项目最忌讳"两个变量一起动"，P4 那次已经交过学费 |
| **给出逐个验过 peer 的确切版本** | **实测** `npm view <pkg> peerDependencies` | 本机解析到的是 `typescript@7`、`vue-router@5`、`jsdom@30` 这类**大版本跳跃**。不先核 peer 就写版本号，装出来可能直接冲突，而报错会指向一堆无关包 |
| **点名 vue-router 5 与 skill 材料不一致** | skill 内容（讲 Router 4） | 任务文档 §14 让读 `vue-router-best-practices`，但那份材料讲的是 Router 4。不点明，AI 会硬套过时示例，然后花半天怀疑自己配错了 |
| **Vite 代理写成硬要求** | **实测** `create_app()` 无 CORS 中间件 + P8 不许改后端 | 这是本版最隐蔽的坑：页面直连 8077 会被 CORS 挡死，而报错根本不提"代理"。不写死，五个页面会一起连不上后端 |
| **要求"装完先空跑 build 与 vitest 再写业务"** | 本次判断 | 工具链的风险要在**没有业务代码**时关掉。等写了页面再发现 TS 配置不对，排查面会大十倍 |
| **接口 URL 一律相对路径，并写用例断言不以 http 开头** | 与代理同源 | 防的是"有人为了让某个请求通过，写死 `http://127.0.0.1:8077`"——那样单页能跑，部署时全崩 |
| **types.ts 要求以真实响应为准** | **实测** resume 响应原文 | 后端的 `change_list[].evidence[]` 带 `char_start`/`char_end`/`text`，`dimensions[]` 带 `band`/`quote`/`chunk_ids`/`status`。凭想象命名类型，页面里会出现大片"取不到值但不报错" |
| **视觉方向里明确列"不做"清单** | `frontend-design` 的反模式 | 该 skill 明确把暖奶油底、无差别圆角卡片、逐卡片 fade-in、装饰性 01/02/03 编号列为 AI 生成感的典型特征。写成硬约束，比写"要好看"有用一百倍 |
| **Element Plus 必须覆盖主题变量** | 计划书定了 Element Plus + `frontend-design` 的反模式 | Element Plus 默认长相就是"标准后台模板"。不覆盖主题，上面那条视觉方向等于白写 |
| **四条门禁而不是一条** | 项目"退出码 0"的纪律 | 后端只有 pytest；前端必须补 `vue-tsc`（类型）、`vitest`（组件）、`playwright`（真布局）。三者覆盖的失效类型不同，少一条就有一类错能溜过去 |
| **E2E 必须走 5173、不许直连 8077** | 同代理原因 | 直连等于把代理这条链路跳过去，测试绿了而真实页面连不上 |
| **要求如实记录 Playwright 双服务起不来时的绕行** | 本次判断 | 环境问题最容易诱发"把用例改成跳过"。先堵住，并给一条出路：写进补充说明、说明绕行，而不是改绿 |
| **progress.md 用「阶段 n/6」而不是发明新里程碑号** | 三份文档都以 v0.9.0 = P8 | 不发明 `v0.9.1`～`v0.9.5` 当里程碑。需求、计划书、执行手册都把 P8 记为 v0.9.0；分段只是执行方式，不是新的里程碑 |
