### 1.1 现状诊断（为什么要重设计）

**已经做对的**（不要推翻）：`tokens.css` 的方向定义相当完整——偏冷近白纸底、深灰蓝黑墨色、三个语义色各自可辨、论文原句用衬线、等宽只给真数据、圆角统一 4px、动效只留章节确认一处、无装饰渐变。这套令牌是项目的视觉资产。

**问题在布局与层次**（本版要改的）：

1. **骨架是标准文档站形态**：顶部一条水平导航 + 居中单栏。这是最普通的"后台/文档"套路，**没有把五步评审流程的递进关系表达出来**，也没有体现"校样稿"该有的工作台感。
2. **五页高度同构**：五个页面都是 `h1 → StageTracker → 信息条 → 列表` 的同一套结构。页面之间没有主导区/次要区的区分，用户扫过去分不清当前在哪一步、该看哪里。
3. **核心价值没有视觉表达**：本项目最要紧的一件事是"每一维的判断都能回到量规条款和论文切片"。现在这条链是靠文字说明和"定位原句"按钮体现的，**没有变成可见的空间关系**。
4. **卡片是模板化的浅底细边框**：整齐但无层次，配合单栏布局就是典型的 AI 生成感。
5. **空态与降级是纯文字**：一行业务说明，没有指引性。

### 1.2 会被本版打破的测试契约（必须先处理，不是"顺手改测试"）

| 位置 | 现有断言 | 为什么会破 |
|---|---|---|
| `tests/e2e/smoke.spec.ts` | 对五页各断言 `h1` 文案 = 导航名 | 改布局时极易把 `h1` 挪进某个条件分支，或让某页出现两个 `h1` → **必须保持每页恰好一个 `h1`、无条件渲染** |
| `tests/unit/app-shell.spec.ts` | 挂载 `App`，断言 `[data-nav-item]` 恰好 5 个、`main` 文本含当前页标题、`main` 内恰好一个 `h1` | 改 `App.vue` / `AppNav.vue` 的骨架时，导航项若被包进别的结构或 `main` 被改名/拆成多个区域，这条会红 → **`data-nav-item` 属性、`main` 元素、五个入口文案一个都不能少** |
| 各页 `data-testid` | 源码共 **86 个** `data-testid`，其中 **E2E 依赖 30 个**、**单测依赖 42 个**（`parse-page` / `section-item` / `dimension-card` / `conflict-item` / `suggestion-item` / `metric-card` / `evidence-hit` / `locate-quote` / `located-mark` / `single-paper-placeholder` …） | 重新设计时重写模板最容易把这些属性丢掉 → **86 个一个都不能少**，少了测试立刻红 |
| `tests/unit/source-scan.spec.ts` | ① `.vue`/`.css` 里无裸十六进制颜色（`tokens.css` 除外）；② `.vue` 里无 `fade`、无 `animation:`、不同时出现 `hover` 与 `translate`；③ `tokens.css` 必须含 `--pr-motion-confirm`、`--pr-paper`（蓝 ≥ 红）、`--pr-ink`（非纯黑且 max 通道 < 140）、`--el-color-primary:` 等 | 重设计时若在新组件里直接写色值、或加过渡动效，四条全中 → **新颜色只能加进 `tokens.css`，动效只能用既有 `--pr-motion-confirm`** |
| 各页空态用例 | 空态文案**不得含**四个档位词 / 审查五类词 / 建议相关词（见 v1.8.2 §1.5、v1.8.3 §1.5、v1.8.4 §1.4） | 空态改版时最容易"写得更完整"，一不小心把「证据不足」「数字冲突」写进说明 → **空态文案沿用现有措辞，只改样式不改文案** |
| `tests/unit/views.spec.ts` | 五个 view 各断言「恰好一个 h1 + 文案 = 页面名」 | 同上，`h1` 必须无条件渲染 |

> 这六类不是"测试写错了"，是重新设计必须付出的代价。**允许更新测试，但不得放宽断言意图**（例如把 `h1` 断言删掉、或给 `data-testid` 断言加 `try/catch` 绕过）。

### 1.3 三条不能推翻的既有决策

1. **校样稿方向不变**：v1.8.0 定的「纸白偏冷、深灰蓝黑正文、强调色只承载语义」继续有效。本版是把这个方向**做得更足**，不是换成 Glassmorphism / Neumorphism / 深色主题之类的别的风格。
2. **`tokens.css` 仍是唯一颜色来源**：所有新颜色（含新增的状态色、强调色）只能加进这个文件，`.vue` 与别的 `.css` 里不许出现十六进制色值。
3. **Element Plus 只用于表单 / 表格 / 消息类重交互件**，页面骨架一律手写。本版不因为"要好看"就把 `el-card` / `el-row` 铺满页面——那正是"标准后台模板"的由来。

### 1.4 skill 组合与各自职责

| Skill | 职责 | 边界 |

| `frontend-design` | **主导**。产出新的布局与组件代码，负责"去 AI 味" | 它默认倾向强视觉冲击（非对称、氛围背景、编排动效）——本项目是**内部评审工作台**，需要克制：可以有个性与层次，但不要营销页式的动效与氛围背景 |
| `ui-ux-pro-max` | 查 `style` / `color` / `typography` 三个域做决策依据；读它自带的 `data/stacks/vue.csv`（针对 vue 3.5.x 的 40+ 条 guideline） | 它的 21 个技术栈里**没有 Element Plus 专档**，组件级用法仍要按 §1.3 第 3 条来 |

一、设计任务（四件事，按顺序做）

一.1  骨架：让五步流程可见
现状是「顶部水平导航 + 居中单栏」，流程递进完全看不出来。重设计目标：
- 让用户**在任何一页都知道自己在五步里的哪一步**、前后是什么；
- 保留五个入口可点击跳转（data-nav-item 五个、文案顺序不变）；
- 保留 `main` 元素与 1040px 版心（--pr-measure 的值可以讨论后调整，但要有理由并记 Ruling）；
- 允许把导航从"顶部横条"改成侧轨 / 顶部流程带 / 步骤条等形式，选哪种由 frontend-design 定，
  但必须满足自检第 2 条的全部契约。
- 移动端不做专门适配（这是桌面工作台），但 1280×800 与 1920×1080 两种视口下都不许出现横向滚动。

一.2  页面层次：五页不再同构
现状五页都是 h1 → StageTracker → 信息条 → 列表。重设计目标：
- 每页有明确的**主导区**（这一页最该看的东西）与次要区；
- 分项评分页的主导区是**维度卡**（档位 + 原句），一致性审查页是**冲突列表**，
  修改建议页是**三段清单**，论文解析页是**章节树 + 正文的对照**，评测对照页是**三项指标**；
- StageTracker 降为辅助元素（它可以小、可以收起来，但 data-testid="stage-tracker" 与 stage-badge 要保留）；
- 页面之间的差异要**看得出来**，不是换了个标题的同一张表。

一.3  证据可视化：把「可溯源」做成可见的空间关系
这是本项目的核心卖点，也是目前最弱的一环。现状是维度卡上一个「定位原句」按钮。
重设计目标（任选其一或组合，但要做出来）：
- 维度卡与它引用的论文原句、以及原句所在的章节位置，三者之间有**可见的关联**（连线 / 同屏高亮 / 侧栏对照均可）；
- 点击定位后，用户能看到"这一维的证据在论文的哪个位置"这件事本身，而不只是页面跳了一下；
- 证据不足的维度继续用 --pr-insufficient 单独配色（这条是需求 §12.2 的硬要求，不许改）；
- 定位逻辑（indexOf 真实子串、找不到诚实降级）一行不许改——本版只改表现，不改语义。

一.4  空态与降级：从"一行业务说明"变成"有指引的空态"
现状空态是一行灰字。重设计目标：
- 空态要说清"现在缺什么、下一步做什么"（例如：未确认章节 → 提示去 /parse 确认，并给可点的链接）；
- 加载中、出错、有数据三种状态要有可辨的视觉差异，但不许用定时器伪造进度；
- 空态文案文字不改（自检第 3 条），改的是排版、图标/标记、留白与链接的可点性。

二、先写测试，再改实现

## 3. 为什么提示词要这么写（给你复核用）

| 约定 | 来源 | 为什么写进提示词 |
|---|---|---|
| **「深化」而非「推翻」单列成节** | `tokens.css` 实测 161 行 + v1.8.0 的方向决策 | 用户说的是"重新设计"，但项目已有一整套定义良好的令牌。**推翻重来的代价是作废七版积累的视觉资产 + 连带改一堆令牌断言**；而现有问题（同构、无层次、核心价值不可见）靠深化完全能解决 |
| **六类测试契约逐条列表格** | 读 `smoke.spec.ts` / `app-shell.spec.ts` / `views.spec.ts` / `source-scan.spec.ts` + grep 全部 86 个 `data-testid` | 改外观是**最容易无意中打破回归网**的一类改动——`h1` 被挪进条件分支、`data-testid` 在重写模板时丢掉、新组件里顺手写个色值。不写清，AI 会把测试改绿而不是守住契约 |
| **空态文案不许改文字** | v1.8.2 §1.5 / v1.8.3 §1.5 / v1.8.4 §1.4 + 现有 E2E | 空态文案刻意避开了档位词/审查词/建议词，因为 E2E 断言"未确认时没有任何结果"。**改空态时"写得更完整"是最自然的冲动**，也最容易踩这条 |
| **Element Plus 边界重申** | MEMORY 里的纪律 + `tokens.css` 的主题覆盖注释 | "为了好看把 el-card 铺满页面"正是标准后台模板的由来，与项目方向直接冲突 |
| **零新依赖写进完成定义** | 前七版教训（typescript 7 不兼容）+ bundle 已 1 MB | 把"零依赖"变成可核对的硬条件。需要图标就用内联 SVG，**并禁 emoji 当图标**（emoji 是 AI 生成感的典型特征） |
| **证据可视化单列一节** | 需求 §12.3「每条进入总分的判断都能回到量规条款和论文切片」 | 这是本项目区别于"通用评语生成器"的核心，而现状只靠一个按钮。重设计若只改配色不改这条，等于没抓到重点 |
| **`ui-ux-pro-max` 限定三个域 + 读 vue.csv** | 实测它的 `data/stacks/vue.csv` 存在、21 个栈里无 Element Plus | 它数据很全（89 风格 / 193 调色板 / 120 UX 指南），但**不限定域就会把 79 种风格全搬出来**，反而挑花眼；且它管不了 Element Plus 组件级用法 |
| **`frontend-design` 提醒"要克制"** | 它的 description 主打 bold typography / asymmetric layouts / atmospheric backgrounds | 它的默认倾向是**营销页式强冲击**，直接用在内部工作台上会过头。写明"可以有个性与层次，但不要氛围背景与编排动效" |
| **两个视口无横向滚动写成 E2E** | 版心 1040px + 桌面工作台定位 | 改布局最容易在窄视口下溢出，而这是**真布局断言**，jsdom 验不了，必须 Playwright |
| **不调大 chunkSizeWarningLimit** | v1.8.0 的同款取舍 | 把告警按掉是掩盖问题；本版不拆包，告警留着并说明原因 |
