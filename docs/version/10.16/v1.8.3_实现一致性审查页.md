### 1.2 本版的数据源：`change_list` 里的审查类条目（实测，不是推断）

**关键事实**：后端没有「GET 审查结果」这种接口。一致性审查的 `findings`（`backend/app/review/consistency.py` 产出，含 `kind` = 数字冲突 / 越界 / 未提到条件 / 缺少情形 / 引用缺失）**不落库、不进任何 HTTP 响应**。它们被 `backend/app/report/change_list.py` 的 `build_change_list()` 转写成修改清单，其中**审查类条目**长这样：

```json
{
  "section": "题目约束与数字冲突",
  "kind": "数字冲突",
  "finding_kind": "数字冲突",
  "upstream_id": "finding:数字冲突:盘入终止时刻",
  "target": "盘入终止时刻",
  "evidence": [
    {"char_start": 175, "char_end": 180, "text": "412 s"},
    {"char_start": 699, "char_end": 704, "text": "386 s"}
  ],
  "action": "把两处数值改成同一口径，并在正文说明取值来源"
}
```

审查类条目的判定特征：**带 `finding_kind` 字段**，且 `evidence[]` 的元素是 `{char_start, char_end, text}` 三字段。对照地，维度类条目（证据不足 / 表述）带 `dimension_code`，其 `evidence[]` 元素是 `{text, band, status, chunk_ids}`、**没有字符偏移**。

**本版只取 `section === "题目约束与数字冲突"` 的条目**，它们覆盖五类审查结果（`数字冲突` 独占 `kind`，`越界 / 未提到条件 / 缺少情形 / 引用缺失` 统一归 `kind === "题目约束"`、各自保留 `finding_kind`）。**`证据不足` 与 `表述` 两段不是审查结果，归修改建议页（v1.8.4），本版不碰。**

> 若你发现某条审查类条目没有 `char_start`（例如「未提到条件」「缺少情形」的 `evidence` 是空数组），那是后端本来就有的：**没有可定位的偏移就不显示"定位"按钮**，只显示 `target` 与 `action`。不要为了凑一个偏移去编数字。

### 1.4 字符偏移的语义（本版最容易踩的坑）

审查类条目的 `char_start / char_end` 是**论文全文**的偏移（`consistency.py` 在整个 `paper_text` 上切 `section_spans`、找 `measurement`），不是某一段落内的相对偏移。而前端共享状态里存的是 `sections[]`（每个 `{title, section_type, level, content}`），**没有整篇 `paper_text`**。

因此定位时要**先按 `sections` 的顺序把各段 `content` 拼回一段完整文本**（中间的分隔策略要与后端切分方式一致，见下），再用 `char_start` 定位。实测的分隔要点：

- 后端 `section_spans` 按 ATX 标题切，标题后的正文连续；把 `sections[i].content` 依次接起来时，**段与段之间用一个换行 `\n` 连接**即可复现绝大多数偏移（标题行本身被 `section_spans` 计入长度，而 `sections[].content` 不含标题行——**这是一个已知偏差**）。
- **诚实处理**：定位到大致位置后，用 `text`（该条 `evidence` 里的原文，如 `"412 s"`）在拼接文本里 `indexOf` 校准——**能精确找到就用精确位置，找不到就落到 `char_start` 的大致位置并明确标注「按偏移定位，未精确匹配」**，绝不静默跳到错误处。
- 这一「全文偏移 vs 分段正文」的拼接复现是**双源风险**，写进 Ruling（见第三节）。

### 1.5 两个诚实性约束

1. **空态不允许出现任何审查字样**：没有 report（未确认章节）时，页面显示空态「还没有审查结果」+ 指向 `/parse` 的链接，文案**不得**含「数字冲突 / 越界 / 未提到 / 引用缺失 / 412 / 386」这些词——它们会污染"未确认时没有审查结果"这条验收。
2. **不按题号写分支**：板凳龙样例的 412 s / 386 s 必须**从 `change_list` 数据里自然渲染出来**，源码里不许出现 `cumcm-2024-A` 或对"板凳龙"的专门判断。写死题号分支会被 `source-scan.spec.ts` 的题号字面量扫描抓到。

## 3. 为什么提示词要这么写（给你复核用）

| 约定 | 来源 | 为什么写进提示词 |
|---|---|---|
| **数据源判断单列 §1.2 并贴实测 JSON** | 实测 + 读 `change_list.py` / `consistency.py` | 这是本版最容易被误解的点：后端没有审查结果接口，AI 极易去"找一个不存在的接口"或"在前端重跑审查"。把"findings 只经 change_list 转写后进报告"这件事讲死，才能挡住这两条歧路 |
| **只取 `section === 题目约束与数字冲突`** | `change_list.py` 的三段排序 | 修改清单里还有「证据不足」「表述」两段，属 v1.8.4。不写清，AI 会把三段全塞进审查页，两个页面职责就糊了 |
| **「定位」按钮只给有偏移的条目** | 实测「未提到条件」「缺少情形」`evidence` 为空 | 没有偏移就没法定位，硬凑一个偏移会跳到错误处。写清"没偏移就不给按钮"，比让 AI 去编一个数字干净 |
| **全文偏移 vs 分段正文的拼接复现写成 Ruling** | 读 `section_spans` 与共享状态结构 | `char_start` 是全文偏移，而 `sections[].content` 不含标题行，段间拼接有偏差。**`indexOf(text)` 校准是能消除这个偏差的关键**——直接拿偏移切段落必跳错 |
| **精确匹配优先、找不到诚实标注** | 同上 | 任务文档 §14 任务 5 要求"视口落在对应偏移"。如果因为标题行偏差做不到精确，标注「按偏移定位」比静默跳错好——后者让用户误判引用对不上 |
| **两条必现事实从数据渲染、禁题号分支** | 需求 §12.2 + `source-scan` 的题号扫描 | 412/386 必须来自 change_list 数据；写死 `if (contest==='cumcm-2024-A')` 会同时踩"题号字面量"扫描和"按题号写分支"两条红线 |
| **空态文案禁审查字样** | 阶段验收「未确认章节时没有审查结果」 | 与评分页空态禁档位词是同一类：文案里的"数字冲突"会污染"没有审查结果"这条断言，且是因为文案不是因为功能失败 |
| **`views.spec.ts` 名单减为两页** | 读源码 | 与 v1.8.1 / v1.8.2 同款坑：占位页断言在页面变真后必然红 |
| **`h1` 无条件渲染** | `smoke.spec.ts` 断言 | E2E 对五页都断言 h1 文案 = 导航名 |
| **高亮三段拼接、禁 v-html** | 本次判断 + v1.8.2 同款 | 正文是用户可控输入，v-html 会把正文里的标记当 HTML 执行 |
| **E2E 复用解析页链路** | 任务文档 §14 任务 3 | "确认后才有报告、报告里才有 change_list"这条链不跑真浏览器验不到 |
| **E2E 写库污染记 Ruling** | 冻结清单无删除路径 | 同 v1.8.1 / v1.8.2 纪律 |
