### 1.3 「点进单篇」缺口（本页必须裁决，理由见 §3）

需求原文：

> （第 262 行）**agent5-评测对照.html** — 展示 15 篇自建论文的人工档位和系统档位……可点进任意一篇查看错在哪一维。
> （任务文档 §14 任务 6）评测页展示 v0.8.0 的三项指标，点一行进入单篇，能看见系统档位和 `gold` 的差异。
> （任务文档 §14 阶段验收）评测页从汇总进入单篇，单篇能看到至少一对系统档位与人工档位。

**实测**：单篇的 `gold`（`[{dimension_code, band}]`）与 `expected_findings` 只存在于 `data/samples/eval/*.json`；`GET /api/eval/summary` 只回聚合数，`GET /api/samples` 只有 `has_gold` 布尔。**没有单篇接口**，P8 不许改后端、也不许前端读 `data/`。

**本版处置**：

- 汇总页（三项指标 + 口径 + 来源 + note）**完整实现**，数据全部来自 `getEvalSummary()`。
- 15 篇列表（`listSamples`）可以列出来，但**「点进单篇」只做占位**：`/eval/:paperId` 路由渲染一行说明——「单篇的系统档位与 gold 差异需要后端提供单篇接口，当前接口未提供」，**不臆造 gold、不读 data/、不前端重算**。
- 记 Ruling 挂账（原文见第三节）。

> 若你希望本版就把单篇做出来，那需要后端加一条「取单篇评测结果」的接口（返回该 paper 的 `gold` 与系统档位），属于**改后端 + 改执行手册 §3.6 冻结清单**，超出 P8 范围。默认按上面的处置执行。

### 1.4 一处会被本版打破的既有断言

| 文件 | 现有断言 | 为什么会被打破 |
|---|---|---|
| `tests/unit/views.spec.ts` | `PLACEHOLDERS` 名单只剩**一个**页面（评测对照），断言其含「待实现」且无 `[data-dimension]`、无 `table` | 评测对照页变成真页面后不再有「待实现」四字 → **`PLACEHOLDERS` 名单清空**，评测页单独写真实断言 |

### 1.5 三个诚实性约束

1. **`rate` 可能为 `null`**：分母为 0 时后端把 `rate` 设为 `null`（`no_samples` 为 true 时）。页面显示「—（无样本）」而不是把 null 显示成 0 或 NaN。
2. **必须展示 `source` 与 `note`**：`source='deterministic'` 时三项数字是脚本自检，**不是模型准确率**。页面必须把 `note` 原文展示出来，不能只摆一个 43.3% 让人误以为是模型效果。
3. **空态（取数失败）**：`getEvalSummary()` 失败（jsdom 无后端）时页面必须捕获并降级显示错误/空态，`h1` 无条件渲染——否则 `app-shell.spec.ts` 与 `smoke.spec.ts` 会红。

| **单篇缺口单列 §1.3 并给默认处置** | 实测没有单篇接口 + 需求第 262 行 / 任务文档 §14 任务 6 | 这是本页最大的一件事。任务文档明确要求「点进单篇看 gold 差异」，但后端根本没有单篇接口。不写清，AI 极可能去读 `data/` 或臆造 gold——两者都踩红线 |
| **`rate` 为 null 要显示「无样本」** | 实测 `_metric` 分母为 0 时 `rate: None` | null 被模板直接渲染成空，或 `(rate*100).toFixed()` 抛错。写清"null → 无样本"，防 NaN 与崩溃 |
| **必须展示 note、不把百分比当成果** | 实测 `note` 已写明确定性回退 | 43.3% 这个数字极容易被 AI 放大加粗当"评测成果"。但它是脚本自检，不是模型效果。这条是本页最关键的诚实性约束 |
| **不需要 StageTracker** | 六步是单次评审流程 | 评测汇总不是单次评审，硬塞步骤指示器会让"过程可观测"的语义错位。写清"不要硬塞"防止 AI 为了页面统一而滥用组件 |
| **空态 / 失败降级 + h1 无条件** | `app-shell.spec.ts` / `smoke.spec.ts` | 评测页是 `app-shell` 之外第一个"挂载即取数"的页面（`/eval` 不在 app-shell 的 push 路径里，但 smoke 会逐页点），取数失败必须捕获 |
| **`views.spec.ts` 名单清空** | 读源码 | 这是最后一个占位页，变真后 `PLACEHOLDERS` 空了——要处理"名单为空"这个边界，不能留着空数组让循环断言变成无意义通过 |
| **E2E 只读不写库** | 评测接口只读 | 本页不需要走创建/确认链路，无污染——与前几页不同，写清避免 AI 习惯性走完整链路 |
| **不放大百分比、禁奖项字样** | 需求红线 | 评测页最容易出现"成果感"，也最容易踩奖项/名次字样 |
