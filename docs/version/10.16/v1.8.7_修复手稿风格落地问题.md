### 1.1 先辟谣：截图发黄不是页面颜色

用户截图显示整体暖黄，疑似"纸底被改成暖纸"。**实测结论：没有。**

```text
--pr-paper                      = #f6f7f9        （tokens.css 第 8 行，冷白，一行未改）
getComputedStyle(body).backgroundColor = rgb(246, 247, 249)
纸张颗粒                        = 已生效（opacity 0.035，灰度噪点）
source-scan 的"底色 b≥r"断言    = 仍然成立（未改）
```

截图发黄来自截图环境（浏览器护眼模式、显示器色偏、或截图工具的色彩处理）。**本版禁止以"截图偏暖"为由修改 `--pr-paper` 或任何纸底/墨色令牌**——那会把已经正确的东西改错，还会连带改掉 `source-scan` 的断言理由。

> 如果用户确实想要暖纸，那是**独立的视觉方向决策**（v1.8.6 §2 冲突一的选项 A），要单独提、单独改断言理由，**不搭本版的车**。

### 1.2 三个必须修的 bug

**Bug 1：手绘圈跑位（评分页 + 审查页都有）**

- `frontend/src/components/DimensionCard.vue` 的 `.card__band-circle`：
  ```css
  position: absolute;
  inset: -9px -11px;              /* 已经确定了位置和尺寸 */
  width: calc(100% + 22px);       /* 又写 width/height，把 right/bottom 的效果覆盖掉 */
  height: calc(100% + 18px);
  ```
  `inset` 与 `width/height` 混用会互相覆盖，圈的尺寸与位置因此错乱；再叠加父元素定位关系不确定，圈就跑到了卡片左上角。
- `frontend/src/components/ConflictItem.vue` 的 `.conflict__hit-circle`：`inset: -7px` 依赖其父级 `<button>` 是 `position: relative`，但这一点没有保证，圈于是落到更外层的定位祖先上，偏到文字下方。

**修法**：圈只用 `inset`（不写 width/height），并**显式给父元素加 `position: relative`**；`sketch-circle.svg` 本身是 `preserveAspectRatio` 默认（等比缩放），套在短文本上会被拉扁，所以圈要用**固定比例的容器**包住目标文本，而不是靠 `inset` 撑满。

**Bug 2：评测页折线图是假的**

`frontend/src/components/MetricCard.vue` 直接 `import chartUrl from '../assets/sketch/sketch-chart.svg'`，三张卡渲染同一条折线。截图里三条线一模一样——**用户会读成"三项指标趋势相同"**，这是数据误导，比没有图更糟。

**修法**：折线改为**按 `matched / total` 实时生成 path** 的内联 SVG（手绘风格：微弯的折线 + 数据点小圈 + 手绘坐标轴），每条卡的线随自己的数据变化；`rate === null` 时不画线，只显示「—（无样本）」。静态 `sketch-chart.svg` 可保留作空态/占位，但**不得用于有数据的卡**。

**Bug 3：修改建议页完全没手稿化**

五页里四页有手绘语言，唯独建议页是朴素卡片 + 文字徽标，风格断裂。且三段之间只有标题文字，没有"先改硬伤 → 再补证据 → 最后改表述"的递进感。

**修法**：建议条用与评分页/审查页**同一套**手绘边框；三段之间用 `sketch-arrow-right.svg` 表示推进方向；段标题加等宽体编号。

### 1.3 一致性问题（四件事）

1. **密度节奏不统一**：审查页的冲突条框高内容少（大量空白），评分页密集，建议页紧凑。同一套页面应有一致的留白节奏。
2. **手绘边框粗细/双线不完全一致**：三页都用了 `sk-card-frame`，但视觉重量有差异（可能与卡片高度拉伸 SVG 有关——`preserveAspectRatio="none"` 会把双线拉变形）。
3. **修改建议页三段无递进**（见 Bug 3）。
4. **解析页输入区两块卡片高度不一致**（"用演示样例"与"或粘贴正文"一高一低）。

## 3. 为什么提示词要这么写（给你复核用）

| 约定 | 来源 | 为什么写进提示词 |
|---|---|---|
| **辟谣放最前，并禁改纸底** | 实测 `--pr-paper` / computed color / source-scan 断言 | 用户截图发黄，最直觉的反应是"纸底被改成暖纸了，改回去"。但实测证明**页面本来就是冷的**。不写清，AI 会照着一张失真截图把正确的令牌改错，还要连带改断言理由——这是本版最大的风险 |
| **圈注 bug 给出代码位置与根因** | 读 `DimensionCard.vue` / `ConflictItem.vue` 的 CSS | `inset` 与 `width/height` 混用会互相覆盖、父级缺 `position: relative`，这是具体可指的错。不写清，AI 可能"重新设计一个圈"而不是修这两行 |
| **圈要套固定比例容器** | `sketch-circle.svg` 默认等比缩放 | 直接 `inset` 撑满会把圆拉成椭圆。这一点不说，修完还是一个扁圈 |
| **假折线图单列并引方案原文** | 读 `MetricCard.vue` 的 `import chartUrl` + 方案第 10 条 | 三条一样的线比没有线更糟（数据误导）。给"按 matched/total 生成 path"的具体修法，并保留手绘语言，避免 AI 改成标准图表库风格 |
| **补齐修改建议页** | 截图对比五页 | 五页里四页有手绘语言、一页没有，这是最刺眼的不一致。要求"用同一套边框"而不是重新设计 |
| **密度统一 + 边框不变形** | 截图：审查页框高内容少、评分页密集 | `preserveAspectRatio="none"` 的双线在拉伸时变形，是"边框粗细看起来不一致"的根因。指出这一点比笼统说"统一风格"有用 |
| **`data-testid` 与 `h1` 契约重申** | v1.8.6 的同款纪律 | 改圈注结构最容易碰掉属性；本版是修 bug，更容易"顺手重构" |
| **E2E 断言圈中心偏差 ≤ 4px** | 本次新增 | 圈注位置是**真布局断言**，jsdom 量不到几何中心，必须 Playwright 用 boundingBox 算 |
