# 阶段一：视觉诊断与页面排版优化

```markdown
# Phase 1 — Editorial Layout Refinement

## 任务目标

请检查当前项目的前端页面，对现有 UI 进行一次专业的视觉诊断和排版优化。

当前设计系统为：

Sketch / Hand-drawn / Editorial / Designer Wireframe / Refined Roughness。

现有项目已经具备基础配色、组件样式和白天 / 黑夜主题。当前问题是页面过于单调，内容布局缺少视觉焦点，页面之间的构图过于相似，整体看起来像未经精细设计的基础原型。

本阶段只优化布局、排版、信息层级、空间节奏和内容呈现方式，不进行全面的主题重构。

## 1. 先分析现有项目

在修改代码之前：

1. 检查前端目录、页面路由、公共布局、组件结构和样式组织。
2. 找出页面过于空旷、内容排列机械、卡片重复、标题层级不明显的问题。
3. 识别最重要的页面和用户最常使用的功能。
4. 复用现有组件与主题变量，避免创建重复的组件系统。
5. 保留已有业务逻辑、API 调用、路由、表单校验和交互行为。

先确定改动方案，再开始修改代码。不要只给建议，要实际完成前端修改。

## 2. 优化整体排版

将普通的模板式布局升级为具有艺术指导感的编辑式布局。

优先考虑：

- 非对称网格与不同比例的内容列。
- 更有表现力的页面标题和副标题。
- 清晰的标题、说明、正文、元信息层级。
- 大小不一但具有逻辑关系的内容模块。
- 合理的横向分组、纵向节奏和留白。
- 适量的分隔线、局部手绘标记和构图辅助元素。
- 重点内容与辅助内容之间更明显的视觉差异。

不要让每个页面都变成完全相同的三列卡片布局。

不要为了非对称而破坏对齐、可读性和响应式布局。

## 3. 建立页面视觉焦点

每个主要页面都应具有明确的第一视觉焦点。

视觉焦点可以来自：

- 大尺寸标题。
- 有特色的 SVG 线稿。
- 有层次的主内容区域。
- 非对称构图。
- 手绘圈注和箭头。
- 特定内容的尺寸与位置变化。
- 主色的局部强调。

每个页面优先设置一个主要焦点，必要时设置一到两个次级焦点。

不要让所有标题、卡片、图标和按钮都拥有同等的视觉权重。

## 4. 优化组件呈现

重新审视现有卡片、列表、表格、表单和导航。

卡片不必全部拥有相同尺寸和相同视觉样式。

允许：

- 重点内容使用较大的展示区域。
- 辅助内容使用轻量的文字模块。
- 列表采用清晰的分组和节奏。
- 局部模块使用轻微错位的手绘边框。
- 通过线条、间距和背景明度区分内容，而不是全部依靠卡片容器。

保持原有的 Sketch / Hand-drawn 语言，不要改成常规 SaaS Dashboard。

## 5. 保持双主题

必须继续支持 Light Theme 和 Dark Theme。

两套主题共用现有语义 Token。

不要为改善视觉效果而引入一套独立配色。

所有文字、边框、背景、装饰线和交互状态继续通过主题变量控制。

## 6. 响应式要求

桌面端优先，但必须支持平板和移动设备。

- 桌面端可以使用非对称多列布局。
- 平板端适当缩减列数和模块间距。
- 移动端恢复清晰的单列阅读顺序。
- 禁止水平溢出、内容遮挡和固定高度造成的文字裁切。

## 7. 严格限制

本阶段不允许：

- 重写业务逻辑。
- 修改后端 API。
- 删除已有功能。
- 引入大型 UI 框架。
- 大量增加没有意义的装饰。
- 将所有页面统一改成同一种模板。
- 使用紫蓝渐变、霓虹效果、玻璃拟态。
- 通过增加大量阴影和圆角制造所谓的高级感。

## 验收标准

完成后，页面应该具有更加鲜明的视觉层级、合理的空间节奏和明确的内容焦点。

整体仍然像一个专业设计师绘制的数字产品，而不是普通模板套用手绘配色。

请实际修改代码，并总结修改的文件、页面布局变化以及需要进一步优化的部分。
```

# 阶段二：为整个系统设计全局背景

```markdown
# Phase 2 — Global Background Art Direction

## 任务目标

为当前 Web 应用设计一套统一的全局背景系统，提升页面的空间层次和设计感。

背景必须服务于现有的 Sketch / Hand-drawn / Editorial 风格。

目标不是简单地给页面添加背景图片，而是建立一个具有纸张材质、构图线条、轻微手绘痕迹和层次变化的完整背景系统。

## 1. 设计全局背景

请为整个应用建立统一的背景体系，包括：

1. 页面基础背景色。
2. 低对比度纸张纹理。
3. 可选的淡色构图网格。
4. 少量符合手绘主题的线稿装饰。
5. 与页面内容区域相协调的表面层级。

背景应该让界面更有质感，但用户的注意力仍然集中在内容上。

## 2. 纸张纹理

白天模式：

- 使用白色或极浅灰色的纸张基底。
- 加入非常轻微的纸张纤维、细颗粒和自然材质变化。
- 避免明显的污渍、旧报纸效果和过度泛黄。
- 保持现代、干净、精致的设计工作台感觉。

黑夜模式：

- 使用深灰蓝或炭灰色基底。
- 保留细腻、低对比度的材质颗粒。
- 不要将浅色纸张纹理直接反色。
- 不要使用纯黑背景或高亮白色纹理。

两种主题应呈现同一种材质语言，但拥有各自合理的明暗关系。

## 3. 全局 SVG 装饰

可以使用少量原生 SVG 构建全局构图元素，例如：

- 建筑设计辅助线。
- 不规则的几何线稿。
- 轻微的测量刻度。
- 铅笔绘制的弧线。
- 局部虚线和构图标记。
- 低对比度的抽象工作台草图。

SVG 装饰应该放在页面的背景层，不应遮挡按钮、文字、输入框或其他交互区域。

所有纯装饰性 SVG 必须设置 `pointer-events: none`，避免影响正常操作。

不要在每个页面重复绘制完全相同、明显可见的图案。

## 4. 技术实现

优先使用 CSS 实现底色、微弱纹理和重复网格。

对于需要独特构图的装饰，可以使用独立的 SVG 文件或可复用的背景组件。

背景系统应当：

- 不影响页面布局。
- 不改变现有组件层级。
- 不引起横向滚动。
- 不拦截鼠标和触摸事件。
- 不产生明显的加载闪烁。
- 不依赖大型图片资源。
- 不使用高开销的实时滤镜。

如果需要位图纹理，应优先使用可复用、体积较小的本地资源，避免将整张大型背景图重复应用到每个组件。

## 5. 背景与内容分层

页面背景、内容表面和重点模块之间应存在合理的层级。

不要让所有内容都像贴在一块完全不透明的白色矩形画布上。

可以通过微妙的表面色差、局部边框、轻微纸张层次和留白建立关系。

但不要将整个界面变成复杂的拼贴画。

## 6. 双主题支持

背景系统必须通过现有语义 Token 适配 Light Theme 与 Dark Theme。

允许两种模式使用不同的纹理资源，但不能改变页面结构。

切换主题后：

- 文字保持可读。
- 边框保持清晰。
- 背景装饰仍然低调。
- 表面层级仍然明确。
- 手绘元素仍然与整体风格一致。

## 7. 验收标准

背景应当在第一眼中提供更丰富的视觉氛围，但不应该比页面主要内容更醒目。

如果关闭背景装饰，页面仍然应当保持完整、清晰和可用。

请实际完成代码修改，并说明全局背景的实现位置、资源文件和双主题适配方式。
```

# 阶段三：增加主题专属的 SVG 插画

```markdown
# Phase 3 — Custom SVG Illustration System

## 任务目标

为现有 Web 应用增加一套符合 Sketch / Hand-drawn / Editorial 设计风格的 SVG 插画系统。

插画必须融入真实产品功能，提升视觉识别度和页面叙事能力。

不要只在页面角落添加没有意义的装饰。

## 1. 先识别插画使用场景

检查项目中的所有主要页面和核心功能，优先识别以下场景：

- 首页或应用总览。
- 项目或工作区介绍。
- 知识库与文档管理。
- 搜索、检索或数据关系展示。
- 空状态和首次使用引导。
- 任务执行、处理进度和结果展示。
- 设置、帮助和功能说明。

只为确实需要视觉辅助的区域增加插画，不要求每个页面都必须有大插图。

## 2. 插画视觉规范

所有插画应共享统一的设计语言：

- 手绘墨线与铅笔线稿。
- 适度不规则的几何轮廓。
- 少量辅助构图线。
- 克制的箭头、刻度和手写标注。
- 低饱和度的局部强调色。
- 具有呼吸感的构图和留白。
- 清晰、可辨识的主要对象。

插画应像设计师工作手稿中的精致图解，而不是儿童涂鸦或普通素材库图标。

禁止大量堆叠装饰、复杂的 3D 效果、渐变填充、荧光描边和机械化的重复图形。

## 3. 使用原生 SVG

优先创建真实的 SVG 文件或可复用的 SVG 组件。

根据具体内容使用：

- `path`
- `line`
- `circle`
- `rect`
- `ellipse`
- `polygon`
- `g`

可以使用轻微的线条粗细变化、局部虚线、非完全对称的形状和少量填充区域，表现手绘质感。

避免将整张插画转换成单张不可维护的图片。

插画应当具有合理的 `viewBox`，支持响应式缩放，并避免裁切关键内容。

## 4. 建立可复用的插画组件

如果项目适合组件化，请建立统一的插画目录或组件目录。

例如：

- `HomeIllustration`
- `WorkspaceIllustration`
- `KnowledgeIllustration`
- `SearchIllustration`
- `EmptyStateIllustration`

这些名称仅作为建议，应根据现有项目结构调整。

尽量复用绘制规则，而不是强制所有插画使用相同的主体形状。

## 5. 主题适配

SVG 必须支持白天和黑夜模式。

优先使用：

- `currentColor`
- CSS Custom Properties
- SVG 内部的语义色变量

避免在 SVG 中大量硬编码固定的黑色、白色和单一背景色。

白天模式使用适合浅色纸面的深灰墨线。

黑夜模式使用柔和的浅灰线条，并保留适当的明暗层次。

辅助色继续沿用系统的蓝色、青绿色、暖橙色及对应的深色主题变体。

不要让黑夜模式下的 SVG 变成一片刺眼的白色轮廓。

## 6. 插画与布局结合

插画应与页面排版形成整体。

可以采用：

- 插画与标题并列。
- 插画位于主内容模块的一侧。
- 插画作为局部背景图解。
- 小型插画与空状态说明组合。
- 图解与数据、流程、功能说明并列。

不要让插画挤压主要内容，也不要将所有插画统一放在标题右侧。

每个页面根据内容选择最合理的构图。

## 7. 资源与性能

优先使用原生 SVG，不要为了手绘插画引入庞大的图形依赖。

插画应避免不必要的滤镜、复杂的动画和大量重复路径。

纯装饰性 SVG 不应拦截用户操作。

对于有语义的插画，提供适当的无障碍说明；对于纯装饰图形，应避免重复朗读。

## 8. 验收标准

插画应让页面更具有品牌辨识度，并强化用户对功能的理解。

所有插画必须与现有排版、双主题配色和手绘边框体系保持一致。

请实际创建插画资源、完成页面接入，并说明新增文件及对应使用位置。
```

# 阶段四：重点页面艺术指导与精细排版

```markdown
# Phase 4 — Editorial Art Direction & Page Composition

## 任务目标

在已完成的排版优化、全局背景和 SVG 插画基础上，对现有主要页面进行精细的艺术指导与视觉整合。

本阶段不是重新设计整套系统，而是让每个页面拥有自己的构图特点，同时保持统一的品牌风格。

## 1. 为每个页面确定视觉策略

请逐页检查当前应用，为每个主要页面定义：

- 页面主要目标。
- 第一视觉焦点。
- 主要内容区域。
- 辅助信息区域。
- 插画的使用位置。
- 手绘标记的使用目的。
- 页面背景与内容表面的关系。

不同页面不应仅仅更换标题和数据，却使用完全相同的布局。

## 2. 首页与总览页面

如果应用存在首页或总览页面：

- 让页面标题具有明确的编辑式排版特征。
- 将核心功能入口与辅助信息区分开。
- 允许主标题、说明和插画形成非对称组合。
- 使用适量手绘箭头、圈注或构图线引导视线。
- 让用户能够迅速找到最重要的功能入口。

不要将首页设计成大标题、四张相同卡片和一排统计数字的标准模板。

## 3. 功能页面

对于知识库、工作区、文档、搜索、编辑器等页面：

- 优先确保真实业务内容清晰。
- 通过排版和空间关系区分主内容与辅助操作。
- 使用与功能直接相关的 SVG 插画。
- 在适合的位置增加轻量的说明、标签或手绘注释。
- 通过表面明度、边框和间距构建内容层级。
- 让表单、表格和列表拥有一致的视觉语言。

不能为了视觉效果隐藏功能、减少必要的信息或增加操作步骤。

## 4. 空状态与首次使用体验

对没有数据、尚未创建内容、搜索无结果等状态进行专门优化。

可以加入：

- 与功能相关的线稿插画。
- 简短而明确的说明。
- 具有明确操作目的的主按钮。
- 少量手绘箭头或注释。
- 适度的留白和局部构图。

空状态不能只有一个小图标和一句文字，也不能变成占据整个屏幕的装饰海报。

## 5. 微观排版

统一检查：

- 标题与副标题间距。
- 正文行宽和行高。
- 表格与列表的密度。
- 按钮之间的距离。
- 卡片内边距。
- 文字与插画的对齐。
- 页面左右边距。
- 不同区块之间的垂直节奏。

重点优化视觉节奏，不要机械地将所有间距统一成同一个数值。

## 6. 装饰元素的使用规则

每一个手绘箭头、圈注、网格、插画和边框都应有明确目的。

装饰应当：

- 强化信息层级。
- 引导视线。
- 解释内容关系。
- 提供品牌辨识度。
- 丰富构图。

如果某个装饰删除后不会损失任何视觉或信息价值，应考虑删除。

## 7. 双主题一致性

在白天和黑夜模式下分别检查每个页面。

确保：

- 插画没有消失。
- 装饰线条没有过亮。
- 卡片与背景仍有合理层次。
- 标题、正文和辅助文字保持可读。
- 主按钮仍然清晰可辨。
- 不会出现某个主题精致、另一个主题单调的情况。

## 8. 验收标准

每个主要页面都应具有自己的视觉焦点和构图特点，同时共享相同的手绘语言、语义色系统、字体体系和交互规则。

请实际完成修改，并提供逐页的变更说明。
```

# 阶段五：全站视觉打磨与质量验收

```markdown
# Phase 5 — Visual Polish & Quality Assurance

## 任务目标

对已经完成视觉优化的前端项目进行全站检查和最终打磨。

本阶段重点关注视觉一致性、细节质量、双主题适配、响应式布局、性能和功能完整性。

## 1. 全站视觉巡检

逐一检查所有主要页面和状态：

- 正常内容页面。
- 数据为空的页面。
- 加载中状态。
- 搜索无结果状态。
- 错误提示状态。
- 表单校验状态。
- Hover、Focus、Active、Disabled 状态。
- 白天主题。
- 黑夜主题。
- 桌面、平板和移动端布局。

不要只检查首页。

## 2. 消除视觉不一致

检查是否存在：

- 相同组件使用不同边框颜色。
- 同类按钮拥有不同主色。
- 手绘线条粗细不一致。
- 不同页面使用互不相关的插画风格。
- 背景纹理在不同页面重复叠加。
- 卡片阴影过重。
- 局部装饰过多。
- 页面标题层级不统一。
- 黑夜模式下文字或插画对比度不足。

优先通过统一 Token、复用组件和修正布局解决问题，而不是增加更多覆盖样式。

## 3. 颜色与无障碍检查

使用实际渲染的前景色与背景色检查 WCAG 对比度。

重点检查：

- 正文与页面背景。
- 辅助文字与卡片背景。
- 按钮文字与按钮背景。
- 链接与周围文字。
- 输入框边界与背景。
- SVG 线稿与其背景。
- 状态提示文字与状态背景。
- 键盘焦点指示器。

不要仅凭视觉感觉判断颜色是否合格。

必要时调整语义 Token，但不要因此改变整体设计方向。

## 4. 响应式检查

确保：

- 页面没有横向溢出。
```
