=== P1 两张表（backend/app/auth/models.py） ===

照 report/models.py 的结构：模块自己的 `AuthBase(DeclarativeBase)` + `create_auth_schema(engine=None)`，
不碰别家的 metadata，不引入 alembic。

class User(AuthBase):
    __tablename__ = quoted_name("user", True)     # user 是 MySQL 保留字，照 constraint 的先例
    user_id / username / email / password_hash / display_name / role / status
    created_at / last_login_at

class Permission(AuthBase):
    __tablename__ = "permission"
    permission_id / user_id / permission / resource / granted_at / granted_by
    ForeignKey("user.user_id") + UNIQUE(user_id, permission, resource)

字段类型严格按 §4.1：全部 VARCHAR + DATETIME，不要自作主张改成 JSON 或 Text。
`username` `email` 各加唯一索引；`role` 默认 'student'；`status` 默认 'active'。

create_auth_schema 要求：
- 幂等：连跑两次不报错（`create_all` 自带，但你要在测试里真连跑两次证明）
- 在真实 MySQL 上跑一次，然后 `show tables` 看到 `user` 与 `permission`
- 不要建在应用启动时（`api/app.py` 的注释已经写明「应用启动不隐式改库」），

=== P2 密码哈希（backend/app/auth/security.py） ===

禁止使用 argon2 / passlib / bcrypt——前两个没装，bcrypt 不在 requirements.txt，
属于隐式依赖。用标准库：

    hashlib.scrypt(password.encode(), salt=salt, n=2**14, r=8, p=1, dklen=32)

存储格式自描述，一个字段装完：
    scrypt$16384$8$1$<salt_b64>$<dk_b64>
（salt 16 字节、dk 32 字节，base64 后总长约 90 字符，VARCHAR(256) 富余）

对外只暴露三个函数：
    hash_password(password: str) -> str
    verify_password(password: str, stored: str) -> bool      # 用 hmac.compare_digest
    check_password_strength(password: str) -> str | None     # 返回错误原因或 None

规则：长度 8~64；至少一个字母、一个数字；不含空白。
用户名：3~32，仅 [A-Za-z0-9_-]；邮箱：简单正则即可（不追求 RFC 5322 全量）。
verify_password 要能吃下"格式不对的 stored"，返回 False 而不是抛异常——
库里的脏数据不该把登录接口打成 500。

=== P3 自签 token（backend/app/auth/token.py） ===

这不是 JWT，别在文档、注释、响应里写 JWT。格式三段：

    v1.<b64url(payload_json)>.<b64url(hmac_sha256(secret, "v1." + payload_b64))>

payload = {"uid": user_id, "role": role, "exp": 到期unix秒, "pv": 密码指纹}
- `pv` = sha256(password_hash).hexdigest()[:16]
  作用：用户改密码后，所有旧 token 自动失效，**不需要第三张表**
- 默认时效 8 小时，可用 AUTH_TOKEN_TTL_HOURS 覆盖

AUTH_SECRET 只从环境变量读（.env 里加一行，`.env.example` 只加键名）：
- 长度 < 32 直接 raise RuntimeError，**不许有默认值、不许静默降级**
- 生成方式：python -c "import secrets; print(secrets.token_urlsafe(48))"
- 这个值不许出现在任何 log_event、任何响应、任何测试夹具、任何提交文件里

对外：
    issue_token(user_id, role, password_hash) -> str
    decode_token(token) -> dict        # 失败抛 TokenError(reason=...)
    reason 枚举只有五个：bad_format / bad_signature / expired / pv_mismatch / unknown_user
校验一律 hmac.compare_digest，不要用 == 比签名。

## 三、为什么这么写

**为什么哈希不用 argon2、也不顺手拿 bcrypt。** 计划书写的 argon2 依赖 `argon2-cffi`，环境里没有；`bcrypt` 能 import 是因为它被某个包捎带装进来了——**能 import 不等于能依赖**，换台机器或换个大版本就可能消失，这类 bug 在 CI 上表现为「本地全绿、服务器 ImportError」。`hashlib.scrypt` 是标准库、内存硬、参数可存进哈希串里，唯一代价是要自己写 12 行封装与自描述格式。这个代价比引入依赖小。

**为什么 token 里要带 `pv` 指纹。** 「改密码后旧 token 立即失效」通常要靠一张 `token` 表或 Redis 黑名单，但计划书明确只要两张表。把 `sha256(password_hash)[:16]` 写进 payload，校验时与库里现算的值比一下——改密码必然换 `password_hash`，旧 token 的 `pv` 立刻对不上。**用一条 16 字符的字段，省掉一张表**。

**为什么登出不做服务端黑名单。** 做黑名单要么建第三张表，要么放内存——内存版的登出在进程重启后失效，是更糟的假安全。本版选择：登出清前端 token + 记一条 auth 日志，服务端不撤销。代价必须写清楚：**token 在 8 小时窗口内仍然有效**，要立刻断掉所有人的会话，走 `user.status='disabled'` 或改密码。这个取舍写进 findings，不许含糊成「已实现登出」。

**为什么两条 409、两条 401 必须文案一致。** 注册接口如果回「邮箱已被注册」，攻击者就能拿邮箱列表批量探测哪些人在这个系统里注册过——这是登录页最常见的泄漏点，且修起来只是把两句话合成一句。测试里专门用「两句文案完全相同」来锁，是因为这种要求一旦没有断言，改文案的人一定会顺手写清楚一点。

**为什么 `test_metrics.py` 必须改。** `auth_total` 现在是 `render()` 里两行写死的 `0`，不管发生什么都输出 0——P17 接上登录成败后，如果不动它，指标永远显示零，比没有更坏（运维会以为没人登录）。改成计数器渲染是必须的，同时**必须把断言改得更严**：原来只断言「这两行字在文本里」，改后要断言「成功一次变 1、失败一次变 1、两者互不串」。这是本版唯一允许动既有测试的地方，所以单独点名。

**为什么 P0 要卡 `check_logs.py` 退出码 0。** P16 收口的判据之一就是它。如果带着 `report`/`review`/`importing` 三个空目录直接开 P17，下一步就会有人为了让脚本绿而把它们加进白名单——白名单一旦为了「当前状态」而加，就再也收不回来。**先收口，再开工。**
