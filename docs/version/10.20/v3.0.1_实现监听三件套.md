=== P1 /health（进程存活） ===

    {"status":"ok","uptime_s":1234,"version":"0.3.0"}

- `uptime_s` 取进程启动到现在的整秒数，模块级记一个 `_STARTED_AT = time.monotonic()`
- 永远返回 200，就算 MySQL 挂了也返回 200——「活着」和「能干活」是两件事，后者交给 `/readyz`
- `version` 从 `create_app()` 里的 `FastAPI(version=...)` 取，**不要硬编码第二份**

=== P2 /readyz（依赖就绪） ===

`GET /readyz`，逐项检查，**必须能指出哪个不通**：

    // 全通，200
    {"status":"ready","checks":{"mysql":{"ok":true,"elapsed_ms":3},
                                  "chroma":{"ok":true,"elapsed_ms":8}},
     "collection":{"name":"paper_review","count":2522}}

    // 有不通，503
    {"status":"not_ready",
     "checks":{"mysql":{"ok":false,"elapsed_ms":3,"error":"connection refused"},
               "chroma":{"ok":true,"elapsed_ms":8}},
     "failing":["mysql"]}

实现要求：

- **MySQL**：用 `backend/app/importing/db.py` 的 `get_engine()` 开连接跑 `SELECT 1`。
  不要新建 engine，不要绕过它（`get_engine` 已带 `pool_pre_ping=True`）。

- **Chroma**：用 `parent_child.get_collection()`，成功后再 `.count()`。

- 每项的 `elapsed_ms` 单独记，用 `time.perf_counter()`。

## 三、为什么这么写

**为什么 `/readyz` 要求「先跑完两项再汇总」。** 最省事的写法是第一项失败就 `return 503`。但运维半夜看到「mysql 不通」，修好重启，再一看「chroma 不通」——两次重启，两次故障窗口。把两项都探完、一起报，是这类端点唯一值得坚持的细节。

**为什么强调「`/readyz` 不能写成永远 ok」。** 只返回 `{"status":"ok"}` 的 readiness 探针在 Kubernetes 里会直接把流量导进一个连不上库的实例。它存在的全部意义就是「不通时说清哪里不通」，否则 `/health` 已经够用了。

**为什么 `/metrics` 要手写而不是引库。** `prometheus_client` 会带来一个多进程模式的坑（需要 `PROMETHEUS_MULTIPROC_DIR`），而本项目单进程、指标只有五个。手写一份 exposition 大约六十行，还能顺带把「浮点别用科学计数法」「标签要转义」这两个真实坑显式处理掉——引库反而把这两点藏起来了。

**为什么三个端点要跳过日志中间件。** Prometheus 默认 15 秒抓一次，一天 5760 条 `api/request`。这些日志没有任何诊断价值，却会把真正有用的请求日志淹掉，还让 `logs/api/` 的文件滚动提前触发。这类「观测行为本身成为噪音」的问题，通常要等日志炸了才被发现。

**为什么测试里要专门用 monkeypatch 造单项失败。** 正常环境下 `/readyz` 永远 200，测不到 503 分支。而 503 分支恰恰是这个端点唯一的价值所在。测试必须能证明「Chroma 挂时 `failing` 里只有 chroma」，否则写完等于没写。

**为什么 P6 要求真跑一次 503。** 单测里 mock 掉的失败路径和真实连接失败的路径，在错误信息上往往不一样（真实异常可能是 `OperationalError`，mock 的是自己抛的 `RuntimeError`）。要确认 `except` 分支真的兜住了真实异常、且没把 DSN 打进响应，只能真断一次。

**为什么这一版不碰 Playwright。** 前端 9 条红灯是 `v3.0.0` 就存在的，和监听端点毫无关系。把它塞进这一版，等于让「监听三件套」的验收结果取决于前端修复进度。放到 `v3.0.2` 的门禁章节，单独定级。
