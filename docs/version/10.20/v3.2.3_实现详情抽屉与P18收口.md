**一件必须先解决的事：抽屉要定位原句，但落档记录没有正文。**

`locateEvidence` 需要「拼好的全文」才能 `indexOf`。而 `GET /api/reviews/{id}` 在**已落档**分支只返回 `review` + `dimensions` + `change_list`，**不返回 `sections`**；只有「尚未落档、仅有会话快照」的分支才返回章节树。抽屉如果只拿 quote 文本，就只能显示原文、点不了定位——那计划 §5 任务 4 的「原句可点定位」就是空的。

所以本版补一步最小后端改动：**落档分支也带 `sections`**（从 `review_session` 取，没有快照就给空数组）。不改权限、不加新接口——**不要再开 `/records/{id}/detail`**，同一份数据两套接口，改一处必忘另一处。

**另一件：教师 E2E 的身份供给。** 现在 `global-setup` 只造学生账号，而 `role` 没有接口可改。本版写一个**测试装置脚本** `scripts/promote_e2e_teacher.py`：连库把 `e2e_teacher` 的 `role` 改成 `teacher` 并重写 7 条权限，幂等。它**不进产品路径、不挂任何 API**，只在 E2E 前置里由人手动跑一次。`global-setup` 里加一道校验：教师 token 的 `/auth/me` 若不含 `review:read:all`，立刻抛错并提示跑这个脚本——用于挡「忘了提权就跑 E2E」这种情况。

## 三、为什么这么写

**为什么宁可改一个已有接口，也不新开 `/records/{id}/detail`。** 抽屉要的数据（五维、`change_list`、`sections`）与 `GET /api/reviews/{id}` 已经给的几乎重合，差的只有 `sections`。新开一个接口意味着同一份数据两条读路径、两处权限判断、两处审计埋点——而人类的记忆只够记住一条。补一个字段是 3 行，新开接口是 100 行加一次「为什么这里没记审计」的追问。

**为什么原句定位放在抽屉里，不跳 `/scoring`。** `/scoring` 与 `/consistency` 读的是 `useReviewFlow` 里的 sessionStorage，那是「我当前正在看的这篇」。抽屉打开的是**别人**的历史记录，跳过去只会看到空页面或者自己那篇的数据——比不能点更糟。所以定位必须在抽屉内部完成：`concatSections(sections)` 拼正文、`locateEvidence` 找位置、就地高亮。这套逻辑已经有现成实现（`useOffsetLocator`），复用它还能保证「同一条原句在哪个页面定位结果都一样」。

**为什么教师身份用脚本提权，而不是加一个「改角色」接口。** 加接口最省事，但那个接口在生产里就是「任何人可以把任何人变成教师」——为一个 E2E 用例开这种口子，是典型的本末倒置。脚本连库、只改固定用户名、幂等、不进产品路径，代价是 E2E 前置多一条手工命令；收益是生产面没有多出一个提权入口。

**为什么 `global-setup` 要校验教师权限并在缺失时抛错。** 如果提权没做，`e2e_teacher` 只是个普通学生，教师用例会以 403 失败，日志看起来像「权限功能坏了」。加一道 `/auth/me` 校验，把它变成一句「先跑 promote 脚本」——**同样的失败，报错信息不同，排查时间差十倍**。

**为什么判据不写「新的 passed 总数」。** 本 shell 跑不了 E2E（`spawn EPERM`），新增用例一条都没真跑过。这时候写「41 passed」是编的；而写「8 条既有红灯集合不变、新增用例不引入新红」，是可以在人类跑完后一条条对上的。**没跑过的数字不写，写可验证的条件。**

**为什么允许改 `RecordsTable.vue` 与 `记录总览.vue` 而不算「动既有测试」。** 它们是被改功能本身（加行点击、接抽屉），不是断言。单测里 `records-view.spec.ts` 已有的 6 条断言不受行点击影响——如果它红了，说明表格结构被改坏了，那时候该修代码，不是改断言。
