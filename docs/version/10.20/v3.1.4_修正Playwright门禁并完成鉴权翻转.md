## 二、本次复核结论（2026-10-20 17:16–17:20，同一台机器实测）

我把三件事依次跑了一遍，结论是**项目、浏览器、配置都没问题，EPERM 来自执行沙箱**：

| 复现项 | 结果 |
|---|---|
| 子进程自检 `spawnSync('cmd',['/c','echo','hi'])` | `ERR: undefined`、`OUT: hi` → 这个 shell 能 spawn |
| 浏览器目录 `%LOCALAPPDATA%\ms-playwright` | `chromium-1248` / `chromium_headless_shell-1248` / `ffmpeg-1013` / `winldd-1007` 都在 |
| 单条 E2E `npx playwright test tests/e2e/theme.spec.ts` | **1 passed (16.2s)**，webServer 自动拉起，退出码 0 |
| **全量 `npx playwright test --reporter=list`** | **37 passed / 8 failed，2.0 min，EXIT=1** |

两点必须纠正的口径：

1. **`--list` 的 45 条不是基线。** 45 = 37 passed + 8 failed，是**用例总数**；`--list` 只证明「用例可被发现」，跟「能不能跑」无关。上一轮把 45 和 37/8 当成两个冲突的数字，其实是同一个东西的两种读法。
2. **Playwright 全量的退出码本来就是 1。** 8 条既有红灯没修，所以 `--reporter=list` 跑完必定 EXIT=1。`v3.1.3` 的 P0 只写了「记下 passed/failed」，没写清这一点，才让执行方以为「退出码 1 = 门槛不通过」。**判据是「与 37/8 逐条一致」，不是「退出码 0」。**

所以本版**不降低门槛、不豁免 Playwright**，只把「在哪个 shell 里跑」这件事写死。

## 四、如果确实换不了执行环境

只有一种情况算「环境不可用」：P0 三连里 **a 报 EPERM**，且用户在本机终端跑 c 也失败。此时**不许硬着头皮往下做**，按这个顺序处理：

1. 提交**证据包**：`npx playwright --version`、a 的两行输出、b 的目录清单、c 的完整错误原文、`ls test-results`；
2. `progress.md` 记「本轮未执行 E2E，原因附证据包」；
3. `findings.md` 记一条裁决：「Playwright 在当前执行环境不可启动，判据 6 记部分满足，允许带病进 P18」；
4. `report-P17.md` 的判据 6 写「三条绿 + E2E 未复测」，**不许写成通过**；
5. 立一版 `v3.1.5` 专补 E2E 复核，标题写清「等执行环境恢复」。

**为什么允许这样，而不是干脆不算完成**：P17 的产品改动（鉴权翻转）完全由 pytest 覆盖（288 条里有 8 条专测四个端点的 401/404），E2E 在这里的作用是「确认前端没被带崩」，而不是「验证鉴权正确」。但「允许」不等于「可以不记」——所以必须留下证据包与一条明确的部分满足结论。

## 五、为什么这么写

**为什么先判归属再谈门槛。** `spawn EPERM` 有三种完全不同的成因：执行沙箱拦子进程、浏览器没装、webServer 起不来。这三种的处置互斥——换终端、装浏览器、腾端口。不分清就动手，最常见的结局是把 `playwright.config.ts` 改得面目全非，最后发现是沙箱。P0 三连（能不能 spawn / 浏览器在不在 / 单条能不能跑）用不到两分钟就能定位，比读代码猜快得多。

**为什么把「全量退出码 1 是正常的」写死。** 这是上一轮真正的误判点。8 条既有红灯没修，`playwright test` 就必然返回非零，而 `v3.1.3` 的 P0 只写「记下 passed/failed」——执行方看到退出码 1，就判了门槛不过。**当门槛是个复合条件时（数量 + 集合），必须把「哪个数字是判据、哪个不是」写明**，否则每换一个人执行都要重新踩一次。

**为什么 `--list` 的 45 条要专门纠正。** `--list` 只做静态收集，不启动浏览器，所以它在 EPERM 的环境里也能成功——这恰恰是它的危险之处：它让「用例可发现」看起来像「环境可用」。把它和 37/8 并排放进体检表，就会产生「45 与 37+8 对不上」的错觉。说清「45 = 37 + 8」，这个疑点自然消失。

**为什么默认身份给教师。** 80 条历史记录 `user_id` 是 NULL；本版收紧后，无主记录只有 `review:read:all` 能读。默认给 student 会让一批与权限无关的用例变 404，那时你无法区分「鉴权写错了」还是「默认身份选错了」。给 teacher 的意义是：**翻转前后除了「必须有身份」这一条，其它变量都不变**。

**为什么那条「匿名建评审存 NULL」必须改写，而不是加 marker 混过去。** 它断言的是「匿名可以创建评审」——正是本版要取消的行为。加 marker 让它继续跑，等于让测试替旧行为背书，最后要么它红、要么你把翻转做回去。改写后的形态是：HTTP 层断言 401（更严），存储层的意图（空串必须落 NULL）下沉到 store 层继续覆盖。**判断「改断言」是否放宽只有一个标准：改完更严还是更松。**

**为什么把 `optional_user` 整个函数删掉。** 翻转最怕的不是漏翻一处，而是留个「反正还能用」的后门。函数还在，下一个人遇到「不方便带 token」就会顺手用它。删掉之后，想放行得重新写函数、重新解释理由，成本高到不会顺手做。
