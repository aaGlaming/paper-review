## 一、本版要解决什么

### 1.1 P23 至今没有细则

`Phase-3-plan.md` 的挂账写明：P21～P26 的逐条任务表随 `v1.10.0_第二期计划.md` 一起删了，**开工前需按框架重写，不凭记忆补**。P21、P22 都已经产出细则（`Phase-3-P21-plan.md` / `Phase-3-P22-plan.md`），**P23 没有**。

### 1.2 真正的问题不是「补不补」，是分母 2 被当成百分比

v3.7.0 测出的事实：

| 指标 | 分子/分母 | 页面现在显示 |
|---|---|---|
| 档位一致率 | 26 / 60 | 43.3% |
| 引用精确匹配率 | 60 / 60 | 100% |
| **证据不足命中情况** | **0 / 2**（deterministic） | **0%** |
| 同上（model 档） | 2 / 2 | **100%** |

`MetricCard.vue` 的 `formatRate` 把 `rate` 一律乘 100 加百分号。于是 **2 个样本的判定被渲染成一个加粗的 100%**，和 60 样本的 100% 长得一模一样。

这不是显示瑕疵，是**口径漏洞**：分母 2 只可能给出 0%、50%、100% 三个值，任何一个都自带 ±50 个百分点的粒度。**把噪声当精度呈现，比不呈现更糟。**

### 1.3 八条 E2E 红已经连续六个版本「沿用」

P19 至 P23，每一版的 progress 都写「E2E 46 passed / 8 failed，均为既有 `confirmed-card` 超时」。它们从未被修、也从未被显式交接。**长期挂账的待办在报告里长得像结论。** 本版给它一个明确的接收方（P25，因为 P25 本来就是「超时可见」）。

### 1.5 第三次空转：pytest 度量的是 PATH，不是代码

本版唯一新增的证据来自一次「读错解释器」的停版。原文：`85 tests collected, 42 errors`，而正确值是 467。我在同一台机器上复现了：

| 命令 | 解析到 | 结果 |
|---|---|---|
| 裸 `pytest backend/tests -q --collect-only` | `D:\Configuration\python\Scripts\pytest` | `85 tests collected, 42 errors in 2.05s` |
| 裸 `python` | `D:\WorkBuddyData\binaries\python\versions\3.13.12\python.exe` | 不是项目环境 |
| `"$PY" -m pytest ...` | `env\agent-task\Scripts\python.exe` | `467 tests collected` |

两点必须记住：

1. **裸 `python.exe` 也是错的**，它落到受管的 3.13，不是项目的 3.11.16。`scripts/check_eval_gold.py` 在 3.13 下直接 `ModuleNotFoundError: No module named 'sqlalchemy'`，EXIT=1。也就是说提示词里每一处 `python.exe` 都该写成 `"$PY"`。
2. **`check_logs.py` 和 `check_docs_encoding.py` 只用标准库**，在任何解释器下都能输出 `[ok] ...`。它们会通过，但它们的通过**不能证明解释器正确**——这解释了为什么这次「日志检查通过」与「收集数不对」能同时成立。

这是我第三次在同一类问题上空转：第一次空转在 Chroma（读不了库），第二次在 3306（判据没写全），这次在 PATH（命令没写全）。**三次的共同点不是环境坏，是判据没把「用什么工具测」写进去。** 收集数是一个对解释器极度敏感的量，却写在了一条不绑定解释器的命令上。

## 三、为什么这么设计

**「不补」比「补」需要更多证据。** 少做一件事很容易被读成偷懒，所以本版把理由压到数据上：候选 136 条里 133 条在同一个赛题，2025-A 是 0 条。这不是「没时间标」，是**用现有候选无论怎么挑，都会把 4/4/4 变成 5/4/4**。计划里写的「可选补 1 篇」在候选分布面前自动失效——这比一句「本版不做」有力得多。

**降呈现而不是改数字。** 很多人会想把分母 2 的指标直接删掉。不删的理由是它确实是 gold 的一部分，删了覆盖率就少一块；但把它从「100%」改成「样本过少」，页面**既没丢信息，也没伪造精度**。`rate` 保留原值还带来一个好处：将来补到 5 条以上，同一份代码自动恢复百分比，不需要再动一次。

**阈值必须是常量。** `LOW_SAMPLE_THRESHOLD = 5` 写在模块顶，是因为「多少样本才敢给百分比」迟早会被质疑（有人会说 3 就够、有人会说 10 才够）。写成常量，争议只需要改一个数字；写死在 `if total < 5`，争议就变成翻代码。

**给八条 E2E 红指定接收方，是本版最像「项目管理」的一节。** 它们的根因（确认链路 25–40 s vs 测试等待 5 s）属于 P25 的范围，不属于 P23。但「属于 P25」和「写在 P25 收口判据里」是两件事：前者是解释，后者是约束。写进移交清单，P26 验收时才不会发现有一笔六版陈账没人认领。
