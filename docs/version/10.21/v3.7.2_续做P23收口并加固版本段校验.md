## 三、为什么这么设计

**先修审计链，再干活。** 上一轮的 P0 证据是真的，但它挂成了 v3.7.0 的三级子标题——**这意味着下一版无论用 grep 还是用眼睛，都判不出「v3.7.1 跑过没有」**。先把它提升为 `## v3.7.1` 段（内容一字不改、并标注原层级），后面所有判断才有立足点。修标题不是补记录，改的是"能不能查"。

**把误判机制写进纪律。** `^## v3.7` 会同时命中 v3.7.0，这是版本号只差一位时的经典陷阱。所以本版要求三条同时满足：精确标题（带边界）+ **产出的文件存在** + 可 grep 的符号存在。三条里「文件存在」权重最高，因为文本 grep 只能证明"有人写过这几个字"，`ls` 能证明"东西真的在"。

**不重跑 P0。** P0 的取证产物（3.11.16、467、3306 三法、只读四数）已经被记录，重跑一遍只会多花时间，还可能因为环境漂移产生新数字、引出"到底以哪次为准"的争论。**续做版的第一原则是不制造第二份同源证据。**

**不加新判据，只把已有判据说清楚。** 本版判据全部沿用 v3.7.1：469 / 159 / 新增失败 0 / 三个脚本 EXIT=0。一个已经卡了三轮的小阶段，最不该做的事是趁续做时顺手加要求。
