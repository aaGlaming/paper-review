# v3.3.8 · 修正问询定点取证与摘要口径

> **阶段**：Phase-3 / P19（收口修正版；通过后进 P20）
> **前置**：`v3.3.7` 前端与门禁已通过（356 passed / vitest 146 / E2E 43-8），但 **P19 判据 1 记「部分满足」**——单条详情与修改建议追溯都没命中被问的那条记录。
> **本版范围**：定位根因 → 让「问到某条记录」能确定性答出来（不依赖向量检索）→ 修摘要数字口径 → 重跑两类真实问询 → 更新 P19 判据。**不做前端、不碰 P20**。

---

## 一、根因：不是检索精度，是**那条记录根本没进索引**

`report-P19.md` 把两条失败归因为「检索精度未达标」。我按这个假设去查了实际数据，结论不同：

| 观察 | 实测值 |
|---|---|
| 被问的那条 `c50ee35713d6446d835b50d30caf9e5c` 在 `review` 表 | **在**（`cumcm-2024-A`） |
| 它在 `paper_parent` 里的父块 | **0 条**（`parent_id like 'rr-c50ee357…-%'` 无结果） |
| 该记录在 `review_dimension` 的维度行 | 5 条（齐） |
| `review` 总行数 / `review_dimension` 总行数 | **129 / 645** |
| 已索引的 review 数（`distinct review_id` in `rr-%` 父块） | **102** |
| **从未索引的 review** | **27** |
| `rr-` 父块总数 | **510**（= 102×5） |

**结论**：27 条记录只进了 MySQL、没进 Chroma。`search_records` 走的是向量库，所以无论问得多准都不可能有结果——回答里的「这些记录里没有相关信息」是**如实反映索引状态**，不是模型判断错，也不是相似度不够。

而「模块没坏」这一点反而更麻烦：**任何新提交只要没人记得跑回填脚本，就永远是问不到的**。所以本版不靠「记得跑脚本」修，而是让「问到具体某条记录」这条路**完全不经过向量库**。

### 摘要 88 与 83 的差额，也在同一轮查清了

`post_summary` 把 `compare_bands` 的原始 JSON 整段塞进 prompt，而其中 `counts` 是**按原始写法分键**的：

```
assumption: {"基本": 88, "证据不足": 76, "不足": 18, …}
insufficient: 94        ← 代码已把两种写法合并
insufficient_total: 94  ← 合计
```

同一档事在 prompt 里出现了两个名字（`证据不足` 与 `不足`），旁边又有一个代码算好的合计。模型按字面把「证据不足」当成独立一档去加，漏掉「不足」那部分——**差额恰好等于该赛题内 band 为「不足」的条数**（当时 5 条，现在 `cumcm-2024-A` 是 13 条、`cumcm-2024-C` 是 7 条）。

这是**我们自己在 prompt 里造出来的歧义**，不能算模型数不准。修法是让 prompt 只出现一套口径，并把合计写成一行「照抄」文本。

## 三、为什么这么写

**为什么先把「27 条没进索引」查出来，再谈检索精度。** 上一版把失败归因为「检索精度不够」，听起来合理、方向却错了：精度问题表现为「召回到了但排得不好」，而这次是**召回的候选集里根本没有这条记录**。两者的修法不通用——调相似度、调 top_k、改 prompt 都不会让一个不在库里的块被召回。**归因错一层，后面所有工作都是白做。**

**为什么核心修法是「定点取证」，而不是「保证每次都跑回填脚本」。** 靠脚本就得靠人记得，而这个项目每天都有新提交产生（129 条里 27 条没索引，就是这么攒出来的）。定点取证把「问到某条记录」变成一次主键查询：不依赖索引、不依赖向量库、不依赖后端是否正好在跑。**能变成确定性查询的事，不要留在概率检索里。**

**为什么定点模式下不掺向量结果。** 掺进来看着「信息更全」，实际是给模型提供了错误的引用素材：它可能引用另一条记录里同样写着「证据不足」的块，答案读起来毫无破绽，refs 也可点、也可追溯——**唯一的错是那不是被问的那条**。v3.3.7 的失败正是这个形态。宁可用 6 条确定的块。

**为什么概览块不可引用。** 它列的是 `change_list`（修改条目），不是评审维度。若允许引用，`refs` 里会出现 `dim=record_summary` 这种维度值——前端 chip 会显示成一个不存在的维度，判据 2 的「引用带 dimension_code」在形式上仍成立、语义上已经空了。**让它当线索、不当依据。**

**为什么摘要要「代码算好一行照抄」。** 现在的 prompt 同时给了 `counts`（两种写法分键）和 `insufficient_total`（已合并），等于让模型在两套口径间自己选。人看到这种 prompt 也会犹豫，模型漏加一部分才是正常反应。改成「一套数字 + 禁止自行相加」后，模型只需要把给定的串抄进句子——**这类错误不能靠 prompt 措辞提醒，要靠取消歧义。**

**为什么批次要分开跑。** 17 条测试里有一半在验证「数字对不对」，另一半在验证「路径走没走对」。一次写完再跑，红了面对一片红，你分不清是取块逻辑错了还是口径合并错了。**先让路径绿，再让数字绿。**
