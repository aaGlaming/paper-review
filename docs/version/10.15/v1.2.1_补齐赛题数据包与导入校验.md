   - archive_contest(contest_id)：置为 archived。
   - copy_rubric_as_draft(contest_id)：从当前 published 量规复制出 version + 1 的 draft。
   - publish_rubric(rubric_id)：发布该版量规；同一赛题同时只能有一条 published 量规。

   - check_type 不在 mention / numeric_range / required_case 之内；

   - dimension.code 不在五个允许值内；
   - exemplar.band 取了「证据不足」。
   整包拒绝后，库里已发布赛题的行数必须与导入前完全一致。
5. 导入代码**不得出现按题号的分支**：不得出现 `cumcm-2024-A` 之类的字面量比较。差异只能来自 JSON 数据。

## 3. 为什么提示词要这么写（给你复核用）

| 约定 | 来源 | 为什么写进提示词 |
|---|---|---|
| 「零、动手前自检」单独成节 | 实测 | 生成首版时 `.env` 的 `MYSQL_DSN` 实测为空（现已在 v1.2.1 填写并验证连通），但自检一节仍保留：DSN 缺失或凭据轮换时，不写死处置的话 AI 会自己编一个 `mysql://root:root@localhost/paper_review` 然后一路跑偏——**这是本版最大的坑** |
| 明令禁止把凭据写进测试与文档 | 需求第十一章 | 测试文件要入库，凭据进去就是泄露；而且 `.env` 已被 gitignore，只有从环境变量读才安全 |
| 点明 alembic 不在锁定依赖 | 实测 | AI 见到 SQLAlchemy 第一反应就是 Alembic 迁移。引入即违反"只用锁定依赖"，必须先堵住 |
| 明令不得引入新依赖 | 任务文档 §2 | 共享环境 `agent-task` 被多个项目共用，随手装包会波及别人 |
| 只建七张表 | 计划书 §7 | 一次性建完所有表会顺手把 `review`/`sample_paper` 的表结构定死，而它们的字段要到 P6/P7 才明确，**早定早返工** |
| 坏包矩阵逐条列死 | 任务文档 §8 | "整包拒绝"最容易做成"部分写入后报错"，必须逐条对应到测试 |
| 用 AST/正则扫描源码断言无题号分支 | 需求 §12.5 | 光靠"我保证没写分支"没用，**要用机器验证**。这条是验收里的原话 |
| 测试双环境策略 | 执行手册 §6.1 | 执行手册对 P3 有"没 Docker 就用内存假件"的口径；P2 同理。既不强求凭据到位，也不放弃校验覆盖 |
| 第 2 版量规行为留给 v0.8.0 | 任务文档 §8 任务 4 | 防止本版提前把"新旧评审版本隔离"做掉，那是 v0.8.0 和评审记录一起测的 |
| 明示 MySQL 版本 8.4 | 实测 | 文档写的是 MySQL 8.0，本机是 8.4。要求"保持 8.0 兼容语法"，避免用 8.4 专有写法把后续部署（AWS RDS）搞挂 |
