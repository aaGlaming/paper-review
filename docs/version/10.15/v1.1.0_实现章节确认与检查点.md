一、本版不调用云端模型

二、实现 build_review_graph()
以下导入路径已在本机 langgraph 1.2.15 实测可用，照抄即可，不要另找写法：
  from langgraph.graph import StateGraph, START, END
  from langgraph.types import interrupt, Command
  from langgraph.checkpoint.memory import InMemorySaver

1. 状态用 TypedDict，至少含这些键：review_id、paper_text、sections、confirmed、status、score_node_calls。
2. 节点顺序固定为 parse → confirm → score → END。
   - parse：按 Markdown 标题规则切出章节树。章节类型只允许六个：假设、模型、求解、结果、检验、参考文献。切不出类型的标题归入「未分类」，不得新造第七类。产出后 status = 待确认。
   - confirm：调用 interrupt()，把当前章节树作为 payload 交给调用方；收到 Command(resume=...) 的答复后用答复中的章节类型覆盖，confirmed = True，status = 评分中。resume 之后不得重新解析章节树。
   - score：本版是占位节点，不做评分，只把 score_node_calls 加 1 并令 status = 完成。它存在的唯一目的是让测试能断言「未确认时它一次都没被调用」。
3. 检查点用 InMemorySaver，thread_id 取 review_id。只有 compile(checkpointer=...) 的图才支持 interrupt/resume；没传 checkpointer 的图不得用于本版验收。
4. 对外暴露三个函数：
   - build_review_graph(checkpointer=None) -> 编译后的图
   - create_review(paper_text, review_id=None, *, graph=None) -> str：文本为空或全是空白时立刻抛错（自定义 EmptyPaperError 或 ValueError），且不得产生 review_id；正常文本创建评审并推进到 interrupt，返回 review_id。
   - resume_review(review_id, sections, *, graph=None) -> dict：用 Command(resume={"sections": [...]}) 继续，返回最终状态。
5. status 取值只有五个：草稿解析、待确认、评分中、完成、失败。不得出现「已获奖」之类状态。
6. 本版不接 MySQL、不接 Chroma、不做文件解析（Markdown 字符串直接入参）。pypdf 与 python-docx 留到后续版本。

三、先写 backend/tests/graph/test_interrupt.py

2. 首次 create_review 后 status 为待确认，且 score_node_calls == 0。
3. graph.get_state(config).next == ("confirm",)，即确实停在确认节点。
4. 用同一个 review_id、同一个 checkpointer 重新调用 build_review_graph() 后，仍停在待确认且 confirmed 仍为假，sections 与首次解析结果一致——证明重启后从暂停点继续、不重算章节树。
5. resume_review 传入修正后的章节类型后：status 为完成、score_node_calls == 1，且 sections 严格等于 resume 传入的值，而不是重新解析的结果。

7. 对同一个已完成的 review_id 再次 resume，score_node_calls 不得变成 2。

## 3. 为什么提示词要这么写（给你复核用）

| 约定 | 来源 | 为什么写进提示词 |
|---|---|---|
| 必须有 `score` 占位节点 | 任务文档 §7 任务 3 | 验收要求「未 resume 时评分节点不被调用」，**没有节点就无法计数**。不点明的话，AI 很可能直接不建评分节点，这条验收就悬空了 |
| 给出实测过的导入路径 | 本机实测 | `interrupt` 与 `Command` 在 `langgraph.types`、`InMemorySaver` 在 `langgraph.checkpoint.memory`，写错一处就卡在 ImportError。已实测通过，照抄即可 |
| 「重建图后不重算章节树」写成断言 | 本机实测 | 实测同一 checkpointer 重新 `compile` 后 `next` 仍为 `("confirm",)`、`confirmed` 仍为 None，说明该验收确实可达；不写死断言方式，AI 容易只测个「能 resume」就交差 |
| 夹具写在测试文件内 | 任务文档 §7 允许目录 | 本版允许修改的目录不含 `data/`，**读样例文件就会越界改动 v0.7.0 的地盘** |
| `docs/plan` 列入允许修改 | 任务文档 §3.2 第 7 条 | 任务文档 §7 的允许目录没列 `docs/plan`，但每版必须写进度；这是明文例外，**不写清楚 AI 要么漏写进度、要么不敢动** |
| 明确「不接 MySQL／Chroma／文件解析」 | 任务文档 §7 依赖说明 | 防止本版顺手把 SQLAlchemy 和 Chroma 接进来，把 v0.3.0／v0.4.0 的活提前干完 |
| 重复 resume 不得重复评分 | 本机实测 | 实测对已完成 thread 再次 resume 不会重跑下游节点，`score_calls` 仍为 1；写成断言可锁住回归 |
| 禁止「已获奖」状态 | 任务文档 §4.6 | 状态枚举是最容易被 AI 自行发挥的地方，必须封死 |
