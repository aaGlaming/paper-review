一、实现 backend/app/llm/client.py

2. 配置只从环境变量读：LLM_BASE_URL、LLM_API_KEY、LLM_MODEL、EMBEDDING_MODEL。缺失时抛 LLMConfigError，错误信息不含密钥。
3. chat：POST {LLM_BASE_URL}/chat/completions；请求头 Authorization: Bearer {LLM_API_KEY}；请求体 {"model": LLM_MODEL, "messages": messages, "temperature": temperature}。只读取 choices[0].message.content 并返回。

6. 不得把 content / embedding 以外的响应字段暴露给调用方，不读取厂商私有字段。
7. 网络超时与重试放在客户端内部（httpx timeout 30s，网络层异常最多重试 1 次）。不要在本版实现「JSON 解析失败重试一次」，那是调用方在 v0.6.0 的事。

## 3. 为什么提示词要这么写（给你复核用）

| 约定 | 来源 | 为什么写进提示词 |
|---|---|---|
| 只做 v0.1.0，不碰赛题 JSON 和页面 | 任务文档 §1、§17 | 骨架里三道赛题、五张图、五个页面目录都已存在，**极易被 AI 当成「顺手填一下」**，一旦填了就是越版本提交 |
| `transport` 注入而非 monkeypatch 内部 | 工程判断 | `chat()` / `embed()` 是模块级函数，没有注入点就只能 monkeypatch，测试会很脏；`MockTransport` 是 httpx 官方测试方案 |
| 禁止返回空串冒充结果 | 任务文档 §6 任务 3 | 这是全文最容易被糊弄过去的一条——AI 最爱写 `return data.get("content", "")` |
| 明确「JSON 解析重试属于 v0.6.0」 | 任务文档 §11 | 防止 v0.1.0 提前把选档重试写进客户端，污染后续版本 |
| 两条 Ruling 直接给原文 | 任务文档 §3.3 | 省得 AI 自己编一条不痛不痒的裁决 |
| 给出当前基线退出码 5 | 实测 | 让 AI 知道「no tests ran」不是环境问题，是测试还没写 |
