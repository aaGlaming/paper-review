一、加总：backend/app/scoring/aggregate.py
1. 实现**纯函数** weighted_sum(dimensions, dimension_results) -> dict。
   本模块**不连数据库、不发 HTTP、不导入 backend.app.importing**；权重只从参数拿。
   - dimensions：量规数据，每项至少含 dimension_code 与 weight；
   - dimension_results：每维的选档结果，至少含 dimension_code、band、status。
2. 加权规则（逐条实现）：

   - band 为「证据不足」的维度**不参与求和**；
   - status 为「引用失败」的维度**不参与求和**；
   - 权重**只读** dimensions；模型返回里若出现 weight 或 score 字段，**一律忽略**，不报错也不使用。
3. 返回值至少含：total、weighted（进入合计的维度）、excluded（被排除的维度及原因）、weight_sum（进入合计的权重之和）。
4. 代码里不得出现题号分支。维度编码可以引用现有常量，不要另起一套字符串。

二、选档：backend/app/graph/review_graph.py
1. 给 build_review_graph 新增可注入参数 chat=None。

   chat(messages, temperature=0.2, *, transport=None) -> str
   **本模块不得导入 backend/app/llm/client.py**，源码里不得出现 httpx / requests / urllib / aiohttp 字样。
   模型只能用注入进来的那一个。
2. score 节点分两路：
   - 注入了 chat：逐维选档。每维的输入是该维检索到的父块（最多 4 段，取自 state 里的 retrievals）；

3. 选档的模型输出是 JSON，**只采纳三个字段**：band、chunk_id、quote。

   - quote 必须是该维某段父块 content 的**连续子串**（不是分词、不是模糊匹配、不是相似度）；

     **总 chat 调用次数不超过 2**。
   - JSON 里若带了 weight 或 score，**忽略**。
4. 三种"不进入加权"的状态要分清楚，不得混用：

   - 模型给的 quote 对不上父块 → 「引用失败」；
   - JSON 两次都解析失败 → 「失败」。
5. 确定性降档守卫（对应验收"云团写成静止且没有 3 m/s 下沉时，对应维度不得为充分"）：

## 3. 为什么提示词要这么写（给你复核用）

| 约定 | 来源 | 为什么写进提示词 |
|---|---|---|
| 把 P1 测试的断言原文摆出来 | 实测 `test_interrupt.py:173-211` | 这是本版**唯一的一改就炸点**。P5 要往 `score` 节点塞选档逻辑，而 P1 的用例正断言"未注入模型时仍能正常走完"。不把断言原文贴出来，AI 很自然会改成"没模型就报失败"，**绿灯变红灯** |
| 选档必须可注入 | P4 的既有模式 + P1 约束 | 和 P4 的 `retriever` 一样：模块内不出现模型调用，能力从外面注入。这样测试才能离线跑，`graph` 也才能继续"源码里不含 HTTP" |
| 「未注入保持占位」写成硬要求 | 推断（本版特有） | "缺省应当报失败"是很合理的直觉——所以要点明它在本项目**是错的**，并给出代价（打破 P1），否则这个直觉会赢 |
| `weighted_sum` 定为纯函数 | 本版模块边界判断 | 权重读量规数据 → 直觉是"去查库"。但 `scoring` 不在允许目录里含 `importing`，一查库就要重演 P3 的边界冲突。纯函数把这个坑提前填掉 |
| 忽略模型给的 weight/score，且"不报错" | 任务文档 §11 任务 1 | 只说"忽略"容易被实现成"校验并报错"。明确"忽略、不报错"，语义才唯一 |
| 三种状态分清楚 | 需求 §9.3 + 任务文档 §11 | 「证据不足」「引用失败」「失败」是三件不同的事，混用会让后面的报告说不清哪一维为什么没得分 |
| 降档守卫必须"数据驱动" | 需求 §12.2 + 禁止题号分支 | 验收原话是"云团写成静止且没有 3 m/s 下沉时不得为充分"。最省事的写法是 `if "静止" in text and "3 m/s" not in text`——**那就把题面字面量钉进代码了**，直接违反"不按题号写分支"。所以要求走 `mention` 型约束数据 |
| 重试次数写成"恰为 2" | 任务文档 §11 任务 3 | 和 P4 的"恰为 2 轮"同理：只说"重试一次"不够，要钉死上界与总数 |
| graph 侧断言写进 `tests/scoring` | 任务文档 §11 允许目录 | 本版可改的测试目录只有 `scoring`，但要改 `graph`。不说明，AI 会新建 `tests/graph/` 而越界 |
| 完成定义含"用例不少于 74" | P4 补丁的经验 | 防止靠删测试变绿 |
| 明确 `test_interrupt.py` 未被修改 | 本版边界 | 与"不许改测试"同理，单独列一条便于逐项核对 |
