### 1.4 决定性事实：测试不读 `.env`

`importing/db.py:28-32` 的 `_load_env_file()` 只在 `get_dsn()` 内部触发，且 `load_dotenv(override=False)`。而 `test_review_flow.py` **自己造 sqlite 引擎**、不调 `get_dsn()`。同理 `llm/client.py` 的 `_read_env()` 只读 `os.environ`，不读 `.env` 文件。

**所以：跑 pytest 时 `.env` 里的 DeepSeek 密钥根本不会生效**（除非有人 export 了同名环境变量）。这是本版"分支设计"能成立的基础，也让 134 个测试可以继续全绿。

### 1.5 架构死结：`chat` 与 `embed` 共用 `LLM_BASE_URL`

`llm/client.py` 里两个函数都读同一个 `LLM_BASE_URL`：

```python
def chat(...):  base_url = _read_env("LLM_BASE_URL").rstrip("/"); ... f"{base_url}/chat/completions"
def embed(...): base_url = _read_env("LLM_BASE_URL").rstrip("/"); ... f"{base_url}/embeddings"
```

而 **DeepSeek 没有 `/embeddings` 端点**。解法已定案（2026-10-18 勘误）：

| 环节 | 服务商 | 模型 | 说明 |
|---|---|---|---|
| 对话选档 | DeepSeek | `deepseek-flash` | 500 万 token 新人额度；`parse_scoring_json` 只容两次失败，**对话质量优先**，不用硅基流动的 8B/9B 免费小模型（JSON 崩坏率高，会换来一堆「失败」维度） |
| 嵌入 | 硅基流动 | `BAAI/bge-m3` | **完全免费**、1024 维、100+ 语言、Apache 2.0 可商用 |
| 重排 | 硅基流动 | `BAAI/bge-reranker-v2-m3` | **完全免费**、Cohere 兼容接口 |

**落地的三个配置键**（`.env` 与 `.env.example` 已补）：

```text
EMBEDDING_BASE_URL=https://api.siliconflow.cn/v1   # 缺省回落 LLM_BASE_URL
EMBEDDING_API_KEY=                                 # 硅基流动的 key，与 DeepSeek 的不是同一个
RERANK_API_KEY=                                    # 同上
```

**为什么仍保留"无向量分支"兜底**：嵌入是主路径，但 `paper_parent` 当前 0 行、Chroma 空集合，且硅基流动免费档限 RPM。若嵌入因网络/限流/未配 key 而不可用，检索退化为"按 `contest_id + section_type` 从 MySQL 取父块"，**主链不断**。这是兜底，不是主路径——执行方不得因为兜底存在就跳过嵌入接入。

  * 端点：`POST {RERANK_BASE_URL}/rerank`，body `{"model": RERANK_MODEL, "query": "...", "documents": ["正文1", ...]}`；
  * 响应：`{"results": [{"index": 0, "relevance_score": 0.98}, ...]}`，按 relevance_score 降序；
  * 鉴权：`Authorization: Bearer {RERANK_API_KEY}`（**新键，与 LLM_API_KEY 不是同一个**）。
- 在 `rerank.py` 新增 `SiliconFlowRerankClient`，实现既有 `RerankClient.rerank(query, candidates) -> list[str]` 协议：
  * **入参是 parent_id 列表，而硅基流动要文档文本**——所以客户端构造时要能拿到 `parent_id → content` 的映射
    （`ParentBlock` 有 `content` 字段，数据是有的，只是现在没传进来；由装配层把映射注入客户端）；
  * 调完把返回的 `index` 按传入顺序换回 `parent_id`；
  * 任何一条没被返回、或 index 越界，一律抛错——**不让 `validate_rerank_order` 静默通过**。
- HTTP 只能经 `client.py`：在 client.py 加一个 `rerank(query, documents, *, transport=None)` 出口
  （读 RERANK_BASE_URL / RERANK_API_KEY / RERANK_MODEL，返回排序后的 index 列表），
  rerank.py 的适配层只调它、自己不得 import httpx。
- `build_rerank_client("http")` 改为返回 `SiliconFlowRerankClient`；`FakeRerankClient` 原样保留。
- **未配置 `RERANK_API_KEY` / `RERANK_BASE_URL` / `RERANK_MODEL` 时仍抛 NotImplementedError**，
  不许静默降级成假客户端——那会让"重排没生效"看起来像"生效了"。
- 先写测试：用 MockTransport 返回打乱顺序的 results → 断言只改顺序、集合相等、按分数降序；
  index 越界或漏条目 → 断言抛错；未配置 → 断言仍抛 NotImplementedError。

## 3. 为什么提示词要这么写（给你复核用）

| 约定 | 来源 | 为什么写进提示词 |
|---|---|---|
| **分支而非默认走模型** | 实测 `load_dotenv` 只在 `get_dsn()` 内触发、`client.py` 只读 `os.environ`、测试自己造 sqlite 引擎 | 这是本版能成立的地基。默认走模型会让测试打真实 API（花钱+不稳定）、缺密钥时接口 500 |
| **conftest 显式清空 LLM_* 键** | 测试无 `conftest.py`、`test_client.py` 自己用 monkeypatch 设值 | 万一开发者本机 export 了密钥，测试会静默走模型路径。加一道夹具把这条意外堵死 |
| **未注入行为逐字保留** | `test_interrupt.py:173-175` 断言 `status=="完成"`、`score_node_calls==1`，该文件多版本冻结 | 注入逻辑只能在"注入了什么"上做文章，不能动"没注入时怎样" |
| **注入放在装配层、不在 graph 模块** | `review_graph.py:12` 注释明令"本模块不导入模型客户端、不含 HTTP 字样" | 图模块的可注入契约是项目最重要的架构约定，破了它 `test_review_flow.py` 的 `FORBIDDEN_TOKENS` 扫描会直接红 |
| **真实重排仍走 client.py** | `rerank.py:72-79` 的 `NotImplementedError` 注释已解释原因 | 唯一 HTTP 出口的约束；且未配置时必须显式失败而不是静默降级——后者会让"没生效"伪装成"生效了" |
| **嵌入解耦 + 选品定案** | DeepSeek 无 `/embeddings`；硅基流动免费对话模型最大仅 9B | 对话要质量（`deepseek-flash` 扛 JSON 输出）、嵌入重排要免费（bge-m3 / bge-reranker-v2-m3 完全免费），三家各取所长；一个环境问题不会同时卡住两件事 |
| **重排写适配层而非改协议** | 硅基流动是 Cohere 风格 `/rerank`，项目协议是 `(query, ids) -> ids` | 保持 `RerankClient` 协议与 13 个既有测试不动，形状差异在适配层内部消化；id→文本映射由装配层注入 |
| **无向量分支只作兜底** | `paper_parent` 0 行、硅基流动免费档限 RPM | 嵌入仍是主路径；兜底仅用于"嵌入未配置或调用失败"，防止主链断掉。**不得因兜底存在跳过嵌入接入** |
| **评测默认仍走回退、显式才跑模型** | 12 篇 × 5 维 ≈ 60～120 次调用 | 花钱的事不能默认触发；且回退下的三项数字是脚本自检，页面已如实标注 |
| **thinking 模式风险单列 + 失败分级** | `deepseek-flash` 默认开思考；`parse_scoring_json` 只容两次失败 | 这是最可能第一次就撞上的坑。给出三级处置并禁止"降低 prompt 要求糊过去" |
| **同篇对比表作为 core deliverable** | 用户要的是"跑通"，不是"改完" | 没有对比表就无法证明模型路径真的生效了——档位可能只是看起来变了 |
| **前端四道门禁也要复跑** | `frontend/` 零改动是硬约束 | 防止后端改动通过共享状态/接口响应形状间接把前端搞坏 |
