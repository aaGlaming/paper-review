## 1. 现状体检（实测，不是推测）

### 1.1 `chat()` 确实没有 `tools`

- `backend/app/llm/client.py` 第 109～123 行：payload 只有 `{"model", "messages", "temperature"}`，没有 `tools` 也没有 `tool_choice`。
- 第 19 行 `__all__ = ["chat", "embed", "rerank", ...]`，没有带工具的函数。
- 全仓 `grep -rn "tools\|tool_call\|function_call" backend/app` **命中 0**。
- 结论：工具调用这条路现在是通的**零**，不是"做了一半"。

### 1.2 端点到底支不支持 `tools`：未知，必须先测

- 现有代码只能证明「我们没发过」，不能证明「服务端不支持」。DeepSeek 兼容端点对 function calling 的支持取决于具体模型与部署，猜没有意义。
- 探针成本：一条极短请求（约 100 token 量级），几分钱。
- 探针风险：如果直接把 `tools` 塞进现有 `chat()`，一旦服务端 400，整条选档链路会一起挂——所以必须是**独立函数**，不许改 `chat()`。

### 1.3 测试为什么不能承担探针

- `backend/tests/conftest.py` 的 autouse fixture 会把 9 个模型环境键设成空串 → 测试进程里没有 base_url、没有 key，物理上打不出去。
- 既有契约测试全部用 `httpx.MockTransport` 注入（`test_client.py` 的 `_set_env` / `_transport` / `_ok`），断言的是「我们发了什么、怎么解析」，不是「服务端回了什么」。
- 结论：探针只能是**一次性手工命令**，结论写进 `progress.md`；仓库里只留离线的契约测试。

### 1.4 现有的重试语义（新函数必须沿用，不许另写一套）

- `_post_json()`：`_MAX_ATTEMPTS = 2`；`httpx.TransportError` 重试 1 次；`httpx.HTTPStatusError` **立刻抛**，不重试；`response.json()` 非法抛 `LLMResponseError`。
- 超时 `_TIMEOUT_SECONDS = 30.0`。
- 这两条行为被 `test_client.py` 断言着，新函数沿用即可，不要复制粘贴出第二份实现。

返回（两条路线必须同形状，让上层不感知 A/B）：

- payload 增加 "tools"（OpenAI 兼容形状）与 "tool_choice"；

B 路线要点：
- payload 不加 tools；在 system 消息末尾追加一段工具清单与输出约定

- 抽不出 JSON 抛 LLMResponseError，不返回空 tool_calls 冒充"模型决定不调工具"。

- 网络与 HTTP 错误一律复用 _post_json 的语义（TransportError 重试 1 次、HTTPStatusError 立刻抛），

## 3. 为什么提示词要这么写（给你复核用）

| 约定 | 来源 | 为什么写进提示词 |
|---|---|---|
| **先探针、后实现** | §1.2：现有代码只能证明"我们没发过 `tools`" | 不先测就写 A 路线，一旦服务端 400，`chat()` 旁边会多一段永远走不到的死代码；写 B 路线同理。两条都写一半是本阶段最容易犯的错 |
| **探针明令不进 pytest** | `conftest.py` 清空 9 个模型键 + 首期"测试不许打真实 API"纪律 | 探针一旦进测试，要么改 conftest（破隔离），要么让 CI 变成要联网，两种都比手工跑一次贵 |
| **A/B 共用返回形状** | P13 的循环只认识一种 `tool_calls` 结构 | 两条路线各返回一套结构，P13 就得写两个分支，等于把"路线未定"这个不确定性带进控制流 |
| **`arguments` 解析失败就抛** | `parse_scoring_json` 的既有做法：宁可失败也不返回半截 | 返回半截结构，上层会当成"模型调了工具但参数为空"，然后静默走错分支，比报错难查十倍 |
| **`chat()` 一行不改** | 159 个测试锁着它的签名与 payload 断言 | 改 `chat()` 等于重写契约测试；新能力用新函数旁挂，出问题能整段回滚 |
| **门禁四道全跑（含前端）** | 首期惯例：`v1.9.3` 也是四道全跑 | 本版前端明明零改动，仍然跑一次 `npm run build`——防的是"以为没改"和"别人改过没提交" |
| **探针只打四项** | 密钥纪律 + 计费信息不进仓库 | 打印完整响应会带 usage、内部字段、有时带 request id，落盘即污染 |
