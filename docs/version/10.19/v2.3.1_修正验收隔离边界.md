### 另外纠正一个技术错误

v2.3.0 里我建议「monkeypatch `trace.session_scope`」——**这条是错的，照做会失败**。

`backend/app/agent/trace.py` 第 100、118 行是**函数内局部 import**：

```python
if session is not None:
    return _insert(session)
from ..importing.db import session_scope    # ← 函数内 import
with session_scope() as db_session:
```

局部 import 意味着 `trace` 模块的命名空间里根本没有 `session_scope` 这个名字，`monkeypatch.setattr(trace_mod, "session_scope", ...)` 会抛 `AttributeError`。**必须 monkeypatch 源头模块 `backend.app.importing.db.session_scope`**。

```

    import pytest
    from contextlib import contextmanager

    @pytest.fixture(autouse=True)
    def isolate_agent_trace(monkeypatch, request):
        """把 agent 轨迹写入重定向到内存 sqlite，避免污染真实 MySQL。

        只对 backend/tests/agent 下的用例生效：session_scope 是全局单例，
        对全部测试替换会打断那些真正需要 MySQL 的用例
        （实测会把 tests/api/test_review_indexing.py 的 2 条打红）。

        trace.py 内部是「函数内 from ..importing.db import session_scope」，
        局部 import 不会在 trace 模块命名空间留下名字，
        所以必须 patch 源头模块 importing.db，而不是 trace。
        """
        path = str(request.node.fspath).replace("\\", "/")
        if "/tests/agent/" not in path:
            yield
            return

        from sqlalchemy import create_engine
        from sqlalchemy.orm import sessionmaker
        from sqlalchemy.pool import StaticPool
        from backend.app.agent.trace import AgentTraceBase
        import backend.app.importing.db as db_mod

        engine = create_engine(
            "sqlite://",
            connect_args={"check_same_thread": False},
            poolclass=StaticPool,      # 内存库必须共用同一连接，否则每会话一个空库
        )
        AgentTraceBase.metadata.create_all(engine)
        SessionLocal = sessionmaker(bind=engine)

        @contextmanager
        def _scope():
            s = SessionLocal()
            try:
                yield s
                s.commit()
            except Exception:
                s.rollback()
                raise
            finally:
                s.close()

        monkeypatch.setattr(db_mod, "session_scope", _scope)
        yield
```

## 3. 为什么这么改（给你复核用）

**「可以改什么」必须列出白名单，而不是只写黑名单。** v2.3.0 只写了「冻结两个文件」，执行方需要自己推断「那其他文件呢」；遇到不确定就保守停手。这不是它笨，是我把判断题留给了它。v2.3.1 直接给正反两列，判断题变判断题。

**为什么必须用 `StaticPool`。** `sqlite://`（内存库）每个连接是独立数据库。如果 `sessionmaker` 每次拿新连接，`create_all` 建好的表在下一个会话里就看不见了，报 `no such table`。`StaticPool` + `check_same_thread=False` 强制所有会话共用一个连接，这是内存 sqlite 做测试库的标准写法。不写这条，执行方大概率会踩。

**为什么 patch 的位置从 `trace` 改到 `importing.db`。** 这是 v2.3.0 的实质错误。`trace.py` 第 100、118 行用的是函数内 `from ..importing.db import session_scope`，局部 import 不会往 `trace` 模块命名空间塞名字。所以 `monkeypatch.setattr(trace_mod, "session_scope", ...)` 会抛 `AttributeError: module ... has no attribute 'session_scope'`。**必须 patch 源头模块的属性**，这样函数执行时 import 到的就是被替换的那个。

**为什么留了兜底方案还要求「不许当成等价」。** sqlite 对 MySQL 专有类型（`JSON`、某些长度约束）未必全兼容，`create_all` 可能失败。兜底方案（把落库函数换成内存 list）能保证测试不污染库，但**它让落库路径在测试里彻底不执行了**——这是真实覆盖度的损失，`test_trace.py` 的 sqlite 用例只能部分补偿。所以要求写明，不能悄悄降级还报「已修复」。

**为什么必须限定目录，而不是全局替换。** `session_scope` 是全局单例，被整个后端共用。无条件替换后，`tests/api/test_review_indexing.py` 那两条真正要往 MySQL 建 parent 表的用例会被改道去 sqlite，当场红。实测是 `2 failed, 229 passed`；加上 `/tests/agent/` 路径判断后回到 `231 passed`，且行数仍是 +0。**「堵住污染」和「打断别的测试」是两件事，前者容易，后者要靠范围判断。**

**为什么 P1 还是只出结论不改代码。** 现在动 `submit_dimension` 的 guard，会牵动首期已验收的评分链路（`review_graph.py:405` 用同一个 guard）。验收阶段掺进结构性重构，出了问题分不清是验收发现的还是验收改出来的。先定级、后决策，顺序不能反。

**为什么要求「+43 / +0」的 before-after 写进报告。** 这是本次唯一一个可以量化验证的修复。写清楚「修复前跑一次涨 43 行，修复后涨 0 行」，比写十句「已修复」有说服力。
