### 先说一个硬约束：不能替换图

冻结文件 `backend/tests/graph/test_interrupt.py` 断言：

```text
final["score_node_calls"] == 1
final["status"] == "完成"
graph.get_state(_config(review_id)).next == ()
```

这三条把「把 retrieve/score 换成独立 agent 节点」这条路堵死了——一换必红，而该文件不许改。所以本版的装配方式是：

```text
START → parse → confirm → retrieve → score → END
                                      │
                                      └─ 注入了 agent_runner 时，score 内部跑 create_agent 子图
```

`retrieve` 在 agent 模式下提前返回空 `retrievals`（检索改由工具做，避免同一篇检索两遍）；`score` 做成**分派器**：没有 `agent_runner` 走首期逻辑，有就跑 agent，但 `score_node_calls` 照常 +1。

### 本版范围

| 做 | 不做 |
|---|---|
| `state.py`：`ReviewAgentState` | 不做无进展检测（`v2.1.1`） |
| `middleware.py`：预算计数 + 轨迹写入 | 不做 `critique`（P14） |
| `prompt.py`：选档 system prompt | 不做前端轨迹面板（`v2.1.1`） |
| `graph.py` + `runner.py`：装配与结果收口 | 不改 `tools.py` / `retriever.py` / `chat_model.py` / `client.py` |
| `review_graph.py`：score 分派器 + retrieve 短路 | 不改冻结测试与 conftest |
| `routes.py`：注入 `agent_runner` 与 `recursion_limit` | 不改 API 响应形状 |

### 1.2 装配所需的真实 API（实测签名，别照老教程写）

```text
create_agent(model, tools, system_prompt=..., middleware=[...], state_schema=..., name=...)
  -> CompiledStateGraph

AgentMiddleware 钩子：
  before_agent(self, state, runtime) -> dict | None
  before_model(self, state, runtime) -> dict | None
  after_model(self, state, runtime) -> dict | None
  wrap_tool_call(self, request: ToolCallRequest, handler) -> ToolMessage | Command
  after_agent(self, state, runtime) -> dict | None
```

注意两件事：

1. **没有 `max_iterations`**——那是旧 `AgentExecutor` 的参数。预算只能靠 `recursion_limit`、middleware 计数、工具内 deadline 三处。
2. **`wrap_tool_call` 的签名是 `(request, handler)`**，不是 `(state, ...)`；`request.tool_call` 里有 `name` / `args` / `id`。

二、middleware.py

class BudgetExceeded(RuntimeError):
    # 带 reason 字段，取值见四闸：model_calls / tool_calls / dimension_steps / wall_clock

class BudgetMiddleware(AgentMiddleware):
    def __init__(self, *, max_model_calls=8, max_tool_calls=24,
                 max_steps_per_dimension=3, wall_clock_seconds=150): ...
    before_model: 模型调用 +1；超限抛 BudgetExceeded("model_calls")；墙钟超时抛 BudgetExceeded("wall_clock")
    wrap_tool_call:
        1) 工具调用 +1，超限抛 BudgetExceeded("tool_calls")
        2) 按 request.tool_call["args"].get("dimension_code") 记单维步数，超限抛 BudgetExceeded("dimension_steps")
        3) 记开始时间，调 handler(request)
        4) finally 里把耗时交给 TraceMiddleware 用（用 request 里挂不住的，直接在本类里记到 state 也行——
           由你定，但**轨迹里必须有 elapsed_ms**）
    after_agent: 把 terminated_by 写回 state（预算未触发则留空，由 runner 判定）

class TraceMiddleware(AgentMiddleware):
    after_model: 读最后一条 AIMessage：
        - 有 tool_calls → 写一条轨迹 action=<第一个工具名>，result_note="决定调用 N 个工具"
        - 无 tool_calls → 写一条 action="final"，result_note=content 前 80 字
        **只写 node="model"**；论文原文与原句一律不许进 result_note。
    wrap_tool_call: 调 handler 后按 ToolMessage 内容写 node="tools" 的轨迹，
        ok = 是否含 "error_code" 不为 null；result_note 存 "命中 N 条" 或 "错误码: xxx"。
    失败不许吞：写轨迹后原样 raise，让上层决定。

## 3. 为什么提示词要这么写（给你复核用）

| 约定 | 来源 | 为什么写进提示词 |
|---|---|---|
| **agent 挂 `score` 内部** | 冻结测试断言 `score_node_calls == 1`、`next == ()` | 把 retrieve/score 换成 agent 节点是最"漂亮"的接法，但会立刻让冻结文件变红；而它不许改。挂在 score 里是唯一既守住测试又能跑 agent 的接法 |
| **`retrieve` 在 agent 模式下短路** | 工具里的 `search_evidence` 已经做了三路召回 | 不短路就会同一篇论文检索两遍，embed/rerank 成本翻倍，P25 的 3 分钟本就紧张 |
| **`recursion_limit` + middleware 双计数** | `create_agent` 没有 `max_iterations` | 只靠 `recursion_limit` 拦不住"同一维被反复检索"；只靠 middleware 又拦不住 LangGraph 自己的递归。两个一起才闭合 |
| **缺维补「证据不足」** | 首期纪律：证据不足不换算分数 | 让模型重跑会烧预算且不可控；缺维按证据不足处理，既不虚高也不虚低，还能在 `reason` 里说清楚 |
| **子图不传 checkpointer** | LangGraph 子图继承父图检查点 | 单独传会导致 resume 时按 `thread_id` 找不到父图快照，`GET /reviews/{id}` 直接 404 |
| **prompt 不许写引导语** | v1.9.2 立的纪律：不许改 prompt 凑分数 | agent 一旦开始"为了让老师满意"挑高分，评测基线 13/60 就没有意义了 |
| **真实调用必须记四项** | P13 的验收判据是"模型真的在决策" | 只看测试通过不够——单测里模型是脚本化的，必须有一次真调用证明它自己选了工具 |
