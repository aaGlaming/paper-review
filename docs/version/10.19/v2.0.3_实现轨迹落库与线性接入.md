> 生成时间：2026-10-19
> 用途：直接整段复制。本版把 `agent_step` 表建起来、把六个工具在真实请求里跑一次（旁路）、并开一个只读接口把轨迹读回来。**评分路径与本版无关，分数一个都不许变。**
> 所属阶段：**P12 Agent 适配层与工具层 · 子任务 3/4** · 本文档版本：v2.0.3

### 本版对「接入」的定义（先说清，免得验收时扯皮）

| 说法 | 本版做到什么 | 谁来做 |
|---|---|---|
| 工具能被调用 | ✅ 在真实请求里被调用（旁路），有轨迹为证 | 本版 |
| 轨迹能回放 | ✅ 落 `agent_step`，有只读接口按序读回 | 本版 |
| 工具有决策权 | ❌ 不参与——调用顺序写死，模型不选工具 | P13 |
| 工具影响分数 | ❌ 不影响——旁路结果只记轨迹，不写 `dimension_results` | P13 |

**旁路的理由**：P12 是地基阶段，本版一旦让工具影响分数，就等于在没装预算、没装 critique 的情况下换了评分实现——出了问题没法判断是工具错还是模型错。旁路只花一次检索的钱，能证明链路通，且分数可逐字比对。

## 1. 现状体检（实测，不是推测）

### 1.1 手上已有的积木

| 积木 | 位置 | 关键事实 |
|---|---|---|
| `ToolContext` | `backend/app/agent/tools.py` | dataclass，字段：`review_id` / `contest_id` / `rubric_id` / `dimensions` / `constraints` / `retrieve_fn` / `read_parent_fn` / `findings_fn` / `results` / `retrieved` / `submitted` |
| `call_tool(ctx, name, args)` | 同上 | 唯一入口，返回 `{"ok","data","error_code","message"}`；错误码封闭五个 |
| `build_tools(ctx)` | 同上 | 6 个 `StructuredTool`，`args_schema` 用 pydantic |
| `PaperRetriever` | `backend/app/agent/retriever.py` | `retrieve_fn` 注入；空结果 `[]` |
| 装配层 | `backend/app/api/routes.py` 的 `_prepare_review_index` | 已能造出 `retriever`、`parent_contents`、五维 `dimensions`、`constraints` |
| 独立 Base 先例 | `backend/app/importing/models.py` / `backend/app/report/models.py` | 各自 Base + 幂等建表函数，`agent_step` 照抄这套，不要塞进既有 Base |

### 1.2 现在的缺口

- 没有任何持久化：跑完一次评审，谁调了哪个工具、命中几段、耗时多少，全靠日志文件猜。
- `agent_step` 表不存在；`writeDiagram` 那套先例（独立 Base + 幂等建表）在 `report/models.py` 里有现成写法。
- 工具只在测试里被调用过，**没有任何真实请求路径**；P13 装配时如果发现工具在生产数据上跑不通，会连同预算、循环一起返工。

### 1.3 三个必须避开的坑

1. **不许改分数**：旁路结果不写 `dimension_results`；验收时同一篇论文的 `score` 必须与 v2.0.2 逐字相同。
2. **不许阻塞主流程**：探针放 `try/except` 里，异常只落一条 `ok=False` 的轨迹；主流程照常返回。
3. **不许重复检索整篇**：旁路只对**第一个维度**调一次 `search_evidence`。五个维度全调等于把检索成本翻倍，而 P25 的 3 分钟时限本就紧张。

## 3. 为什么提示词要这么写（给你复核用）

| 约定 | 来源 | 为什么写进提示词 |
|---|---|---|
| **旁路、不改分数** | P12 是地基阶段；P13 才装配决策 | 现在换评分实现，等于在没预算、没 critique 的情况下动主链，出问题分不清是工具错还是模型错。旁路能证明链路通，还能逐字比对分数 |
| **只跑一次 `search_evidence`** | P25 的 3 分钟时限 + 检索要花 embed/rerank | 五维全跑等于把检索成本翻倍；先证明"能通"，覆盖度留给 P13 |
| **探针异常必须吞成轨迹** | 首期纪律：未注入时保持占位、不报失败 | 旁路是观察者，观察者不许把主流程弄挂；吞异常但落 `ok=False`，既不掩盖也不阻塞 |
| **独立 `AgentTraceBase`** | `ParentBase` / `ReportBase` 的既有先例 | 塞进 ReportBase 会让报告模块的建表函数背上 agent 的字段，将来拆都拆不开 |
| **`args_digest` 而非原文** | 首期密钥纪律 + 论文版权约束 | 参数里可能有原句与论文片段；摘要足够定位，原文落库等于把版权问题引进数据库 |
| **无记录返回 200 + 空数组** | 首期 Ruling：不把"没有数据"伪装成"不存在" | 404 会让前端把"这次没跑过 agent"误读成"评审不存在"，P13 的面板就会报错 |
| **分数不变作为门禁** | 本版的核心风险 | 只跑测试不看真实分数，旁路偷改分数的 bug 会一路带到 P13 |
| **`node` 只写 `tools`** | 本版没有 model 决策 | 写 `model` 会让人以为有模型决策；语义要诚实，P13 再补 `model` / `critique` |
