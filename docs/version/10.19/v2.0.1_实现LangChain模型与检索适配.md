Playwright 这条红灯有两个可疑点，**先查这两个，别急着重跑**：

- 失败形态是「确认动作一直处理中」，而 `TestClient` 冒烟调创建/确认路由是 200、耗时 0.021 s。同一个后端、同一套代码，一个 21 毫秒、一个超 5 秒，差别不在业务逻辑，**在进程环境**。

**所以 P0 的判定标准是**：清掉模型键后**重启后端**再跑 Playwright；若 43 passed 则记为环境问题并留证；若仍红，按真实缺陷查，**不许改断言、不许放宽容差、不许跳过用例**。

三、DeepSeekChatModel（backend/app/agent/chat_model.py）
继承 langchain_core.language_models.chat_models.BaseChatModel。

构造参数：
  model_name: str = ""                # 仅展示用，不参与请求（真模型名由 client 读环境变量）
  temperature: float = 0.2
  chat_fn: Callable | None = None     # None 时用 backend.app.llm.client.chat_with_tools
  bound_tools: list[dict] = []        # 内部使用，bind_tools 后产生

必须实现：
  _llm_type(self) -> str              # "deepseek-compatible"
  _generate(self, messages, stop=None, run_manager=None, **kwargs) -> ChatResult
  bind_tools(self, tools, **kwargs)   # 返回副本，不改 self

_generate 的消息转换（漏一个字段，第二轮就会崩）：
  SystemMessage → {"role":"system","content":...}
  HumanMessage  → {"role":"user","content":...}
  AIMessage     → {"role":"assistant","content":...}
                  若带 tool_calls，追加 "tool_calls":[{"id","type":"function",
                  "function":{"name":..., "arguments": json.dumps(args, ensure_ascii=False)}}]
  ToolMessage   → {"role":"tool","content":..., "tool_call_id":...}   ← tool_call_id 不许丢

_generate 的返回：
  调 chat_fn(messages_dicts, tools=bound_tools, temperature=self.temperature)；
  把 {"content","tool_calls":[{"id","name","arguments"}],"finish_reason"} 转成
  AIMessage(content=content, tool_calls=[{"name":name,"args":arguments,"id":id}])，
  finish_reason 放进 message.response_metadata；
  返回 ChatResult(generations=[ChatGeneration(message=msg)])。
  chat_fn 抛的异常**原样向上抛**，不许吞成空 AIMessage。

bind_tools：
  接受 BaseTool / StructuredTool / Callable / dict，统一转 OpenAI 兼容形状：
  {"type":"function","function":{"name":..., "description":..., "parameters": <JSON Schema>}}
  parameters 取 tool.args_schema.model_json_schema()；没有 args_schema 用 {"type":"object","properties":{}}；
  **返回 self.model_copy(update={"bound_tools": ...})，原实例不变**。

| **不用 `VectorStoreRetriever`** | `three_route.py`：三路召回 + 合并去重 + 一次重排 + 4 段截断 | Chroma 原生 retriever 只表达一次 top-k，用它会丢掉三路与父子块回填 |
| **`ToolMessage` 的 `tool_call_id` 单列一条** | 多轮工具调用是 agent 的核心形态 | 丢了它，第二轮模型无法把工具结果对回调用，会重新调一遍同样的工具，预算瞬间烧光 |
| **`bind_tools` 返回副本** | LangChain 契约：实例可能被多处复用 | 原地改 `self.bound_tools`，同一实例被两个 agent 复用时工具会串，且极难复现 |
| **空结果返回 `[]`** | 首期纪律：证据不足是结论，不是异常 | 抛异常会让 agent 把「没检索到」当故障，反复重试到预算耗尽 |
| **源码扫描禁 `httpx`** | 唯一 HTTP 出口靠自觉守不住 | 10 行测试比 code review 里吵一百次管用 |
