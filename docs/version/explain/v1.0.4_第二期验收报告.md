## 二、本次修复的两个真实缺陷

这两个缺陷在 231 条测试全绿的情况下长期存在，只有把真实论文灌进系统才暴露。

### 缺陷一：跨论文引用污染（严重）

**现象**：a163 论文的五维引用，内容全部来自 a016（另一篇论文）。

**根因**：向量检索的过滤条件只有 `contest_id` / `rubric_id` / `section_type` / `doc_type`，**没有 `review_id`**。同一赛题下多篇论文共用一个 Chroma collection，于是 B 论文会召回 A 论文的父块。

**为什么没被拦住**：`quote_is_substring` 校验的是「是否在该维检索到的父块里」，而那些父块本身就是别的论文的——校验通过了，引用却指向了别人的论文。**这条铁律被绕过，而且绕得很隐蔽。**

**修复**（`retrieve/parent_child.py`、`retrieve/three_route.py`）：

| 位置 | 改动 |
|---|---|
| `ChildChunk` | 新增 `review_id` 字段 |
| `child_metadata` | 元数据写入 `review_id`（第九个键） |
| `build_children` | 新增 `review_id` 入参，缺省取父块的 |
| `_where` | 新增 `review_id` 过滤子句 |
| `search_children_then_parents` | 新增 `review_id` 形参 |
| `default_search_round` | 补齐 `review_id` 并下传（原先完全没接） |
| `retrieve_dimension` | `round_request` 补 `review_id`（原先只在 fallback 分支传） |

**修复前后对比**：

| | 修复前 | 修复后 |
|---|---|---|
| 引用命中本篇原句 | 24 / 50 | **48 / 50** |
| 引用指向他篇 | **26** | **0** |
| 证据不足 | 0 / 50 | 2 / 50（合理：c234 无检验章节、a242 表述维无据） |

剩余 2 处空引用对应 2 个「证据不足」维，是正确行为。

### 缺陷二：档位枚举缺失导致补交全废

**现象**：agent 检索到 14 段证据却不提交，轨迹以 `no_progress` 收尾，五维全「证据不足」。

**根因**：`_force_submit` 用的临时工具 schema 是空壳 `{"items": {"type": "array"}}`，**`band` 没有任何约束**。模型于是自创档位 `high` / `medium`，被 `param_invalid` 逐条挡下，补交 0 条。探针实测：5 条提交的 quote 全是论文原句、校验全过，**唯一失败点就是 band 取值**。

**修复**：

- `tools._SubmitArgs.band` 由 `str + description` 改为 `Literal["充分","基本","不足","证据不足"]`，在工具 schema 层生成 enum（description 只是提示，挡不住自创档位）；
- `_force_submit` 的临时工具补齐完整 schema，并在提示词里显式列出四档。

**修复前后对比**：

| | 修复前 | 修复后 |
|---|---|---|
| 五维档位 | 全部「证据不足」 | 基本 35 / 不足 7 / 充分 6 / 证据不足 2 |
| 终止原因 | `no_progress` | `all_submitted` 8 篇 |
| 主动提交次数 | 0 | **45 次** |

**三处值得说明的现象**：

1. **c234 的 `constraint_check` 判「证据不足」是对的**。该论文只有模型假设、建立求解、优缺点、改进、推广，没有检验或结果分析章节。系统没有硬凑。
2. **a242 三维判「充分」，是全库第一批由真实论文产出的充分档**（此前 1955 条里只有 1 条，来自复述题目条件的 `assumption` 维）。
3. **有 7 篇的引用由收尾补交而非模型主动提交**。说明 v2.1.2 加的补交机制在真实场景是必需的，不是兜底摆设。

## 六、未通过项与挂账

### 判据 5（自我修正）在真实链路上零触发

- **现象**：critique 轨迹 0 条，50 维里一次降档都没发生。
- **结构原因**（v2.2.1 已定级为 C）：`apply_mention_guard` 开头即 `if band != BANDS[0]: return`——**只有「充分」才降档**。本次 50 维里「充分」6 条，且都在 guard 允许范围内，因此 critique 无事可做。
- **本版状态**：单元测试 8 条（含 `test_mention_guard_downgrades_sufficient`）覆盖，但真实链路从未走到。**「已实现、未验证」。**
- **挂账**：需在 Phase-3 有足够多「充分」样本后复验，或显式放宽 critique 触发范围（属改产品语义，须先立 Ruling）。报告不把它记作 ✅。
