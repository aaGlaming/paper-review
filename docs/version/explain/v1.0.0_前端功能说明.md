# 前端功能说明

> 这份文档说明 paper-review 前端**各个页面与组件实现了什么功能**，不涉及代码。
> 阅读对象：想快速知道"这个工作台能干什么、每一页管什么、哪里还做不到"的人。
> 版本：v1.0.0 · 日期：2026-10-16 · 位置：`docs/version/explain/`

---

## 1. 这套前端是什么

一个**竞赛论文预审工作台**。用户选一道赛题、填一篇论文，系统按赛题自己的评分规则逐维给出档位与论文原句，跑一遍一致性审查，最后产出按修改顺序排列的修改清单。

整个过程分五步，对应五个页面：

```text
论文解析  →  分项评分  →  一致性审查  →  修改建议  →  评测对照
 ①选稿并      ②逐维给       ③查数字/      ④按"先改      ⑤系统自身
  确认章节树     档位与原句     引用/越界       硬伤→再补     的三项指标
                             /漏条件         证据→最后
                                            改表述"
```

前四步是同一次预审的流水线（一页推一页），第五步是对系统自身的评测，独立于单次评审。

---

## 2. 整体骨架

**顶部导航**：五个页面入口，顺序就是评审流程的顺序。当前所在页用下划线标出。

**共享状态（跨页记忆）**：从论文解析页确认之后，赛题、评审单号、章节树、完整报告这四项会被记住，后面三页直接接着用。所以刷新页面不丢、从解析页点到评分页也有数据。**如果直接打开某一页而没有走过解析页，那一页显示空态并指回解析页**——这是有意设计的，不是故障。

## 3. 五个页面

### 3.1 论文解析页 `/parse`

**这一页管"把论文读进来并切好，等人确认"**。

| 区域 | 功能 |
|---|---|
| 赛题下拉 | 只列已发布的赛题。**没选题之前提交按钮是禁用的**——不绑赛题就没有量规，后面一维都评不了 |
| 演示样例 | 三篇内置演示稿，一键填入。点一篇 → 「解析这篇演示」 |
| 粘贴正文 | 也可以把自己论文的 Markdown 正文粘进去，用 `#` 标题分段 |
| 两条路互斥 | 「用演示样例」和「粘贴正文」是两条独立的路，一次只能走一条；两条都填或都空时按钮禁用并说明原因 |
| 章节树 | 解析结果按标题层级列成树，点击一条看它的正文。**每条的类型可以改**（假设 / 模型 / 求解 / 结果 / 检验 / 参考文献 / 未分类），改动只在本地，确认时才提交 |
| 正文 | 原样显示选中章节的正文（含表格、引用等一切内容），不做解析 |
| 预留位 | 正文上方有「主张 / 表格 / 引用」三个空位，标注"由后端解析产出，当前接口未提供"——后端还没有这三样，**页内不放假数据** |
| 确认按钮 | 「确认章节树，进入分项评分」。**确认之后才会按量规逐维取证**；这一页在确认前不显示任何档位 |
| 已确认结果卡 | 确认后显示状态、维度数、量规版本、来源，并给一个去评分页的链接 |

**关键设计：人工确认是一道闸门。** 章节树没确认之前，系统不评分——因为解析可能切错，类型可能判错，让机器在错的章节结构上打分没有意义。

### 3.2 分项评分页 `/scoring`

**这一页管"逐维给出档位、证据原句，以及加权结果"**。

| 区域 | 功能 |
|---|---|
| 信息条 | 赛题、量规版本、状态、来源、模型名 |
| 维度卡 | 每个维度一张卡，显示：维度编号、档位、状态、论文原句、切片编号 |
| 证据不足 | 证据不够的维度用**单独的灰蓝配色**，且**不给原句、不给任何分数**——不把缺项写成低分或高分 |
| 定位原句 | 点「定位原句」，页面滚动到该原句在论文里的真实位置并高亮。原句找不到时明确说"无法定位"，不跳到错的地方 |
| 量规条文 | 每张卡里有一个预留块，说明"维度名、权重与四档说明由后端提供，当前接口未给出"——**不臆造中文维度名** |
| 加权区 | 显示后端算出的加权分；同时列出未进入加权的维度（维度、档位、权重、计入、原因） |
| 加权为 0 时 | 不显示「0 分」，而是显示"加权未产生（本次来源 deterministic，未接模型）"，并把后端原始值照实列出 |
| 存档兜底 | 若只有评审单号而没有完整报告（例如从历史记录进来），能读到存档里的维度档位，但**明确标注"加权与修改清单未随存档返回"**，并提示回解析页重跑 |

**关键设计：分数只来自后端，页面自己不算。** 加权规则、权重都在服务端；前端只负责显示，不重算、不拼装。

### 3.3 一致性审查页 `/consistency`

**这一页管"查出论文里对不上的地方，并能跳过去看原文"**。

| 区域 | 功能 |
|---|---|
| 冲突列表 | 每条显示：类型徽标（数字冲突 / 越界 / 未提到条件 / 缺少情形 / 引用缺失）、对象标题、建议动作 |
| 证据条目 | 每条冲突带若干证据（如"412 s""386 s"），**带字符偏移的证据可以点击** |
| 点击定位 | 点证据后，页面拼出论文全文、按字符偏移定位、滚动过去并高亮那一段；找不到精确位置时**明确标注"按偏移定位，未精确匹配"**，不静默跳错 |
| 没有偏移的条目 | 如"未提到条件"这类本身没有可定位位置的，只显示对象与建议，**不给定位按钮** |
| 空态 | 没有报告时显示"还没有审查结果"并指回解析页 |

**关键设计：一次预审里，同一条冲突的两处取值都能分别定位。** 例如板凳龙样例里"412 s"在摘要、"386 s"在结果表，点哪一条就跳到哪一处。

### 3.4 修改建议页 `/suggestions`

**这一页管"把该改什么按顺序列出来，每条都能指回它是从哪来的"**。

| 区域 | 功能 |
|---|---|
| 三段分组 | 固定三段、固定顺序：**题目约束与数字冲突（先改硬伤）→ 证据不足（再补证据）→ 表述（最后改表述）**。顺序由后端定，**页面不重排** |
| 建议条目 | 每条显示：类型徽标、对象标题、建议动作（后端已写好的具体动作，如"把两处数值改成同一口径"）、当前证据 |
| 上游指针 | 每条都带一个上游编号（如 `finding:数字冲突:盘入终止时刻` 或 `dimension:presentation`），**能指回它是从哪条审查结果或哪个维度档位来的** |
| 空段不消失 | 某一段没有建议时，仍显示该段标题 + "本段无建议"——三段框架是修改顺序的骨架，缺一段会让用户以为漏了数据 |
| 定位 | 审查类建议带偏移的证据同样可以点击定位 |

**关键设计：清单只转写已校验的结果，不另写褒贬。** 页面上没有任何"这条改得不好"之类的主观评价，只有"这里对不上、建议怎么改"。

### 3.5 评测对照页 `/eval`

**这一页管"系统自身在 15 篇自建论文上的三项指标"**。

| 区域 | 功能 |
|---|---|
| 信息条 | 语料片数、可算样本、可算维度、来源、是否无样本 |
| 三项指标卡 | 档位一致率、引用精确匹配率、证据不足命中。每张卡显示：百分比、命中数/总数、**口径原文**（说明这个数怎么算的） |
| 无样本时 | 分母为 0 的指标显示「—（无样本）」，不显示 0 或 NaN |
| 来源说明 | 单独一块显示后端 note 原文；当来源是确定性回退时，额外标注"本次为确定性结构回退，非模型评测结果" |
| 样例列表 | 15 篇样例，标注哪些是演示稿、哪些带人工标准答案（gold），可点进单篇 |
| 单篇占位 | 点进单篇后只显示一段说明：单篇的系统档位与人工档位差异需要后端单篇接口，当前未提供 |

**关键设计：不把百分比当成果放大。** 43.3% 这种数字旁边一定带口径和来源说明——它是脚本自检，不是模型准确率。当前未接模型，页面上能清楚看到这一点。

## 4. 八个组件各管什么

| 组件 | 功能 |
|---|---|
| **导航** | 五个页面入口，当前页高亮；顺序即评审流程顺序 |
| **章节树** | 列出解析出的章节，层级用缩进表达（不用 01/02/03 编号——那是层级不是序列）；每条带类型下拉，点击选中后在右侧看正文 |
| **正文阅读器** | 显示选中章节的正文原文；正文上方是「主张 / 表格 / 引用」三个预留位 |
| **步骤指示器** | 显示预审的六个步骤（赛题对齐 / 按维检索 / 选档 / 规则审查 / 原句校验 / 生成报告），以及当前状态徽标（未开始 / 待确认 / 处理中 / 已完成 / 停在：等待服务返回） |
| **维度卡** | 一个维度一张卡：编号、档位、状态、量规条文预留、论文原句、切片编号、定位按钮；证据不足的卡单独配色 |
| **冲突条** | 一条审查结果：类型徽标、对象、建议动作、可点击定位的证据列表 |
| **建议条** | 一条修改建议：类型徽标、对象、建议动作、当前证据、上游指针 |
| **指标卡** | 一项评测指标：名称、百分比、命中数/总数、口径原文。分母为 0 时显示「—（无样本）」；百分比不放大加粗——它是脚本自检数字，不是成果 |

## 5. 四个"看不见但很重要"的机制

这些是功能亮点，光看页面不易察觉：

### 5.1 诚实的步骤指示

预审过程在界面上分步可见，但**后端是同步接口，一次跑完六步，中间态拿不到**。所以：

- 请求进行中只显示「处理中」这个不确定态，**不逐条点亮**；
- **不用定时器假装进度**——那会让超时的页面显示一个从未发生的"已完成到第 N 步"；
- 失败或超时显示「停在：等待服务返回」，**不补写任何评语**。

### 5.2 原文定位必须是真实位置

点击"定位原句"或某条证据时，定位的依据是**后端校验过的连续子串**（原句必须逐字出现在论文切片里）。页面在章节正文里找它的真实下标，找到就精确高亮，找不到就按字符偏移大致定位并标注"未精确匹配"。**绝不编造位置**——点了跳到错段落，用户会以为引用对不上，直接摧毁"可溯源"这件核心价值。

### 5.3 三个状态分开：空态 / 加载中 / 出错

每个页面都有明确的三态，且**失败必须被捕获并降级显示**（例如 jsdom 环境下没有后端时页面也不会崩）。空态不是一句"暂无数据"，而是说清"缺什么、下一步去哪"并给可点的链接。

### 5.4 数据形状先判再用

后端同一种列表里可能出现两种形状的条目（审查类带字符偏移、维度类带档位无偏移），字段名也不同。页面**先判形状再取字段**——只写一种会在运行时静默取到空值，表现是"点了没反应"而不是报错。

## 6. 当前还做不到的（挂账）

这些是前端**有意不做**或**做不了**的，不是缺陷：

| 缺口 | 现在的表现 | 缺什么 |
|---|---|---|
| 量规条文 | 维度卡里只有预留块和说明 | 后端没有"取量规维度"接口，拿不到维度中文名、权重、四档说明 |
| 加权分数 | 显示"加权未产生" | 未接入真实模型，确定性回退下后端不算加权 |
| 主张 / 表格 / 引用 | 解析页三个预留位 | 后端解析只产章节树，这三样从未实现 |
| 单篇评测 | 只显示缺口说明 | 后端没有单篇评测接口，人工标准答案只在数据文件里 |
| 历史记录里的审查清单 | 存档里拿不到 | 审查结果不落库，只在当次报告的修改清单里 |
| 论文文件上传 | 只能粘正文或用演示稿 | 不支持 PDF / docx |

另外：接入真实模型后，需求里几条依赖模型判断的结果（如"两段圆弧半径 2 倍且相切"判为证据不足、种植策略两个金额标红）才会完整出现。

## 7. 一页速查

| 页面 | 一句话 |
|---|---|
| 论文解析 | 选题填稿 → 切出章节树 → 人工确认（确认前不评分） |
| 分项评分 | 逐维档位 + 论文原句；证据不足单独配色；加权只来自后端 |
| 一致性审查 | 冲突列表；点证据跳到论文里的真实位置 |
| 修改建议 | 先改硬伤 → 再补证据 → 最后改表述；每条带上游指针 |
| 评测对照 | 三项指标 + 口径 + 来源；不把脚本自检数字当成果 |
