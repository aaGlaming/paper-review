### 1.3 本轮修复的两个真实缺陷

两个缺陷在 **231 条测试全绿**的状态下长期存在，只有把真实论文灌进系统才暴露。

#### 缺陷一：跨论文引用污染（严重）

**现象**：a163 论文的五维引用，内容全部来自 a016（另一篇论文）。

**根因**：向量检索的过滤条件只有 `contest_id` / `rubric_id` / `section_type` / `doc_type`，**没有 `review_id`**。同一赛题下多篇论文共用一个 Chroma collection，于是 B 论文召回 A 论文的父块。

**为何校验没拦住**：`quote_is_substring` 校验的是「是否在该维检索到的父块里」，而那些父块本身就是别的论文的——校验通过，引用却指向别人的论文。**「引用可回溯」这条底线被合法绕过。**

**修复范围**（6 个点）：

| 位置 | 改动 |
|---|---|
| `retrieve/parent_child.py` `ChildChunk` | 新增 `review_id` 字段 |
| `retrieve/parent_child.py` `child_metadata` | 元数据写入 `review_id`（第九个键） |
| `retrieve/parent_child.py` `build_children` | 新增 `review_id` 入参，缺省取父块的 |
| `retrieve/parent_child.py` `_where` | 新增 `review_id` 过滤子句 |
| `retrieve/parent_child.py` `search_children_then_parents` | 新增 `review_id` 形参 |
| `retrieve/three_route.py` `default_search_round` | 补齐 `review_id` 并下传（原先完全没接） |
| `retrieve/three_route.py` `retrieve_dimension` | `round_request` 补 `review_id`（原先只在 fallback 分支传） |

**修复效果**：引用命中本篇原句 **24 / 50 → 48 / 50**，指向他篇 **26 → 0**。

#### 缺陷二：档位枚举缺失导致收尾补交全废

**现象**：agent 检索到 14 段证据却不提交，轨迹以 `no_progress` 收尾，五维全「证据不足」。

**根因**：`_force_submit` 用的临时工具 schema 是空壳 `{"items": {"type": "array"}}`，**`band` 没有任何约束**。模型于是自创档位 `high` / `medium`，被 `param_invalid` 逐条挡下，补交 0 条。探针实测：5 条提交的 quote 全是论文原句、子串校验全过，**唯一失败点就是 band 取值**。

**修复**：

| 位置 | 改动 |
|---|---|
| `agent/tools.py` `_SubmitArgs.band` | `str + description` → `Literal["充分","基本","不足","证据不足"]` |
| `agent/runner.py` `_force_submit` | 临时工具补完整 schema（含 `enum`）+ 提示词显式列出四档 |

> `description` 只是提示，挡不住模型自创档位；必须在 schema 层用 `Literal` 生成 `enum`。

**修复效果**：主动提交 **0 → 45 次**，五维从「全部证据不足」变为「基本 35 / 不足 7 / 充分 6」。

## 三、核心流程与完成度

### 3.1 Agent 主路径（Phase-2 改造后）

```text
START → parse → confirm ─┬─(interrupt)→ 等待人工确认
                          │
                          ▼
                       retrieve ──→ score ──→ END
                                        │
                                        └─ 内嵌 LangChain create_agent 子图
                                           ├─ list_dimensions / get_constraints
                                           ├─ search_evidence × N → read_parent × M
                                           ├─ submit_dimension（唯一写结论的口）
                                           └─ force_submit（收尾补交，仍走同一校验）
                                              ↓
                                         critique（只降不提，当前 chat_fn=None）
                                              ↓
                                       report（change_list + 存档，不调模型）
```

**关键设计点**：

| 设计 | 作用 |
|---|---|
| Agent 挂在 `score` **内部**而非独立节点 | 冻结测试断言 `score_node_calls==1`、`next==()`、`status==完成`，独立节点会直接打破这三条 |
| Agent 模式下 `retrieve` 提前返回空 | 否则同一篇论文检索两遍，embed/rerank 成本翻倍 |
| 子图**不单独传 checkpointer** | 否则 resume 时按 `thread_id` 找不到父图快照，`GET /reviews/{id}` 直接 404 |
| `submit_dimension` 是**唯一写口** | 内含子串校验 + `apply_mention_guard`；重复提交 `not_allowed`，不允许覆盖 |
| 预算四闸 + `recursion_limit=45` | `create_agent` 没有 `max_iterations`（那是旧 `AgentExecutor` 的参数），必须自己兜底 |
| 递归与预算**分开记录** | 曾把递归达上限误标成「预算耗尽」，指标名报错会让后续排查全跑偏 |
