## 二、系统现状

### 2.1 业务主路径

```text
登录与权限
  → 选择已发布赛题与量规
  → 粘贴/选择样例/上传 Markdown 或 DOCX
  → 解析章节树并由用户确认
  → 检索父块全文、按量规逐维评审
  → 逐字引用校验与结果归档
  → 一致性问题、修改建议、记录、AI 问询、评测与大屏
```

### 2.2 前端主要页面

登录注册、论文解析、分项评分、一致性审查、修改建议、评测对照、记录总览、AI 问询和数据大屏构成主要工作台。路由组件现按需加载。动态反馈绑定真实响应或用户操作，不生成虚构评审步骤；低样本、空数据和错误状态保留原有语义。

### 2.3 核心产品边界

1. 不输出奖项、名次或获奖概率。
2. 引用必须是父块原文的连续子串；校验失败不进入加权结果。
3. “证据不足”不折算成零分，需显示未获得依据的权重。
4. 章节必须由用户确认后才进入评审。
5. 登录开场不影响已有安全重定向，认证失败与会话恢复不触发。
