## 1. 格式

```text
v<主版本>.<阶段位>.<修订号>_<功能描述>.md
```

示例：`v1.1.0_实现章节确认与检查点.md`

## 2. 三段含义

| 位 | 名称 | 含义与递增时机 |
|---|---|---|
| 第 1 位 | **主版本** | 大版本更新。**仅**在发生前端 UI 变更、新增功能等大幅改动时递增。**预定计划完成之前固定为 `1`，不得变动。** |
| 第 2 位 | **阶段位** | 对齐《执行手册》第 4 节的开发阶段编号，**从 P0 的 `0` 起算**（P0→0、P1→1、P2→2 …… P8→8）。**每次进入下一个阶段（如 P0 → P1）时 +1。** |
| 第 3 位 | **修订号** | **同一阶段内的内容更新**递增。纠错、补项、调整措辞都走这一位。**例外**：声明了子任务序号模式的阶段，这一位改作子任务序号——见第 5 节。 |

判定口诀：**换了阶段 → 涨第二位；还在同一阶段里改 → 只涨第三位；计划没做完 → 第一位永远是 1。**

## 3. 阶段 ↔ 版本号对照

| 阶段（执行手册） | 里程碑版本（任务文档） | 文档版本号 |
|---|---|---|
| P0 地基 | v0.1.0 | **v1.0.0** |
| P1 解析暂停 | v0.2.0 | **v1.1.0** |
| P2 赛题数据 | v0.3.0 | **v1.2.0** |
| P3 父子块检索 | v0.4.0 | **v1.3.0** |
| P4 重排与再检索 | v0.5.0 | **v1.4.0** |
| P5 选档与子串 | v0.6.0 | **v1.5.0** |
| P6 规则审查 | v0.7.0 | **v1.6.0** |
| P7 报告 | v0.8.0 | **v1.7.0** |
| P8 页面 | v0.9.0 | **v1.8.0** |
| 首期验收（需求第十二章） | v1.0.0 | **v1.9.0** |

规律：**文档版本第二数字 = 阶段编号**。P0 对应 0，P8 对应 8，总验收接在 8 之后为 9。

读法提示：第二位填**P 编号本身**，不是"第几个阶段"的序数。`P1` 是第二个阶段，第二位却是 `1` 而非 `2`；`P0` 是第一个阶段，第二位是 `0` 而非 `1`。

> ⚠️ **两套编号不要混用。** 里程碑版本（`v0.1.0`～`v1.0.0`）来自任务文档，指"项目做到哪一步"；文档版本（`v1.x.y`）指"这份提示词是第几阶段的第几稿"。二者并行存在，不互相推导。

## 4. 递增示例

| 情形 | 结果 |
|---|---|
| P0 阶段首份提示词 | `v1.0.0_实现云端模型客户端.md` |
| 该提示词在 P0 内改了错字 | `v1.0.1_实现云端模型客户端.md` |
| 进入 P1，写新提示词 | `v1.1.0_实现章节确认与检查点.md` |
| 该提示词在 P1 内补两条用例 | `v1.1.1_实现章节确认与检查点.md` |
| 进入 P2 | `v1.2.0_补齐赛题数据包与导入校验.md` |
| 计划完成后发生前端 UI 大改 | 主版本升为 `2`，如 `v2.0.0_…`（**计划完成前不得出现**） |

## 5. 修订号的两种用法

第三位只有一种职能，**同一阶段内必须二选一，不能既当修订号又当子任务序号**。

### 5.1 默认：修订号

一份文档在同一阶段内反复打磨，涨第三位：`v1.7.0` → `v1.7.1` → `v1.7.2`。旧稿可以作废（如 `v1.7.1` 被 `v1.7.2` 取代），也可以并行存活，只要版本号不同就不会撞名。

### 5.2 例外：子任务序号

阶段内要**按子任务顺序连发多份文档**（每份驱动一段独立实现）时，第三位改作**子任务序号**，从 `0` 起算。启用条件与约束：

1. **必须在该阶段首份文档里声明**"本阶段第三位为子任务序号"，并列出该阶段的文档清单与各自对应的子任务；不声明就默认走 5.1。
2. **序号一次性排定**，不因中途插入子任务而重排；宁可尾部追加，也不要把已发出文档的号改掉。
3. **已发出文档的更正一律「原地勘误」**：不新建文件、不改文件名、不改版本号；在文档顶部「本次更新」块追加一条，写明**日期 / 改了什么 / 为什么改**。
4. **子任务文档之间不互相改**：后一份只能基于前一份已通过的事实写，不能回过头修订前一份的正文——确有错误时按第 3 条由前一份自己勘误。
5. **两个阶段之间不冲突**：子任务序号只在本阶段内有效，换阶段时第二位 +1、第三位归 `0`。

### 5.3 P8 的实际用法（第一个启用该模式的阶段）

| 第三位 | 子任务 | 文件 |
|---|---|---|
| 0 | 前端工程脚手架与门禁 | `v1.8.0_搭建前端工程与门禁.md` |
| 1 | 论文解析页 | `v1.8.1_实现论文解析页.md` |
| 2 | 分项评分页 | `v1.8.2_…` |
| 3 | 一致性审查页 | `v1.8.3_…` |
| 4 | 修改建议页 | `v1.8.4_…` |
| 5 | 评测对照页 | `v1.8.5_…` |

首份 `v1.8.0` 已含本模式的声明；其中 `typescript` 由 `7.0.2` 改正为 `6.0.3` 是按 5.2 第 3 条做的原地勘误，未新发版本号。

## 6. 格式硬性禁止

- 版本号**不得**写在文件名结尾。
- 不得出现日期或迭代序号（`10.15`、`第3版`）——日期由所在目录 `docs/version/<月.日>` 承担。
- 不出现空格，以及 `/ \ : * ? " < > |`、括号、中文标点等 Windows 非法或易错字符。
- 主体不写「提示词」三字（该目录下全是提示词，写了等于没写）；不写阶段编号（版本号第二位已经承担了这个信号）。

## 7. 常驻文档

规范、说明这类常驻文档**不在阶段序列内**，不使用阶段位；沿用自己的编号线，主版本同样固定为 `1`，内容更新只涨第三位（走 5.1 的默认用法，不适用子任务序号）。本文件即 `v1.0.2_命名规范.md`，后续修订为 `v1.0.3_命名规范.md`。
