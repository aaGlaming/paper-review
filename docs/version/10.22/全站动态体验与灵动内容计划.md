# 全站动态体验与灵动内容计划

> 本文是《前端层次感与登录后开场动画方案》的第二份计划，聚焦登录之后的整套系统。当前只形成计划，不修改产品代码。

## 目标

让系统从“静态页面切换”变成会对数据到达、操作选择、任务等待和结果变化作出清楚回应的工作台。所有动效与动态组件都要表达真实的页面状态或用户操作；不添加虚构的实时数字、伪造的评审进度，也不靠全页漂浮和持续闪动制造热闹。

本计划要求每个主要页面至少有一种可感知的动态反馈，并让全站呈现一致的节奏：进入页面有轻量过渡，数据变化有连续反馈，正在处理时看得见等待，最终状态稳定、可读、可操作。

## 与第一份计划的关系

第一份计划负责校样纸的空间层级、认证页壳层和登录成功后的 SVG 开场。本计划沿用它确立的墨色、纸张、批注线、硬边纸影和 reduced-motion 约束，继续处理业务页面内部的动态内容。

- 登录后的开场继续由 `PostLoginIntro.vue` 承担；本计划不再增加第二段全屏片头。
- `StageTracker.vue` 已显示真实等待秒数；本计划在此基础上整理各任务状态的过渡表现，不点亮未经后端确认的步骤。
- 数据大屏已有 ECharts 图表；本计划统一其数据到达、筛选和重新读取时的动画规则。
- 普通内容卡片仍以纸面、边线和留白为主，不给每张卡片加漂浮、旋转或持续呼吸效果。

## 动态体验原则

### 真实状态驱动

- 进入、选中、展开、加载、成功、失败和数据更新均可触发动效，但状态来源必须是路由、用户操作或真实 API 响应。
- 不把单次同步请求拆成六步动画，不用定时器让步骤逐项变绿，不为没有轮询/推送的接口标注“实时”。
- 数字动画只用于真实值的短暂视觉过渡；最终值和分母必须立刻可读，屏幕阅读器只播报最终结果。
- 低样本、无样本、空数据和失败态不得因为动画被伪装成有效数据；例如低样本指标仍不画折线。

### 动效节奏

| 动作 | 建议时长 | 规则 |
|---|---:|---|
| 按钮按下、标签切换、焦点变化 | 100–160 ms | 只反馈当前操作，不改变布局。 |
| 路由与小面板切换 | 160–240 ms | 轻微透明度与最多 6px 位移；使用 `out-in` 时避免旧新内容叠读。 |
| 列表与分组进入 | 180–280 ms | 小批次、最多错开 4 项；长列表不逐条排队。 |
| 数值变更 | 300–600 ms | 只从上一个真实值过渡到当前值；减少动态效果时直接显示终值。 |
| 进行中的等待指示 | 仅请求期间 | 低幅度、不闪烁；请求结束、超时或失败即停止。 |

不添加动画依赖。优先使用 Vue `Transition` / `TransitionGroup` 与短 CSS 过渡；图表用 ECharts 自带的有界动画。动画令牌集中在 `frontend/src/styles/tokens.css`，不得在每个组件散落不同的时长和缓动曲线。

### 无障碍与稳定性

- `prefers-reduced-motion: reduce` 下移除位移、描线和数字滚动，保留状态变化及可操作性。
- 任何装饰性动态区域都不自动获得焦点；焦点仍由用户操作和既有导航流程管理。
- 加载提示提供 `aria-live="polite"` 或等价状态，不能每帧播报计时数。
- 列表过渡必须用稳定业务 key；不得因动画改变排序、筛选、分页或点击目标。
- 所有动画不能遮挡错误文案、拖慢输入、造成横向滚动或导致点击区域移动。

## 全站动态内容设计

| 页面 | 计划增加的动态内容 | 触发时机与结束状态 | 禁止的表现 |
|---|---|---|---|
| 全站路由 | 主要工作区纸页淡入并轻微归位；导航当前页下划线随路由切换 | 路由成功后；动画结束即静止，浏览器前进/后退行为一致 | 认证开场重复播放；整页缩放、旋转或背景持续移动。 |
| 论文解析 | 已收到章节后，章节树分组出现；真实阶段徽标切换；确认后结果卡与已确认章节短暂描边 | 仅在响应和用户确认事件后；等待中继续显示真实 elapsed；失败保留错误状态 | 按时间推测后端步骤、逐项伪造“检索中/评分中”。 |
| 分项评分 | 维度结果按小组进入；分数与维度计数过渡到 API 返回值；点证据后用一次铅笔线强调定位位置 | 报告实际加载完成或用户切换评审时；最终分值与档位立即准确 | 档位从低到高滚动造成“正在评分”的错觉；隐藏未评分或排除项。 |
| 一致性审查 | 冲突条目有界分组进入；选中冲突时，冲突条目与论文证据同时强调；证据定位可见地滚入阅读区 | 真实冲突列表收到、用户选中一项时；选择变化后旧高亮清除 | 未完成扫描的伪进度；多个条目同时脉冲或反复闪烁。 |
| 修改建议 | 建议分组展开/收起；选中建议时来源、证据和正文定位联动 | 用户操作驱动；分组展开后高度稳定，内容可继续键盘访问 | 虚构“已修改”状态；将建议动画表现成系统已经改写论文。 |
| 记录总览 | 初次读取的行占位；筛选、分页结果替换使用短淡入；详情抽屉像纸页一样进入/退出 | API loading 与响应驱动；失败时切换为明确错误，可重试 | 无限骨架闪烁；刷新时清空旧内容造成大面积跳动。 |
| 评测对照 | source 切换时指标组淡换；有效样本指标的数值从旧值更新到新值；允许的折线短暂描线 | 评测响应、source 切换或样本筛选结果变化时 | 低样本指标画趋势线；把确定性自检动画包装成模型评测过程。 |
| 数据大屏 | 首屏模块错峰进入；四项指标计数落到实际值；图表按数据从基线展开；缓存与错误状态清楚显示 | 两个聚合接口都返回或分别失败时；每张图表独立使用其真实数据 | 持续自动刷新、随机增长数字、空数组仍画坐标轴或假趋势。 |
| AI 问询 | 提问进入消息流；等待期间显示短句式动态指示；回答和引用一起出现；分析结果面板展开 | `askQuestion` / analytics 请求开始、完成或失败时 | 模拟逐字流式输出（若后端并未流式返回）；请求结束后仍显示 typing。 |
| 登录/注册 | 保留第一份计划中的登录成功开场；按钮提交期间只显示真实 busy 状态 | 显式认证成功或请求状态变化时 | 页面切换时再次播放全屏开场；错误状态被动效遮盖。 |

## 分阶段执行计划

### 第 1 阶段：统一动态基础

1. 记录现有页面在浅色/深色、390px/768px/桌面宽度下的截图基线。
2. 在令牌文件定义 3 类时长和 `prefers-reduced-motion` 总体策略。
3. 给受保护的业务页加路由过渡；认证公开页单独验证，避免开场重复播放。
4. 测试路由跳转、浏览器回退、窄屏和 reduced-motion 下页面都能立即稳定显示。

### 第 2 阶段：任务与数据到达反馈

1. 解析/评分页为真实响应阶段与结果组接入有界进入效果。
2. 一致性/建议页将列表选择、证据定位和高亮变化连成同一动作。
3. 记录页接入筛选、分页、抽屉的状态反馈；loading 与失败态各自可见。
4. 对每一项验证动画不改变返回数据、顺序、跳转和定位区间。

### 第 3 阶段：指标与对话的动态表达

1. 评测页和大屏用真实指标值更新动效；保留 `low_sample`、`no_samples` 和空态语义。
2. 大屏明确控制 ECharts 动画时长，接口失败模块不显示假图。
3. 问询页为真实请求增加 typing/活动提示，响应消息和分析结果以稳定 key 进入。
4. 对话失败、取消或请求结束后确认活动效果立即停止，输入内容仍可恢复。

### 第 4 阶段：整体验收

1. 跑 Vitest 全套、Playwright 全套和生产构建。
2. 在浅色/深色、窄屏和桌面检查九类页面的动态反馈与稳定终态。
3. 开启系统减少动态效果复核：页面仍有状态变化和信息层次，但不播放位移、描线或数字滚动。
4. 通过真实数据截图确认数字、档位、错误提示、空态没有被动效遮挡或改写。

## 验收标准

- 每个业务主页面至少有一项可触发、可看见、绑定真实用户动作或数据状态的动态反馈；不要求页面持续自动变化。
- 全站路由进入、数据响应、选择/展开、加载/失败的节奏一致；动效结束后页面布局与数值稳定。
- 评审步骤、评分、冲突、建议、记录、指标和聊天内容都以已有数据为准，不引入虚构进度或自动刷新的假活跃。
- `low_sample` 指标仍不画折线；无数据仍显示原空态；失败时的错误和可重试入口始终可见。
- `prefers-reduced-motion` 下无持续或位移动效，所有信息与操作仍完整可用。
- 无新增动画库；生产构建通过；Vitest 与 Playwright 中新增用例全绿，既有功能断言不删不弱化。

## 非目标与边界

- 不改后端 API、评审评分、档位、模型调用和数据写入逻辑。
- 不添加 WebSocket、轮询或“实时动态”业务数据；如后续确需实时更新，另立需求并明确数据来源与频率。
- 不恢复登录前片头，也不在已登录路由刷新时重复播放开场。
- 不使用脱离真实请求状态的全站粒子、光晕、渐变、漂浮卡片、无限循环动画或音效。
- 不改变空数据、错误、低样本、权限拒绝和解析等待的现有文案契约。

## 本轮状态

本计划已按页面职责落地。路由切换使用轻微淡入与 5px 归位；解析/评分/冲突/建议列表使用稳定 key 过渡；建议分组可由用户收放；记录筛选重取时保留旧行并显示请求状态；聊天活动提示只在真实请求期间显示；评测线条与大屏 ECharts 服从 `prefers-reduced-motion`。大屏与评测共用 `MotionNumber`，屏幕阅读器读取最终值，动画只呈现旧值到新值的短暂变化。

为守住首屏预算，工作台各路由改为按需加载；路由与页面逻辑不变，解析页和记录页只加载各自入口需要的代码。首屏预算 E2E 复测：raw 1,029,932 字节（相对原基线 -87,250），gzip 332,381 字节（-23,499）；数据大屏额外 1,565,380 raw / 509,410 gzip，页面模块可交互 398.9 ms。

本轮没有新增 SVG：现有校样纸线稿已满足插图表达，新增状态用 Vue/CSS 与 ECharts 数据动画表达，不需要再加一张装饰图。

验证：Vitest 35 个文件、176 条全绿；生产构建通过；新增真实状态 E2E、路由冒烟与登录开场共 4 条通过。全量 Playwright 曾在路由按需加载前跑出 47 passed / 9 failed，其中 8 条停在确认卡的 60 秒同步评审等待，另 1 条首屏预算失败；预算失败随后通过路由按需加载复测通过。全量 E2E 未在路由拆分后再次重跑，8 条长链路结果因此不宣称归零。
