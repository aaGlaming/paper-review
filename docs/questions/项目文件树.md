## 3. 里程碑 × 允许修改的目录（权限边界）

| 里程碑 | 允许修改的目录 / 文件 | 完成定义（人要看到的结果） |
|---|---|---|
| P0 | 根环境文件、`backend/requirements.txt`、`backend/app/llm`、`backend/tests/llm`、`docs/diagrams`、`docs/plan`、`compose.yaml`、`CLAUDE.md` | mock 客户端测试退出码 0；仓库搜不到 `ollama`/`sentence-transformers`/`qwen2.5`；运行时图 deliver 无失败诊断 |
| P1 | `backend/app/graph`、`backend/tests` | 未确认章节树不进入评分；重启后从暂停点继续 |
| P2 | `backend/app/importing`、`data/contests`、`backend/tests` | 三道赛题可读；坏包整包拒绝且已有数据不变 |
| P3 | `backend/app/retrieve`、`backend/tests` | 先过滤再取父块；错赛题子块不会被取回 |
| P4 | `backend/app/retrieve`、`backend/app/graph`、`backend/tests` | 每维最多 4 段；重排不放宽过滤；证据不足才再查一轮 |
| P5 | `backend/app/graph`、`backend/app/scoring`、`backend/tests` | 原句不是子串则不加权；未写调头圆弧的维度为证据不足 |
| P6 | `backend/app/review`、`data/samples`、`backend/tests` | 三篇演示的数字、引用、速度越界被标出 |
| P7 | `backend/app/report`、`backend/tests` | 清单只转写已校验结果；文本中无奖项 |
| P8 | `frontend/src/views`、`frontend/src/api` | 五个页面可填入示例；评测页能点进单篇 |

> P6 可与 P4、P5 并行开发（它只读论文纯文本和约束，不读向量库）；其余编号顺序执行，上一个编号 pytest 退出码不为 0 就不写下一个。

## 4. 需注意的落点差异与未冻结项

1. **赛题目录前缀**：需求文档第三章写作 `contests/{contest_id}/...`，手册 P2 与计划书 §8 落到 `data/contests/{contest_id}/...`。树按后者（项目根下 `data/`）定稿；若两者被视为冲突，按手册要求应先在 `docs/plan/findings.md` 记一条 Ruling。

2. **前端页面命名**：需求 §4 给出的是 HTML 页名（`agent1-论文解析.html` ～ `agent5-评测对照.html`），计划书与手册落点为 `frontend/src/views/`。技术栈是 Vue 3 + Vite，故实际为单文件组件，**具体文件名尚未在文档中冻结**，树中用 `○` 标注，只保留需求给定的中文页名与编号对应关系。

3. **`__init__.py`**：文档从未点名，属于 Python 包的工程惯例补全，标记为 `○`，可按实际需要增删。

4. **持久化目录**：MySQL 数据与 Chroma 数据由 Compose 卷承载（服务 `frontend`/`backend`/`mysql`/`chroma`），文档未给出宿主机挂载路径，故未在树中虚构目录名。

5. **不交付项**（不要出现在树里）：本地模型权重、优秀论文原文、奖项预测接口、项目内第二个虚拟环境。
