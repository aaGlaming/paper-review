### 3.3 结论

本次属于分支 B 的部分满足。真实模型没有提交“充分”，所以没有形成可被 critique 复核的充分档样本。结构上，`tools.py:207` 在 `submit_dimension` 写入结果前先调用 `apply_mention_guard`；`critique.py:77-81` 只处理“充分/基本”，而 runner 当前以 `chat_fn=None` 调用 critique。若提交层已经把“充分”降为“基本”，critique 的 guard 分支不会再降；本次则更早地由模型直接选为“基本”。因此拿到的是 submit 层和代码路径证据，没有真实 critique 降档证据，判据 5 不写成完全通过。

### 3.4 收口复核：对照实验与原因修正（2026-10-19 22:00）

上述「零触发」的解释不完整。本节补做一组对照实验，用同一篇论文重复运行来分离两个变量：**模型档位的随机性**与**新增约束的影响**。

实验设计：取实测判过「充分」的两篇论文，在原题与 probe 赛题下各重复运行，观察每次的「充分」维度数与 critique 轨迹数。

| 论文 / 赛题 | 运行次数 | 每次「充分」维度数 | critique 轨迹 |
|---|:-:|---|:-:|
| `cumcm-2024-A-a242` / `cumcm-2024-A`（原题） | 3 | **3 / 1 / 1** | 0 / 0 / 0 |
| `cumcm-2024-A-a242` / `probe-critique-acceptance` | 3 | **0 / 0 / 0** | 0 / 0 / 0 |
| `cumcm-2024-C-c234` / `cumcm-2024-C`（原题） | 3 | **2 / 2 / 0** | 0 / 0 / 0 |

先排除量规差异：probe 赛题的 `rubric.json` 与 `cumcm-2024-A` **逐字段比对完全相同**（5 个维度的 `code`/`weight`/`evidence_prompts`/`section_types`/`bands` 全部一致，`version` 同为 1），因此差异不来自量规。

**修正后的结论**：真实机制是**模型档位本身存在随机性，「充分」是低频事件**。同一篇论文、同一道题、同一套量规，「充分」维度数在 0～3 之间波动。

由此推出一个关于「造样本」路线的硬结论：**mention 约束只能「拦」充分，不能「造」充分**。模型压根不判「充分」时，约束没有作用对象，`apply_mention_guard` 首行 `if band != BANDS[0]: return` 直接返回，critique 因此无档可降。probe 赛题三次全为 0 正是这一点的直接验证。

所以 v2.4.0 设计的「加一条命中不了的约束造样本」这条路线，**在真实链路上本质上走不通**——不是执行问题，而是机制上限。

判据 5 的阻塞点由一条变为两条，需同时满足才可能拿到真实证据：

| # | 阻塞点 | 依据 |
|:-:|---|---|
| 1 | 模型极少判「充分」，guard 与 critique 都没有作用对象 | 本节对照实验：原题下 0～3 维随机波动 |
| 2 | runner 以 `chat_fn=None` 调 critique，第二条「模型复核」路径永远走不到 | `critique.py:96` 的 `if chat_fn is None or not parents: continue` |

**这两条都属于产品语义层面**，要解除必须先立 Ruling（给 critique 注入 `chat_fn`，或放宽触发档位），不在验收阶段的改动范围内。
