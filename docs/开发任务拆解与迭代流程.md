### 3.2 每一版的固定顺序

1. 打开 `docs/plan/progress.md`，确认上一版退出码是 0。不是 0 就停。
2. 只粘贴该版本的提示词。提示词里不得同时出现两个版本号。
3. 先写该版本列出的测试，运行 pytest，确认失败原因是功能未实现，而不是导入错误或收集错误。
4. 再写实现。若先写了实现，删掉实现，从失败测试重新开始。
5. 再跑同一条 pytest。退出码 0 后，若该版本还有 archify 图，再出图。
6. 按该版本的阶段验收逐条勾选。有一条做不到，版本保持未通过，开补丁号修，不进入下一版。
7. 在 `progress.md` 写下版本号、命令、退出码、最后一行摘要。
8. 人明确要求提交时，一个已通过的版本对应一次提交。未通过不提交。不要主动打 git tag，除非人要求。

## 4. 开工前冻结的契约

这些内容在 v0.1.0 写入代码之前就定死。实现不得另起一套。

### 4.1 产品边界

做赛前预审。学生或教师选定一道已发布赛题、上传论文后，系统按该题量规逐维取证，给出档位、论文原句和修改清单。

进入加权的每一维必须能打开量规条款和论文原句。证据不够写成「证据不足」，原句对不上写成「引用失败」，这两类不进加权。

不输出奖项、名次、获奖概率。不做全国评阅，不做多用户权限。不把优秀论文原文切进向量库。评分、审查、报告的源码不按 `cumcm-2024-A` 等题号写分支。差异只放在 `constraint` 与 `rubric`。

Markdown 是验收主路径。PDF 抽不出文本时返回解析失败，不得当成空论文。

### 4.2 五维量规

首版已发布量规，每维权重 20，合计 100。证据不足的 `score` 为空，不参与加权。

| dimension_code | 名称 |
|---|---|
| assumption | 假设的合理性 |
| modeling | 建模是否针对本题 |
| solution | 求解与结果 |
| constraint_check | 检验与题目约束 |
| presentation | 表述与结构 |

档位只有：充分、基本、不足、证据不足。充分、基本、不足的 `score` 为数字。这个权重分配是本文冻结的首版数据，不是章程里的官方分数。要改权重，走第 2 版量规，不改旧评审。

### 4.3 三道赛题必须写入的约束

| contest_id | 约束 |
|---|---|
| cumcm-2024-A | 碰撞；螺距 1.7 m；调头圆弧半径 2 倍且相切；龙头速度 1 m/s；把手速度不超过 2 m/s |
| cumcm-2024-C | 不能连续重茬；三年内至少一次豆类；滞销与 50% 降价两种情形 |
| cumcm-2025-A | 云团 3 m/s 下沉；有效范围 10 m / 20 s；无人机 70～140 m/s |

`check_type` 只注册三种：`mention`、`numeric_range`、`required_case`。

`numeric_range` 的 params 示例：`{"min": 70, "max": 140, "unit": "m/s"}`。  
`required_case` 的 params 示例：`{"label": "50%降价", "artifact": "result1_2"}`。

数据包目录：

```text
data/contests/{contest_id}/contest.json
data/contests/{contest_id}/constraints.json
data/contests/{contest_id}/rubric.json
data/contests/{contest_id}/pitfalls.json
data/contests/{contest_id}/exemplars.json
```

题目正文保持公开发布文本的原意，不改螺距、速度上下限和销售规则。样例里的 412 s、386 s、1286 万元、974 万元、22.4 s、18.6 s、160 m/s、缺失的 \[12\] 是验收构造，页面要能看出这是自建样例，不能写成官方答案。

### 4.4 接口

需求分析写了 `POST /api/imports`，开发计划书写了 `POST /api/catalog/imports`。本文冻结采用需求分析的路径，因为验收以需求为准。不实现第二个导入路径。

```text
GET  /api/contests                              # 默认只返回 published
POST /api/reviews                               # 上传或填入样例，创建评审
POST /api/reviews/{review_id}/resume           # 确认章节树后继续
GET  /api/reviews/{review_id}
GET  /api/samples?is_demo=
GET  /api/eval/summary
POST /api/imports                               # 赛题数据包；失败时返回文件名和字段名
POST /api/contests/{contest_id}/publish
POST /api/contests/{contest_id}/archive
POST /api/contests/{contest_id}/rubrics        # 从当前 published 复制出 version+1 的 draft
POST /api/rubrics/{rubric_id}/publish
```

`GET /api/contests` 不在前端写死三道题。`archived` 后新建列表没有它，旧 `review_id` 仍能打开。

### 4.5 模型调用

全项目只有 `backend/app/llm/client.py` 可以发 HTTP。

环境变量只允许这些键，密钥不进仓库：

```text
LLM_BASE_URL
LLM_API_KEY
LLM_MODEL
EMBEDDING_MODEL
RERANK_BASE_URL
RERANK_MODEL
MYSQL_DSN
```

对话：`POST {LLM_BASE_URL}/chat/completions`，请求头 `Authorization: Bearer {LLM_API_KEY}`，只读 `choices[0].message.content`。  
嵌入：`POST {LLM_BASE_URL}/embeddings`，只读 `data[].embedding`。父块不向量化。  
选档要求 JSON。解析失败重试一次，再次失败则该步状态为失败，并显示在页面上。  
重排只改变已过滤候选的顺序，不能把被过滤掉的段加回来。重排的具体 JSON 字段放在一个函数后面，测试用假客户端。没有密钥时，过滤和截断测试仍然要通过。

不使用 Assistants、Responses，不读取厂商私有字段。

### 4.6 检索与状态

编排是 LangGraph 状态图，不是自由 ReAct。章节确认调用 `interrupt()`，用户确认后用 `Command(resume)` 继续。检查点按 `review_id` 保存。

检索顺序：用该维的 `evidence_prompts` 和 `section_types` 生成查询；用 `contest_id`、`rubric_id`、`section_types` 过滤子块；重排；取回父块。每一维分三路取材料：档位说明、论文章节、扣分点。三路各自召回后再收成最多 4 段父块。证据不足才改写查询再查一轮。第二轮仍空则档位为证据不足，不调用第三次检索。

Chroma 的 `doc_type` 只有：`paper_child`、`band_text`、`pitfall`、`exemplar`、`contest_statement`。父块全文只在 MySQL。

评审状态只有：草稿解析、待确认、评分中、完成、失败。

### 4.7 演示样例必须标出的事实

| 文件 | 必须被标出的内容 |
|---|---|
| `data/samples/bench-dragon.md` | 摘要 412 s 与结果表 386 s；假设中的「忽略板凳宽度」；未写调头圆弧半径 2 倍且相切，该维为证据不足 |
| `data/samples/planting.md` | 摘要 1286 万元与汇总表 974 万元；没有豆类「三年内至少一次」；没有 50% 降价 / `result1_2` |
| `data/samples/smoke.md` | 摘要 22.4 s 与正文 18.6 s；正文引用 \[12\] 但参考文献没有 \[12\]；无人机 160 m/s 超出 70～140 m/s |

另外 12 篇放在 `data/samples/eval/`，每篇带 `gold`（`dimension_code` 与 `band`）和 `expected_findings`。评测分母是这 15 篇。

修改清单顺序：题目约束和数字冲突、证据不足、表述。每条建议能指回一个 `dimension_code` 或一条审查结果。删掉上游记录后，这条建议不能单独存在。

> 注：上表两条评审写接口（`POST /api/reviews`、`POST /api/reviews/{review_id}/resume`）
> 在 v0.1.0～v0.8.0 的版本任务清单中均未排期，由 v0.8.1 补实现。

- `fixture-extra` 不改智能体和页面代码即可出现在列表中并创建评审。
- 坏包指出字段，已有赛题不变。
- 第 2 版量规只影响新建评审。
- 归档后不能新建，历史仍可打开。
- 评分、审查、报告源码没有题号分支。
- 配置里的模型地址只指向兼容接口，对话走 `/chat/completions`，嵌入走 `/embeddings`。
