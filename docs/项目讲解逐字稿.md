# paper-review 项目口头讲解逐字稿

---

## 一、主稿

**【1. 定位】**

我讲一个独立完成的系统：竞赛论文预审工作台。它把一篇数学建模论文，按赛题自己的评分量规拆成五个维度，每一维给一个档位和一句理由。**它不排名、不预测获奖、不给概率**。

**【2. 为什么不直接打分】**

打分原本是人工做的：老师拿量规逐条对，慢，而且十个人能给出五个档。

最直觉的方案是丢给模型打个总分，**我一开始就没走**：模型算术不可靠、分数不可解释、同一篇跑两次结果不一样。

所以我把它拆成两半——**语义判断给模型，合法性校验给代码。**

**【3. 主链路：检索到底在干什么】**

模型只被允许输出三样：**一个档位、一个切片编号、一句原文。**多一个字都不采纳。

那句话必须**逐字、连续地**出现在它引用的原文里。不是相似度，不是分词命中，是字符串包含。对不上就判引用失败，档位保留但不进加权。权重和加总全按量规算，模型返回里带了权重，一样丢掉。

更关键的是：**证据不足不换算成分数。**折成一个低分，等于把「没有依据」伪装成结论。我的处理是这一维直接出局，同时告诉你还有多少权重没依据，页面显示「加权未产生」，不显示零分。

检索干的就是这件事：三路来源各自过滤召回，按父块去重，合并后**只重排一次**，三路合计截四段——不是每路四段，那会让提示里塞进十二段噪声。**检索不是为了多给上下文，是为了给出一段能被逐字比对的原文。**

**【4. Agent 层：它补了什么】**

只靠固定流水线，模型是被动喂证据的。这里需要它自己决定：这一维先查什么、查到哪一步算够、什么时候交卷。所以上面加了一层 Agent。

**六个工具**：读维度清单、读赛题约束、检索证据、读原文全文、查一致性问题、提交结论。只有「提交结论」能记录结果——不调它，这一维在本系统里等于没评。

自由度必须关住，我用了**四道预算闸**：模型调用十二次、工具调用二十四次、每一维最多三步、总墙钟一百五十秒；再加一道无进展检测，连续检索不出新东西就停。**撞闸不是崩掉**：没交的维度走一次强制补交，最多两轮；还失败就标证据不足并记录终止原因，让人看得出这是系统放弃，不是论文差。

每次工具调用都落轨迹，**只存参数哈希、不存全文**——轨迹要能复盘，但不能变成第二个泄密面。最后还有一道自检：**只降不提**。允许它提档，等于让模型给自己加薪。

**【5. 第二条链路：记录级问询】**

评过的记录会重新切块索引，教师可以直接问「这个赛题哪些论文假设写得差」。两条约束：问题里带了记录编号就只查那条，**不掺向量结果**——掺进来模型就会引别人的记录；回答里的引用必须来自本次检索，编的会被删掉并计数。**统计数字一律由数据库算，不问模型。**

**【6. 编排与工程】**

主流程是四节点状态图：解析、确认、检索、选档，线性。中间那个确认是**真中断**——章节归属必须人工确认，没确认不进评分；恢复时从断点走，不重跑解析。

还有个我比较满意的决定：检索器和模型**一律外部传入**，编排模块内部不许发网络请求。所以四百七十多条后端测试**一次请求都不发**。没配模型也是合法运行态，会走确定性回退，并明确标注「这是脚本自检」。

**【7. 规模与门禁】**

体量：三十三条接口、十七张表、前后端加测试一万五千行。

四道门禁全绿：后端四百七十二条、前端单测一百六十二条、构建退出码零、端到端五十四条。**这套绿不是天生的**——端到端曾挂八条红，根因是章节确认一次要二十五到四十秒，而用例只等五秒。我放宽的是等待上限，**断言里的业务期望值一个没改小**；剩下两处业务数值差异逐条查清，同样没有动预期值。

**【8. 评测】**

十二篇有 gold 的语料，六十个维度项。我只主动讲两个数：**引用精确匹配 27 比 27，证据不足命中 2 比 2**——证明「不许编」这条硬约束真生效了。

档位一致是 13 比 60，两成出头。不好看，但能解释：gold 是人工按档标的，样本里「基本」占多数，而确定性回退只给「基本」和「证据不足」两档，反而命中更多。**这是样本偏斜，不是模型能力排名。**

**【9. 收尾】**

一句话：**宁可拒答，也不编造。**价值不在打得多准，而在每句判语都能在原文里指到位置，指不到就不给分。

下一步三件事：检查点换持久化、标注集扩到有统计意义、把内容级「选错题」判定做出来——现在只保证无已发布量规的赛题不出结果，不保证论文和题目对得上。谢谢。

## 二、60 秒压缩版

> 竞赛论文预审系统。人工按量规打档慢且口径不一；直接让模型打总分则会编原句、编分数、不可复现。
> 我把语义判断和合法性校验切开：模型只输出档位、切片编号、原句，原句必须逐字出现在检索到的原文里，对不上判引用失败、不参与加权；权重和合计全由代码按量规算；证据不足不换算分数，直接出局。
> 上面挂了一层 Agent：六个工具里只有一个能记结论，配四道预算闸，撞闸走强制补交，每次工具调用落轨迹，自检只降不提。
> 主流程四节点状态图，人工确认用真中断。检索器与模型外部注入，四百七十多条后端测试不发一次网络请求。
> 评测十二篇有 gold：引用 27 比 27、证据不足 2 比 2、档位一致 13 比 60——偏低是标注集偏斜，不是模型好坏。
> 一句话：宁可拒答，也不编造。

## 三、被打断时的短答

| 被打断的点 | 一句话回答 |
|---|---|
| 为什么不直接让模型给总分 | 算术不可靠、分数不可解释、口径不可复现；拆成逐维选档再按量规加总，档位只有四个值，可复核。 |
| 怎么防模型编原句 | 三层：提示要求逐字、代码做连续子串校验、不通过就不进加权。第三层才是硬的。 |
| 校验这么严会不会误杀 | 会。但代价是「这一维不给分」而不是「给错分」。放宽要引入阈值，阈值又是一个不可解释的参数。 |
| Agent 和固定流水线差在哪 | 差在「先查什么、查到哪算够」由模型决定；结论怎么记、能走几步、撞闸怎么办，全由代码锁死。 |
| Agent 会不会乱调工具 | 工具是白名单；读原文限定在本次命中的父块里；提交只认四个合法档位，越界返回错误码而不是抛异常。 |
| 撞预算闸了怎么办 | 没交的维度走一次强制补交，最多两轮；仍失败就标证据不足并记终止原因，不假装评过。 |
| 为什么不做多 Agent 协作 | 五个维度之间没有依赖，也不需要互相谈判；多一层协作只多一份不可复现和一条成本线。 |
| 轨迹为什么只存哈希 | 要能复盘调用序列与成败，又不能把全文参数写进第二份存储变成泄密面。 |
| 第二条问询链路和主链路什么关系 | 共用父子块与检索；问询多了「定点取证」和「引用必须在本次结果内」两条约束，统计数字走数据库。 |
| 检查点放内存能上生产吗 | 不能，这是首期取舍。检查点对象从外部传，换持久化只改一处装配。 |
| 为什么只重排一次、只留四段 | 逐路重排是三倍成本且三路分数不可比；三路各留四段会让提示里十二段互相稀释。 |
| 现在最大的短板 | 标注集只有六十个维度项且偏斜，打分准不准我不敢下结论；只收 Markdown 与 DOCX，PDF 不做在线解析。 |
| 如果重做改哪三件 | 检查点换持久化、标注集分层扩容、补内容级的题目匹配判定。 |
