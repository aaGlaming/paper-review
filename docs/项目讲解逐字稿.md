# paper-review 项目口头讲解逐字稿

> 用途：面试自我介绍、答辩开场、组内分享都能直接念。
> 主稿约 1400 字（实测 1359 汉字），正常语速 **3 分半到 4 分钟**；后面附 60 秒压缩版与打断速答。
> 全文不出现函数名、文件名、类名，只讲机制、取舍与数字。数字均已对照当前代码与门禁实测。

---

## 一、主稿

**【起：定位】**

我讲一个我独立做的系统，叫 paper-review，中文叫竞赛论文预审工作台。它做一件事：把一篇数学建模竞赛论文，按赛题自己的评分量规拆成五个维度，每个维度给出一个档位和一句理由。**它不排名、不预测获奖、不给概率**——这是需求里写死的边界，验收里有一条专门扫这些字样。

**【承：痛点】**

这个场景原本是人工做的。老师拿着量规逐条对，慢，而且不同人给的档位不一样，同一个维度十个人能给出五个档。

最直觉的方案是把论文丢给大模型，让它打个分。**但这条路我一开始就没走。**原因是三个：大模型的算术不可靠；给出来的分数不可解释，你说不清为什么是七十八分；同一篇论文跑两次结果不一样，口径不可复现。

**【转：核心机制】**

我的做法是把「语义判断」和「合法性校验」彻底切开。

模型只被允许输出三样东西：**一个档位、一个切片编号、一句原文**。就这三样，多一个字都不采纳。

拿到之后代码做两件事。第一，这句子必须**逐字、连续地**出现在它引用的那段原文里——不是相似度、不是分词命中，是字符串包含。对不上，这一维直接判「引用失败」，档位保留但不进加权。第二，权重和加总全部按量规算，模型返回里如果带了权重、带了分数，一律丢掉。

还有一条我觉得比前两条更重要：**「证据不足」这一档不换算成分数。**很多实现会把它折成一个低分，但那是把「没有依据」伪装成一个结论。我的处理是这个维度直接出局，同时在结果里告诉你还有多少权重是没有依据的，页面上显示「加权未产生」，而不是一个零分。

三道闸门连起来就是：检索层没证据的进不来，选档层编的原句出局，加总层证据不足的不计权重。

**【编排与工程】**

流程编排是一个四节点的状态图：解析、确认、检索、选档，纯线性。中间那个「确认」是**真中断**——章节归属必须人工确认，没确认不进评分，进程恢复时从断点往下走，不重跑解析。

另外一个我比较满意的工程决策是：检索器和模型**一律从外部传进去**，编排模块内部不允许发网络请求。好处是全量四百多条后端测试**一次网络请求都不发**，一分多钟跑完，测试里只传两个假函数就行。而且没有模型配置也是合法运行态，会走一条确定性的结构回退，并且明确标注「这是脚本自检，不是模型结果」。

**【规模与门禁】**

现在的体量是：三十多条接口、十七张数据表、五个量规维度四个档位权重合一百，前后端加测试一万五千行上下。

门禁跑了四道：后端测试四百三十六条全过、前端单测一百四十九条全过、类型检查与构建退出码零。浏览器端到端是四十五条通过、八条红的，红的原因我说清楚：确认链路单次要二十五到四十秒，而用例的断言窗口是五秒，属于性能问题不是功能缺失，这条已经挂账待修，我没有把它改成「放宽断言让它变绿」。

**【评测】**

我建了一份十二篇有 gold 的评测语料，一共六十个维度项。结果里我只会主动讲两个数：**引用精确匹配 27 比 27，证据不足命中 2 比 2。**这两个数说明的是「不许编」这条硬约束真的生效了。

而档位一致率只有 13 比 60，两成出头。这个数不好看，但我能解释：gold 是人工按档标的，样本里「基本」占多数，而确定性回退只会给「基本」和「证据不足」两个档，所以它反而命中更多。**也就是说这个数反映的是样本分布偏斜，不是模型能力的排名。**真要评估打分准不准，得把标注集扩到有统计意义的规模——那是我明确留给下一期的事，不是含糊过去。

**【合：收尾，15 秒】**

一句话总结：这是一个**宁可拒答也不编造**的系统。它最大的价值不在打得多准，而在于每一句判语都能在原文里指到位置，指不到就不给分。

下一步三件事：检查点换持久化、标注集扩容、解析层补齐表格和主张的结构化产物。谢谢。

## 二、60 秒压缩版

> 竞赛论文预审系统。人工按量规打档慢且口径不一；直接让大模型打分则会编原句、编分数、不可复现。
> 我把语义判断和合法性校验切开：模型只输出档位、切片编号、原句三项，原句必须逐字出现在检索到的段落里，对不上判「引用失败」不参与加权；权重和合计全部由代码按量规算；证据不足不换算成分数，直接出局。
> 编排是四节点状态图，人工确认用真中断，没确认不进评分。模型与检索器外部注入，所以四百多条后端测试不发一次网络请求。
> 评测十二篇有 gold 的语料：引用精确匹配 27 比 27、证据不足命中 2 比 2，档位一致 13 比 60——这个偏低是标注集分布偏斜，不是模型好坏。
> 一句话：宁可拒答，也不编造。

## 三、被打断时的短答

| 被打断的点 | 一句话回答 |
|---|---|
| 为什么不直接让模型给总分 | 算术不可靠、分数不可解释、口径不可复现；拆成逐维选档再按量规加总，档位只有四个值，可复核。 |
| 怎么防模型编原句 | 三层：提示里要求逐字、代码做连续子串校验、不通过就不进加权。第三层才是硬的，前两层只是降概率。 |
| 校验这么严会不会误杀 | 会。但代价是「这一维不给分」而不是「给错分」，我选前者。放宽就要引入阈值，阈值又是一个不可解释的参数。 |
| 为什么状态图没有分支 | 业务上就是线性的，不解章节不能评分；唯一的停顿是人工确认，那是中断不是路由。 |
| 检查点放内存能上生产吗 | 不能，这是首期取舍。兼容点已经留好：检查点对象从外部传，换持久化只改一处装配。 |
| 重排解决什么问题 | 只改顺序、不增不减；输入输出集合必须完全相同，多一个少一个都报错，防它顺手把无关段落捞回来。 |
| 一共检索多少段 | 三路来源各自过滤召回，按父块去重，合并后**只重排一次**，三路合计截四段。逐路重排是三倍成本且分数不可比。 |
| 数字冲突为什么不用模型 | 这类检查要可复现、可解释、零成本。模型只做真需要语义理解的选档。 |
| 现在最大的短板 | 标注集只有六十个维度项且分布偏斜，打分准不准这件事我还不敢下结论；解析层只切章节，表格与主张还没结构化。 |
| 如果重做改哪三件 | 检查点换持久化、标注集扩容并分层抽样、解析产物补全。 |
